CAN ID 12｜硬體

感測器與 CAN 除錯：計步器、刻度尺和廣播線

讀完這章，你會知道 TalonFX 內建編碼器和 CANcoder 的差別、怎麼設定 CANcoder 的零點、怎麼接極限開關並用它歸零，以及 CAN 上找不到裝置時，照什麼順序把問題找出來。

版本說明本章依據 WPILib 2026 與 Phoenix 6 的 2026 版（26.x）文件。2025 年起 CANcoder 的 AbsoluteSensorRange 已改成 AbsoluteSensorDiscontinuityPoint，網路上舊的範例還看得到舊名稱。

生活比喻：班長的計步器、牆上的刻度尺

班長身上有一個計步器。班長每走一步，計步器就加一，非常靈敏、反應很快。但它只知道「從早上戴上到現在走了幾步」，每天早上都從 0 開始算。如果昨天放學時班長停在走廊中間，今天早上計步器還是從 0 開始，它不知道自己在哪裡。

走廊牆上有一把刻度尺。刻度尺不管什麼時候看，都能直接讀出「現在在第幾公尺」，一大早看也是對的。只是刻度尺裝上去的時候，0 不一定剛好對準走廊起點，所以要記下一個「校正值」，讀到的數字加上校正值，才是真正的位置。

走廊盡頭有一個門擋。門擋只會告訴你一件事：「碰到了」或「還沒碰到」。它不能告訴你距離多遠，但很適合用來確認「已經到底了」，也可以用來重新對準計步器：碰到門擋時，就知道現在一定在走廊盡頭。

廣播線是一條串起來的線。學校的廣播線從廣播室出發，依序經過每一間教室，最後接到走廊盡頭。線的兩端各要裝一個吸音墊，不然聲音跑到盡頭會反彈回來，跟新的廣播疊在一起，聽起來全是回音。中間某一段線被剪斷，斷點後面的教室就全部聽不到。

點名點不到，要照順序找。某班點名沒人回應，先確定是不是兩個班長用了同一個代號，再沿著廣播線一段一段查，看是從哪一間教室開始聽不到的。

這個比喻哪裡不準刻度尺是直線的，CANcoder 量的是旋轉，轉滿一圈又會回到同一個讀數。所以 CANcoder 只能在「一圈以內」告訴你絕對角度；如果它和機構之間還有減速，機構轉不到一圈時 CANcoder 可能已經轉了好幾圈，這時它也不知道自己在第幾圈。把 CANcoder 裝在「機構整個行程不超過一圈」的軸上，才能發揮絕對位置的好處。

WPILib 文件也是這樣建議：極限開關只能感測單一位置，適合確保動作不超過極限，但不適合在接近極限時控制速度；手臂的旋轉關節最好用絕對編碼器這類感測器控制，極限開關則當作後備，在編碼器失效時防止機構跑過頭[1]。

CANcoder：設定零點與方向

CANcoder 是一顆接在 CAN 上的磁性旋轉編碼器[2]。CTRE 官方範例的設定寫法如下[3]：

CANcoder armEncoder = new CANcoder(23, CANBuses.CANIVORE); // TODO: 依接線

CANcoderConfiguration ccConfig = new CANcoderConfiguration();
// 讀數範圍的「斷點」：0.5 代表讀數在 -0.5 到 0.5 圈之間
ccConfig.MagnetSensor.withAbsoluteSensorDiscontinuityPoint(Rotations.of(0.5));
ccConfig.MagnetSensor.SensorDirection = SensorDirectionValue.CounterClockwise_Positive; // TODO: 上機確認
ccConfig.MagnetSensor.withMagnetOffset(Rotations.of(0.0)); // TODO: 依下面的步驟量測
armEncoder.getConfigurator().apply(ccConfig);

三個設定的意思：

  • SensorDirection：哪個方向轉算正。要和 TalonFX 的 Inverted 一致，也就是手臂往上時，兩邊的讀數都要變大。
  • AbsoluteSensorDiscontinuityPoint：讀數在哪裡從最大跳回最小。設 0.5 時讀數在 -0.5 到 0.5 圈之間。要把這個斷點放在手臂永遠到不了的角度，不然手臂經過那裡時讀數會突然跳一圈。
  • MagnetOffset：校正值。量測方法：先把 offset 設成 0、套用設定，把手臂擺到你定義為 0 度的位置（例如水平），讀出 CANcoder 的絕對位置 x，offset 就填 −x。
教練提醒：offset 記錄在程式裡每次重裝磁鐵、拆裝 CANcoder，零點都會變。把 offset 寫在 Constants 裡並註明量測日期，比只存在 Tuner X 裡可靠，第 11 章說過：程式裡套用的完整設定會蓋掉 Tuner X 手動改的值。

讓 TalonFX 直接讀 CANcoder

第 6 章的手臂用 TalonFX 內建編碼器，SensorToMechanismRatio 填馬達到手臂的齒輪比。加上 CANcoder 後，可以讓 TalonFX 直接用 CANcoder 當回授來源，閉迴路仍然在控制器內執行[4]：

TalonFXConfiguration config = new TalonFXConfiguration();
config.Feedback.FeedbackRemoteSensorID = armEncoder.getDeviceID();
config.Feedback.FeedbackSensorSource = FeedbackSensorSourceValue.RemoteCANcoder;
config.Feedback.SensorToMechanismRatio = 1.0; // TODO: CANcoder 轉數 / 手臂轉數
config.Feedback.RotorToSensorRatio = 1.0;     // TODO: 馬達轉數 / CANcoder 轉數
// ...其他設定同第 6 章
armLeader.getConfigurator().apply(config);

注意「sensor」換人了：用遠端 CANcoder 時，SensorToMechanismRatio 是 CANcoder 到手臂的比例。CANcoder 直接裝在手臂轉軸上時就是 1.0，不再是馬達的齒輪比。

FeedbackSensorSource做什麼需要 Pro
RemoteCANcoderCANcoder 在 CAN 上發布資料時，TalonFX 就更新位置與速度不需要
FusedCANcoder把 CANcoder 和馬達內建編碼器融合，兼顧準確與反應速度需要
SyncCANcoder開機時用 CANcoder 對齊內建編碼器，之後用內建編碼器控制，並持續監看兩者是否差太多需要

CTRE 文件寫明，沒有 Pro 授權時，FusedCANcoder 和 SyncCANcoder 會退回 RemoteCANcoder，並觸發 UsingFusedCANcoderWhileUnlicensed 故障[4]。RotorToSensorRatio 是馬達轉數對 CANcoder 轉數的比例；CTRE 在手臂重力補償的說明中也要求，用絕對感測器時要把這個比例設好，並讓位置 0 代表手臂水平向前[5]。

極限開關

接在 roboRIO 的 DIO

WPILib 文件說明，roboRIO 內建的數位輸入因為有內部上拉電阻，預設會讀到 high[6]。也就是說，DigitalInput.get() 在什麼都沒接時回傳 true。開關接到地線時，接通讀 false、斷開讀 true。

所以要先想清楚：「線掉了」會被讀成什麼？

開關種類沒碰到碰到線掉了
常開（NO），接地truefalsetrue（看起來像沒碰到）
常閉（NC），接地falsetruetrue（看起來像碰到）

用常開開關時，線掉了程式會以為「還沒到底」，繼續往下推；用常閉開關時，線掉了程式會以為「已經到底」，機構停下來。後者比較安全，因為壞掉時是停，不是撞。這是隊上選擇接法的依據，不是唯一答案，但一定要把這張表寫在程式註解裡。

/** 常閉開關接 DIO 0：碰到或線掉了都回傳 true。 */
private final DigitalInput bottomLimit = new DigitalInput(0); // TODO: 依接線

public boolean atBottom() {
    return bottomLimit.get();
}

要讓 TalonFX 在碰到開關時停止往那個方向輸出，可以把開關狀態直接帶進控制請求[7]：

motor.setControl(request.withOutput(volts)
    .withLimitReverseMotion(atBottom()));

接在 TalonFX 上

開關也可以直接接在 TalonFX 的極限開關接腳上，由控制器自己停止輸出，不經過 roboRIO。讀取狀態用 getForwardLimit() / getReverseLimit()，值為 ClosedToGround 代表開關接通[7]。Phoenix 6 還可以設定碰到開關時，自動把位置設成指定的值（*LimitAutosetPositionValue）[8]，等於控制器自己幫你歸零。

歸零（homing）

只有內建編碼器的升降機構，開機時不知道自己在哪。標準做法是開機後先慢慢往下，碰到底部開關就把位置設成 0。第 6 章的 ArmIO 已經留好 resetPosition，這章的練習會把它串成一個指令。

開關抖動機械開關在接觸的瞬間會快速通斷好幾次。如果「碰到」會觸發一次性的動作，例如重設位置，可以用 WPILib 的 Debouncer：輸入必須持續改變一段時間，輸出才會跟著變[9]。

CAN 的接法

WPILib 文件建議 CAN 採 daisy-chain 接法：從 roboRIO 出發，依序進出每個裝置，最後接到 PDP；黃線是 CAN-High、綠線是 CAN-Low[10]。CAN 網路兩端必須各有一顆 120 Ω 終端電阻，roboRIO 和 PDP 都內建了，所以建議從 roboRIO 開始、以 PDP 結束[10]。CTRE 文件補充：CANivore 也內建終端電阻，用 CANivore 時就是「CANivore ↔ 裝置 ↔ 120 Ω 電阻」[11]。

檢查接線有一個很好用的方法：斷電後用電錶量 CAN-H 和 CAN-L 之間的電阻，應該約 60 Ω（兩顆 120 Ω 並聯）。如果量到 120 Ω，代表只有一端有終端[11]。

找不到裝置時的除錯順序

CTRE 文件指出，CAN 問題通常只有兩種：同型號裝置用了相同 ID（出廠預設都是 0），或 CAN 接線不正確、不牢靠；最麻煩的是兩種同時發生[11]。依照 CTRE 的建議，按這個順序查：

  1. 看 Tuner X。同型號、同 ID 的裝置會顯示成紅色卡片並標示衝突[11]。注意是「同型號」：TalonFX 21 和 CANcoder 21 不會衝突，但兩顆 TalonFX 21 會。
  2. 看哪些裝置消失。daisy-chain 上某一段斷了，斷點之後的裝置全部消失。找到「最後一個還在的」和「第一個不見的」，問題就在兩者之間。
  3. 逐條拉拉看。有用接頭的地方，一條一條輕拉每一根壓接的線；壓接不良是時好時壞最常見的原因[11]。
  4. 檢查顏色。每個接點都要黃接黃、綠接綠，黃綠接反是新機器人最常見的錯誤之一[11]。
  5. 斷電量電阻。約 60 Ω 才對。
  6. 還是找不到，就縮小範圍。只接一個裝置，確認它出現、設好 ID、貼上標籤，再一個一個接回去，直到問題出現[11]。

燈號也有幫助：CTRE 文件提到，TalonFX 和 Pigeon 2 健康但沒有被控制時通常閃橘燈，CANcoder 則是快速亮閃；LED 偶爾閃紅，通常是接點鬆動，可以搖一搖線看能不能重現[11]。

動手試：CAN bus 除錯台

下面是一條接在 CANivore「9427」上的 CAN bus。點裝置之間的線可以剪斷或接回，也可以拿掉末端的終端電阻、故意設錯 ID。每改一次，就「斷電量電阻」和「Tuner X 掃描」看看結果。

在程式裡發現斷線

第 6 章的 ArmIOHardware 已經用 refreshAll(...).isOK() 把 leaderConnected 填進點名表。光是記錄還不夠，要讓操作手在比賽中看得到。WPILib 的 Alert 類別可以發布持續性的警告，儀表板會依嚴重程度與時間排序顯示；文件建議在 periodic 裡呼叫 set，由它內建的變化偵測決定何時啟動[12]。

public class ArmSubsystem extends SubsystemBase {
    private final Alert leaderDisconnected =
        new Alert("手臂主馬達（ID 21）斷線", AlertType.kError);
    private final Debouncer leaderDebounce = new Debouncer(0.5, Debouncer.DebounceType.kFalling);

    @Override
    public void periodic() {
        io.updateInputs(inputs);
        // 連續 0.5 秒讀不到才算斷線，避免偶爾掉一個封包就跳警告
        leaderDisconnected.set(!leaderDebounce.calculate(inputs.leaderConnected));
        // ...其餘同第 6 章
    }
}

kFalling 只延遲「從 true 變 false」的變化：恢復連線時立刻清除警告，斷線要持續 0.5 秒才顯示[9]。0.5 秒是示範值，隊上可以依需求調整。

常見錯誤

以為內建編碼器知道位置沒有歸零的升降機構，開機時讀到 0，不代表它在底部。如果關機時機構停在半空中，開機後「回到 0」的指令會讓它往下撞。
CANcoder 的斷點放在行程中間手臂經過斷點時讀數跳一整圈，閉迴路會以為誤差突然變得很大，手臂猛然甩動。把斷點放在手臂到不了的角度。
SensorDirection 和 Inverted 不一致馬達往上推，CANcoder 卻說在往下，閉迴路越修越錯，手臂衝到底。上機時先用低電壓手動轉，確認兩邊讀數同方向增加。
用常開開關卻沒想過線會掉比賽中線被撞掉，程式以為還沒到底，機構持續往下推。先想清楚「線掉了讀成什麼」。
量電阻時沒斷電通電時量到的數字不準，還可能傷到電錶。一定要斷電再量。

小測驗

練習：升降機構的歸零指令

假設升降機構只有 TalonFX 內建編碼器，底部有一個常閉極限開關接在 DIO 0。請在 ElevatorSubsystem 寫一個 home() 指令：以很小的電壓往下，碰到開關就停止，並把位置重設為 0。為了避免開關壞掉時一直往下推，加上 3 秒的逾時。

看參考答案 
public class ElevatorSubsystem extends SubsystemBase {
    private static final double HOMING_VOLTS = -1.0; // TODO: 實測，越小越安全
    private static final double HOMING_TIMEOUT_S = 3.0; // TODO: 依行程調整

    /** 常閉開關：碰到或線掉了都回傳 true。 */
    private final DigitalInput bottomLimit = new DigitalInput(0); // TODO: 依接線
    private final Debouncer bottomDebounce = new Debouncer(0.05, Debouncer.DebounceType.kRising);
    private boolean atBottom = false;

    private final ElevatorIO io;
    // ...inputs、其他欄位與第 6 章手臂相同

    @Override
    public void periodic() {
        atBottom = bottomDebounce.calculate(bottomLimit.get()); // 每輪只讀一次
        // ...
    }

    public boolean atBottom() {
        return atBottom;
    }

    public Command home() {
        return startEnd(
                () -> io.setVoltage(HOMING_VOLTS),
                () -> io.stop())
            .until(this::atBottom)
            .withTimeout(HOMING_TIMEOUT_S)
            .andThen(runOnce(() -> {
                if (atBottom) {
                    io.resetPosition(0.0);
                }
            }))
            .withName("Elevator.home");
    }
}

幾個重點。until 與 withTimeout 誰先發生都會結束（第 10 章）；結束後再確認一次 atBottom，逾時結束的情況下就不重設位置，否則會把錯的位置當成 0。用常閉開關時，線掉了會讀成「已經到底」，機構會停在原地並被當成 0，所以開機歸零後，還是要目視確認機構真的在底部。

這個寫法為了簡短，直接在 startEnd 裡呼叫 IO；如果這個 Subsystem 和第 6 章一樣在 periodic 裡送出輸出，就要改成切換 ControlMode，不然會被 periodic 蓋掉。
