CAN ID 10｜WPILib 基礎

組合指令：運動會的節目表

比賽裡的動作很少只有一步，像「手臂下去、邊走邊吸、吸到了再收回來」。這章教你用 sequence、parallel、race、deadline 把小指令組成大動作，再加上各種結束條件。還有一條很多人會撞到的規則：同一個指令物件不能用兩次。

比喻：運動會的節目表

運動會的節目大概可以分成四種。接力賽是一棒接一棒，第一棒跑完第二棒才出發，最後一棒到終點才算結束。

大掃除是各組同時掃不同區域，快的組掃完可以休息，但要等最後一組也掃完，大掃除才算結束。

搶答是大家一起作答，只要有一個人先答完，搶答就結束，其他人立刻停筆。

還有一種是「國歌播完前就定位」：國歌一開始播，各班同時走到自己的位置、整理隊伍，國歌一播完這個節目就結束，隊伍整理好沒都一樣。這裡有一件事是主角（國歌），它結束就全部結束。

節目也常常有附加條件：「最多 5 分鐘」、「到裁判吹哨為止」、「下雨就跳過」、「這支舞重複三次」。

節目還能組成更大的節目。「開幕式」本身是一個節目，裡面又有升旗、致詞、表演，可以一層包一層。

有兩條規矩要記得。第一，一個人不能同時排在兩個節目裡：小明排進接力賽，就不能再排同時段的大隊舞，兩個都要有人就得找兩個人。第二，整個節目期間場地都被包下來了：開幕式要用操場和司令台，這兩個地方整段開幕式都保留給它，就算某一段其實只用到司令台。

比喻WPILib什麼時候結束
接力賽Commands.sequence(...) / andThen最後一個指令結束時
大掃除Commands.parallel(...) / alongWith全部都結束時
搶答Commands.race(...) / raceWith任何一個結束時，其他被打斷[5]
國歌播完前就定位Commands.deadline(主角, 其他...) / deadlineFor主角結束時，其他被打斷
最多 5 分鐘withTimeout(秒)時間到或指令本身結束
直到裁判吹哨until(條件)條件成立或指令本身結束
下雨就跳過unless(條件) / onlyIf(條件)條件不符時直接不執行
重複跳三次repeatedly()不會自己結束，要靠外部打斷
一個人不能排兩個節目指令物件不能重複使用
整段預約所有場地組合的 requirements 是所有成員的聯集
這個比喻哪裡不準大掃除的各組是真的同時在動。parallel 裡的指令其實是在同一條執行緒上，每輪輪流各跑一次 execute()，因為都在同一個 20 毫秒裡跑到，看起來才像同時。所以只要有一個成員卡住，其他的也跟著停。

組合本身也是指令

組合指令本身也是指令，一樣實作了 Command 介面，所以組合還可以再拿去組合，一層包一層[1]，像 fooCommand.andThen(barCommand.raceWith(bazCommand)) 這樣[1]。

四種組合，用手臂和 Intake 示範

下面的 arm.goTo(...) 是第 6 章寫的，手臂到目標就會結束；intake.runState(...) 是第 8 章練習寫的，自己不會結束，結束時會設回 NONE。記住這兩個的差別，下面才看得懂。

// 接力：手臂到得分位置 → 吐出 0.5 秒 → 手臂收回
Command score = Commands.sequence(
    arm.goTo(ArmState.SCORE),
    intake.runState(IntakeState.SCORING).withTimeout(0.5), // TODO: 實測時間
    arm.goTo(ArmState.STOW));

// 國歌播完前就定位：手臂往下移到取件位置，途中滾輪先轉起來；手臂到位就結束
Command prepareIntake = Commands.deadline(
    arm.goTo(ArmState.INTAKE),                     // 主角
    intake.runState(IntakeState.INTAKING));        // 被主角的結束打斷

// 大掃除：兩件事都完成才結束
Command stowAndWait = Commands.parallel(
    arm.goTo(ArmState.STOW),
    Commands.waitSeconds(0.3));

// 搶答：吸入，最多 3 秒
Command intakeAtMost3s = intake.runState(IntakeState.INTAKING)
    .raceWith(Commands.waitSeconds(3.0));          // 等同 .withTimeout(3.0)
parallel 裡放了永遠不會結束的指令把 intake.runState(...) 丟進 Commands.parallel，整個組合就永遠不會結束，因為 parallel 要等全部成員都結束。這種時候要改用 deadline 或 race，讓一個會結束的指令來決定什麼時候停。

2025 年的改名：deadlineFor

中置寫法 a.deadlineWith(b) 在 2025 年改名成 deadlineFor 了[3]，意思是「a 是主角，b 陪跑」：

Command prepareIntake2 = arm.goTo(ArmState.INTAKE)
    .deadlineFor(intake.runState(IntakeState.INTAKING));

網路上比較舊的範例還會看到 deadlineWith，知道是同一件事就好。

結束條件與修飾

arm.goTo(ArmState.SCORE).withTimeout(2.0);               // 最多 2 秒，避免卡住
intake.runState(IntakeState.INTAKING).until(arm::atGoal); // 條件成立就結束
arm.goTo(ArmState.SCORE).onlyIf(DriverStation::isTeleop); // 條件成立才執行（示意）
score.withName("Score");                                  // 在儀表板和記錄中顯示的名字

第三行只是示範語法：onlyIf 是條件不成立就直接不跑，unless 剛好相反。實際用的時候，條件通常是「有沒有拿到遊戲物件」這種狀態。

兩條一定要知道的規則

規則一：指令物件不能重複使用

這是 WPILib 明文規定的：指令物件一旦傳進組合，就不能再單獨排程，也不能再塞進第二個組合；呼叫過修飾方法（decorator）之後，原本那個物件也不能再用[1]。

// 錯：同一個物件用了兩次，執行時會丟出例外
Command toStow = arm.goTo(ArmState.STOW);
Command a = Commands.sequence(arm.goTo(ArmState.SCORE), toStow);
Command b = Commands.sequence(arm.goTo(ArmState.INTAKE), toStow);

// 對：每次都呼叫 factory，拿一個新的物件
Command a2 = Commands.sequence(arm.goTo(ArmState.SCORE), arm.goTo(ArmState.STOW));
Command b2 = Commands.sequence(arm.goTo(ArmState.INTAKE), arm.goTo(ArmState.STOW));

這就是為什麼第 6、8 章一直在用「方法回傳新指令」的 factory：每呼叫一次就是一個新的人，可以排進不同的節目。

規則二：整段預約所有場地

組合的 requirements 是所有成員 requirements 的聯集，而且整個組合跑完之前都算數[1]。上面的 score 要用手臂和 Intake；它在吐出的那 0.5 秒，手臂雖然沒在動，還是被 score 佔著，所以手臂的預設指令不會跑，別的需要手臂的指令一來，整個 score 都會被打斷。中斷行為的部分：要所有成員都是 kCancelIncoming，組合才會是 kCancelIncoming[2]。

跨 Subsystem 的指令放在哪

只用到一個 Subsystem 的指令，就放在那個 Subsystem 裡當 factory。score 這種同時用到手臂和 Intake 的，放進哪一個都怪，WPILib 也建議放到外面[4]，例如：

package frc.robot.commands;

public final class SuperstructureCommands {
    private SuperstructureCommands() {}

    public static Command score(ArmSubsystem arm, IntakeSubsystem intake) {
        return Commands.sequence(
                arm.goTo(ArmState.SCORE),
                intake.runState(IntakeState.SCORING).withTimeout(0.5), // TODO: 實測
                arm.goTo(ArmState.STOW))
            .withName("Score");
    }
}

// RobotContainer
operator.y().onTrue(SuperstructureCommands.score(arm, intake));

常見錯誤

把指令存成欄位重複用在 RobotContainer 把 arm.goTo(STOW) 存成欄位，再塞進好幾個組合，一執行就丟例外。要重複用的話，存 factory（方法），不要存指令物件。
等待沒加 timeout序列裡的 arm.goTo(...) 如果因為機構卡住永遠到不了，整個序列就停在那邊。自動階段和重要的動作都加個 withTimeout 當保險。
教練提醒組合寫好先用 withName 取個名字，然後在儀表板或 AdvantageScope 看它怎麼跑。遇到「按了沒反應」，第一件事就是確認是不是有別的指令佔著同一個 Subsystem。

小測驗

練習：取件動作

寫一個跨 Subsystem 的指令 intakeCycle(arm, intake)：手臂先移到 INTAKE，移動途中滾輪就開始吸；手臂到位之後再多吸 1 秒；最後停止吸入、手臂收回 STOW。整個動作最多 4 秒。

整個動作是三步依序進行。第一步裡有兩件事同時發生，而且是看手臂到位了沒。

sequence 串起三步；第一步用 deadlineFor（主角是手臂）；「吸 1 秒」用 withTimeout(1.0)；整體上限用 withTimeout(4.0)。

第一步寫成 arm.goTo(ArmState.INTAKE).deadlineFor(intake.runState(IntakeState.INTAKING))；注意兩次 intake.runState(...) 要各自呼叫 factory，產生不同的物件。

public static Command intakeCycle(ArmSubsystem arm, IntakeSubsystem intake) {
    return Commands.sequence(
            arm.goTo(ArmState.INTAKE).deadlineFor(intake.runState(IntakeState.INTAKING)),
            intake.runState(IntakeState.INTAKING).withTimeout(1.0), // TODO: 實測
            arm.goTo(ArmState.STOW))
        .withTimeout(4.0)                                          // TODO: 實測
        .withName("IntakeCycle");
}

第一步用 deadline：手臂是主角，它到位的時候滾輪指令會被打斷，runState 的結束動作把狀態設回 NONE，然後第二步馬上又開始吸。兩次 intake.runState(...) 是兩個不同的物件，所以沒有違反規則一。到第三步的時候，滾輪已經在 NONE 了。
