CAN ID 10｜WPILib 基礎

組合指令：運動會的節目表

讀完這章，你會用 sequence、parallel、race、deadline 把小動作組成完整動作，知道各種結束條件的寫法，並理解為什麼同一個指令物件不能用兩次。

生活比喻：運動會的節目表

接力賽：一棒接一棒。第一棒跑完，第二棒才出發。最後一棒跑到終點，整場接力才結束。

大掃除：全部完成才下課。各組同時打掃不同區域，快的組掃完就休息，但要等最後一組也完成，才算大掃除結束。

搶答：第一個答完，全部停。幾個人同時作答，只要有一個人先答完，搶答就結束，其他人立刻停筆。

國歌播完前就定位。國歌開始播放時，各班同時走向自己的位置、整理隊伍。國歌一播完，這個節目就結束，不管隊伍整理好了沒。這裡有一件事是主角（國歌），它結束就是全部結束。

節目有時間限制。「這個表演最多 5 分鐘」、「直到裁判吹哨為止」、「如果下雨就跳過這個節目」、「這支舞重複跳三次」。

節目本身也能組成更大的節目。「開幕式」是一個節目，它裡面又包含升旗、致詞、表演。節目表可以一層包一層。

一個人不能同時排在兩個節目裡。小明被排進接力賽之後，就不能再被排進同時段的大隊舞。要兩個節目都有人，就得找兩個人。

整個節目期間，場地都被預約。開幕式要用操場和司令台，這兩個場地在開幕式整段時間都保留給它，就算某一段只用到司令台。

比喻WPILib什麼時候結束
接力賽Commands.sequence(...) / andThen最後一個指令結束時
大掃除Commands.parallel(...) / alongWith全部都結束時
搶答Commands.race(...) / raceWith任何一個結束時，其他被打斷
國歌播完前就定位Commands.deadline(主角, 其他...) / deadlineFor主角結束時，其他被打斷
最多 5 分鐘withTimeout(秒)時間到或指令本身結束
直到裁判吹哨until(條件)條件成立或指令本身結束
下雨就跳過unless(條件) / onlyIf(條件)條件不符時直接不執行
重複跳三次repeatedly()不會自己結束，要靠外部打斷
一個人不能排兩個節目指令物件不能重複使用
整段預約所有場地組合的 requirements 是所有成員的聯集
這個比喻哪裡不準大掃除時，各組是真的同時在動。但 parallel 裡的指令是在同一條執行緒上、每輪依序各執行一次 execute()，只是在同一個 20 毫秒週期內都跑到，所以看起來是同時。任何一個成員卡住，其他成員也會跟著停。

組合本身也是指令

WPILib 文件說明，組合指令本身就是指令，實作了 Command 介面，所以組合可以再被組合，一層包一層[1]。例如 fooCommand.andThen(barCommand.raceWith(bazCommand))[1]。

四種組合，用手臂和 Intake 示範

以下的 arm.goTo(...) 來自第 6 章，會在到達目標時結束；intake.runState(...) 來自第 8 章練習，不會自己結束，結束時設回 NONE。

// 接力：手臂到得分位置 → 吐出 0.5 秒 → 手臂收回
Command score = Commands.sequence(
    arm.goTo(ArmState.SCORE),
    intake.runState(IntakeState.SCORING).withTimeout(0.5), // TODO: 實測時間
    arm.goTo(ArmState.STOW));

// 國歌播完前就定位：手臂往下移到取件位置，途中滾輪先轉起來；手臂到位就結束
Command prepareIntake = Commands.deadline(
    arm.goTo(ArmState.INTAKE),                     // 主角
    intake.runState(IntakeState.INTAKING));        // 被主角的結束打斷

// 大掃除：兩件事都完成才結束
Command stowAndWait = Commands.parallel(
    arm.goTo(ArmState.STOW),
    Commands.waitSeconds(0.3));

// 搶答：吸入，最多 3 秒
Command intakeAtMost3s = intake.runState(IntakeState.INTAKING)
    .raceWith(Commands.waitSeconds(3.0));          // 等同 .withTimeout(3.0)
parallel 裡放了永遠不會結束的指令把 intake.runState(...) 放進 Commands.parallel，整個組合就永遠不會結束，因為 parallel 要等全部成員結束。這時應該改用 deadline 或 race，讓某個會結束的指令決定何時停止。

2025 年的改名：deadlineFor

中置寫法 a.deadlineWith(b) 在 2025 年改名為 deadlineFor[3]，意思是「a 是主角，b 陪跑」：

Command prepareIntake2 = arm.goTo(ArmState.INTAKE)
    .deadlineFor(intake.runState(IntakeState.INTAKING));

網路上較舊的範例還會出現 deadlineWith，看到時記得是同一件事。

結束條件與修飾

arm.goTo(ArmState.SCORE).withTimeout(2.0);               // 最多 2 秒，避免卡住
intake.runState(IntakeState.INTAKING).until(arm::atGoal); // 條件成立就結束
arm.goTo(ArmState.SCORE).onlyIf(DriverStation::isTeleop); // 條件成立才執行（示意）
score.withName("Score");                                  // 在儀表板和記錄中顯示的名字

第三行只是示範語法：onlyIf 在條件不成立時直接不執行，unless 則相反。實際上條件通常是「有沒有拿到遊戲物件」這類狀態。

兩條一定要知道的規則

規則一：指令物件不能重複使用

WPILib 文件明確規定：已經傳進組合的指令物件，不能再被單獨排程，也不能再傳進第二個組合；呼叫過修飾方法（decorator）之後，原本的指令物件也不能再用[1]。

// 錯：同一個物件用了兩次，執行時會丟出例外
Command toStow = arm.goTo(ArmState.STOW);
Command a = Commands.sequence(arm.goTo(ArmState.SCORE), toStow);
Command b = Commands.sequence(arm.goTo(ArmState.INTAKE), toStow);

// 對：每次都呼叫 factory，拿一個新的物件
Command a2 = Commands.sequence(arm.goTo(ArmState.SCORE), arm.goTo(ArmState.STOW));
Command b2 = Commands.sequence(arm.goTo(ArmState.INTAKE), arm.goTo(ArmState.STOW));

這就是為什麼第 6、8 章一直用「方法回傳新指令」的 factory：每呼叫一次，就是一個新的人，可以排進不同的節目。

規則二：整段預約所有場地

組合的 requirements 是所有成員 requirements 的聯集，而且在整個組合執行期間都有效[1]。上面的 score 需要手臂和 Intake；在它吐出的那 0.5 秒，手臂雖然沒動，仍然被 score 佔住，所以手臂的預設指令不會執行，其他需要手臂的指令也會打斷整個 score。中斷行為方面，WPILib 文件說明：只有當所有成員都是 kCancelIncoming 時，組合才是 kCancelIncoming[2]。

跨 Subsystem 的指令放在哪

只用到一個 Subsystem 的指令，放在那個 Subsystem 裡當 factory。score 這種同時用到手臂和 Intake 的，WPILib 的 Organizing Command-Based Robot Projects 文件指出放在任何一個 Subsystem 裡都不合理，應該放在外部[4]，例如：

package frc.robot.commands;

public final class SuperstructureCommands {
    private SuperstructureCommands() {}

    public static Command score(ArmSubsystem arm, IntakeSubsystem intake) {
        return Commands.sequence(
                arm.goTo(ArmState.SCORE),
                intake.runState(IntakeState.SCORING).withTimeout(0.5), // TODO: 實測
                arm.goTo(ArmState.STOW))
            .withName("Score");
    }
}

// RobotContainer
operator.y().onTrue(SuperstructureCommands.score(arm, intake));

常見錯誤

把指令存成欄位再重複使用在 RobotContainer 裡把 arm.goTo(STOW) 存成一個欄位，再放進好幾個組合，執行時會丟出例外。需要多次使用時，存 factory（方法），不要存指令物件。
沒有 timeout 的等待序列裡的 arm.goTo(...) 如果因為機構卡住永遠到不了，整個序列就停在那裡。自動階段和重要動作加上 withTimeout 作為保險。
教練提醒組合寫好後，先用 withName 取名，再在儀表板或 AdvantageScope 看它的執行狀況。「按了沒反應」時，第一件事是確認是不是有別的指令佔住了同一個 Subsystem。

小測驗

練習：取件動作

寫一個跨 Subsystem 的指令 intakeCycle(arm, intake)：先讓手臂移到 INTAKE，移動途中滾輪就開始吸入；手臂到位後繼續吸入 1 秒；最後停止吸入並把手臂收回 STOW。整個動作最多 4 秒。

整個動作是三步依序進行，第一步裡有兩件事同時發生，而且以手臂到位為準。

sequence 串起三步；第一步用 deadlineFor（主角是手臂）；「吸 1 秒」用 withTimeout(1.0)；整體上限用 withTimeout(4.0)。

第一步寫成 arm.goTo(ArmState.INTAKE).deadlineFor(intake.runState(IntakeState.INTAKING))；注意兩次 intake.runState(...) 要各自呼叫 factory，產生不同的物件。

public static Command intakeCycle(ArmSubsystem arm, IntakeSubsystem intake) {
    return Commands.sequence(
            arm.goTo(ArmState.INTAKE).deadlineFor(intake.runState(IntakeState.INTAKING)),
            intake.runState(IntakeState.INTAKING).withTimeout(1.0), // TODO: 實測
            arm.goTo(ArmState.STOW))
        .withTimeout(4.0)                                          // TODO: 實測
        .withName("IntakeCycle");
}

第一步用 deadline：手臂是主角，它到位時滾輪指令被打斷，runState 的結束動作把狀態設回 NONE，接著第二步立刻又開始吸入。兩次 intake.runState(...) 是兩個不同的物件，符合規則一。第三步結束時滾輪已經在 NONE。
