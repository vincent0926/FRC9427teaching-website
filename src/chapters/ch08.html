CAN ID 08｜WPILib 基礎

Subsystem 與 Command：借用體育館

Command-based 這個名字就是從這章來的。這章講一個指令從開始到結束會經過哪四個方法、requirements 怎麼避免兩個指令同時搶一個機構、指令被打斷時會怎樣，還有預設指令（default command）到底拿來幹嘛。

比喻：體育館借用規則

學校有幾間特別教室：體育館、音樂教室、實驗室，每種都只有一間，各有自己的設備和管理規則。別人要用，就要透過管理的老師。

要在體育館辦活動，得先在登記簿寫「這個活動要用體育館」。如果同時要用體育館跟音樂教室，兩間都要登記。

活動有固定的流程。開始時先集合、講規則，只做一次。進行中每隔一段時間做一輪，每一輪結束時負責人會看一下「活動結束了沒」。結束時收拾場地、還器材；如果是被中途趕走的，收拾的時候會多記一筆「被打斷」。

那兩個班搶同一間呢？三年二班正在用體育館，三年五班也跑來登記。學校預設的規則是後來的優先，正在用的被請出去，但場地一樣要收好。除非正在進行的活動門口掛了「請勿打擾」，那後來的就借不到，只能下次再來。

體育館沒人借的時候，體育股長會帶一個固定的自由活動。一有人登記，自由活動就收掉；等那個活動結束、體育館又空了，自由活動會自己再開始。

放假的時候，大部分活動都自動停。只有特別寫「放假也可以進行」的例外，像布告欄更新。

這個比喻哪裡不準學校的活動可以真的同時進行，但指令的四個方法是排程器在主迴圈裡一個一個呼叫的，跟第 7 章講的一樣，全部在同一條執行緒上。execute() 裡寫了等待迴圈，整台機器人都會卡住。還有，「後來的優先」只在搶同一個 Subsystem 時才成立，不同 Subsystem 的指令可以同時跑，互不相干。

Subsystem 的角色

Subsystem 的封裝、繼承和 IO 架構，第 2、3、6 章都講過了。這裡從排程器的角度補一句：Subsystem 是 Command-based 程式的基本單位，也是排程器拿來管資源的單位[2][4]。繼承 SubsystemBase 會在建構時自動向排程器註冊，所以 periodic() 每輪都會被叫到（第 3 章）。一個實體機構只能有一個 Subsystem 物件，就像體育館只有一間。

Command 的生命週期

指令有四個方法會被排程器呼叫[1]：

方法什麼時候被呼叫
initialize()指令被排程時，呼叫一次
execute()指令執行中，每輪呼叫一次
isFinished()每輪 execute() 之後檢查；回傳 true 時指令結束
end(boolean interrupted)指令結束時呼叫一次；被打斷或取消時 interrupted 為 true

拿第 6 章的手臂來寫一個完整的指令類別：

public class MoveArmToState extends Command {
    private final ArmSubsystem arm;
    private final ArmState target;

    public MoveArmToState(ArmSubsystem arm, ArmState target) {
        this.arm = arm;
        this.target = target;
        addRequirements(arm); // 登記借用
    }

    @Override
    public void initialize() {
        arm.setGoal(target);  // 集合：設定目標，只做一次
    }

    @Override
    public boolean isFinished() {
        return arm.atGoal();  // 到了就結束
    }

    @Override
    public void end(boolean interrupted) {
        if (interrupted) {
            // 被打斷：手臂仍保持目前的目標，這裡不需要特別處理
        }
    }
}

你會發現它沒有 execute()。因為目標是存在 Subsystem 裡的，Subsystem 的 periodic() 每輪會自己送出去（第 6 章 A-4），指令不用再做什麼。

Requirements：登記借用

每個指令都要把它控制的 Subsystem 宣告成 requirements。可以呼叫 addRequirements()，或是在大部分指令 factory 的最後一個參數傳 Subsystem 進去[1]。最省事的是直接用 Subsystem 自己的 run、runOnce、startEnd、runEnd，它們會自動 require 自己[1]。

// Subsystem 的 factory：自動 require arm
Command a = arm.runOnce(() -> arm.setGoal(ArmState.STOW));

// Commands 工具類別：要自己把 Subsystem 傳進去
Command b = Commands.runOnce(() -> arm.setGoal(ArmState.STOW), arm);

// 忘了傳 arm：可以編譯，但排程器不知道它在用手臂
Command bad = Commands.runOnce(() -> arm.setGoal(ArmState.STOW));

兩個指令搶同一個 Subsystem

新指令要用的 Subsystem 正在被別的指令用的時候，結果要看正在跑的那個指令的中斷行為。預設是 kCancelSelf：舊的被取消，新的排上去。如果是 kCancelIncoming：新的直接被丟掉，舊的繼續跑[1]。要注意這個設定只管 requirements 衝突的情況，任何指令還是隨時可以被取消[1]。

// 取件中不准被打斷
Command intakeNoInterrupt = intake.runState(IntakeState.INTAKING)
    .withInterruptBehavior(Command.InterruptBehavior.kCancelIncoming);

預設指令

預設指令會在它的 Subsystem 沒人用的時候自動排上去[3]。所以它很適合放「沒人用的時候該做的事」，像滾輪停下來、底盤交給搖桿控制：

// RobotContainer 建構子裡
intake.setDefaultCommand(intake.run(() -> intake.setState(IntakeState.NONE)));
drive.setDefaultCommand(
    drive.run(() -> drive.arcadeDrive(-controller.getLeftY(), -controller.getRightX())));

預設指令一定要 require 它所屬的 Subsystem，而且通常不應該自己結束，不然 Subsystem 一空下來它就會一直被重新排程。用 subsystem.run(...) 做，兩個條件剛好都滿足。

Disabled 時的指令

機器人 Disabled 的時候，指令預設是不跑的。有些東西 Disabled 也要跑（像更新遙測資料），可以加 ignoringDisable(true)[1]。但控制馬達的指令絕對不要這樣做。

動手試：搶體育館

下面的模擬器裡只有一支手臂。照順序排程指令，看誰被打斷、預設指令什麼時候跑回來。

常見錯誤

用 Commands 工具類別，卻忘了傳 Subsystem指令一樣會跑，但排程器不知道它在用機構，結果兩個指令可能同時在控制同一顆馬達。盡量用 Subsystem 自己的 factory，就不會漏。
預設指令自己會結束像是拿 runOnce 當預設指令，它一結束 Subsystem 就空了，下一輪又被排上去，變成每輪都在重複 initialize 和 end。預設指令請用 run。
在 execute() 裡等東西跟第 7 章一樣，指令裡寫 while 迴圈或 sleep 會卡死整個主迴圈。要等某件事發生，就讓 isFinished() 回傳那個條件。
教練提醒寫任何指令之前先問自己：「它控制了哪些機構？」答案就是它的 requirements。Code review 看到控制馬達卻沒有 requirements 的指令，一律退回。

小測驗

練習：Intake 的指令

幫 IntakeSubsystem 寫一個 factory runState(IntakeState state)：執行時把狀態設成 state，結束（包括被打斷）時設回 NONE。然後把它的預設指令也寫出來。

「開始做一件事、結束做另一件事」，Subsystem 有現成的 factory 可以用。

用 startEnd(開始動作, 結束動作)，被打斷時也會執行結束動作；預設指令要持續執行，用 run。

runState 回傳 startEnd(() -> setState(state), () -> setState(IntakeState.NONE))；預設指令是 intake.run(() -> intake.setState(IntakeState.NONE))。

// IntakeSubsystem 裡
public Command runState(IntakeState state) {
    return startEnd(() -> setState(state), () -> setState(IntakeState.NONE));
}

// RobotContainer 建構子裡
intake.setDefaultCommand(intake.run(() -> intake.setState(IntakeState.NONE)));

startEnd 開始時跑第一個動作，結束時跑第二個，不管是正常結束還是被打斷。它自己不會結束，要靠放開按鍵或被別的指令打斷才會停，第 9、10 章會用到這個特性。
