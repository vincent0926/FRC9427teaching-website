Subsystem 與 Command：借用體育館

讀完這章，你會知道 Command 的四個生命週期方法、requirements 怎麼避免兩個指令搶同一個機構、指令被打斷時會發生什麼事，以及預設指令（default command）的用途。

生活比喻：體育館借用規則

學校有幾間特別教室。體育館、音樂教室、實驗室，每一間都只有一間。它們有自己的設備和管理規則，別人要用，必須透過管理的老師。

每個活動都要先登記借用。一個班要在體育館辦活動，必須先在登記簿寫下「這個活動要用體育館」。如果活動同時要用體育館和音樂教室，兩間都要登記。

一個活動有固定的流程。活動開始時先集合、說明規則，這只做一次。活動進行中，每隔一段時間做一輪。每一輪結束時，負責人會看一下「活動結束了沒」。結束時收拾場地、歸還器材；如果活動是被中途趕走的，收拾時會特別記一筆「被打斷」。

兩個活動搶同一間教室。三年二班正在用體育館，三年五班也來登記。學校的預設規則是：後來的人優先，正在進行的活動被請出去，照樣要收拾場地。但如果正在進行的活動門口掛了「請勿打擾」，後來的人就借不到，只能等下次。

體育館沒人借的時候。體育館沒有任何活動登記時，體育股長會帶一個固定的自由活動。一旦有人登記，自由活動就結束；等那個活動結束、體育館又空下來，自由活動會自動重新開始。

放假時的規定。學校放假時，大部分活動自動停止。只有特別註明「放假也可以進行」的活動例外，例如布告欄更新。

這個比喻哪裡不準學校的活動可以同時做很多事，但指令的四個方法是由排程器在主迴圈裡依序呼叫的，和第 7 章講的一樣，全部在同一條執行緒上。execute() 裡如果寫了等待迴圈，整台機器人都會卡住。另外，「後來的人優先」只適用於搶同一個 Subsystem 的情況；不同 Subsystem 的指令可以同時執行，互不干擾。

Subsystem 的角色

第 2、3、6 章已經分別講過 Subsystem 的封裝、繼承和 IO 架構。這裡只補上排程器的觀點：WPILib 文件說明 Subsystem 是 Command-based 程式組織的基本單位，也是排程器用來管理資源的單位[2]。繼承 SubsystemBase 會在建構時自動向排程器註冊，periodic() 因此每輪被呼叫（第 3 章）。每個實體機構只應該有一個 Subsystem 物件，就像體育館只有一間。

Command 的生命週期

WPILib 文件說明，指令有四個會被排程器呼叫的方法[1]：

方法什麼時候被呼叫
initialize()指令被排程時，呼叫一次
execute()指令執行中，每輪呼叫一次
isFinished()每輪 execute() 之後檢查；回傳 true 時指令結束
end(boolean interrupted)指令結束時呼叫一次；被打斷或取消時 interrupted 為 true

延續第 6 章的手臂，一個完整的指令類別：

public class MoveArmToState extends Command {
    private final ArmSubsystem arm;
    private final ArmState target;

    public MoveArmToState(ArmSubsystem arm, ArmState target) {
        this.arm = arm;
        this.target = target;
        addRequirements(arm); // 登記借用
    }

    @Override
    public void initialize() {
        arm.setGoal(target);  // 集合：設定目標，只做一次
    }

    @Override
    public boolean isFinished() {
        return arm.atGoal();  // 到了就結束
    }

    @Override
    public void end(boolean interrupted) {
        if (interrupted) {
            // 被打斷：手臂仍保持目前的目標，這裡不需要特別處理
        }
    }
}

這個指令不需要 execute()，因為目標保存在 Subsystem 裡，由 Subsystem 的 periodic() 每輪送出（第 6 章 A-4）。

Requirements：登記借用

WPILib 文件要求每個指令都要把它控制的 Subsystem 宣告為 requirements；宣告方式包括呼叫 addRequirements()，或在大多數指令 factory 的參數最後傳入 Subsystem[1]。Subsystem 本身提供的 run、runOnce、startEnd、runEnd 等 factory 會自動 require 自己[1]。

// Subsystem 的 factory：自動 require arm
Command a = arm.runOnce(() -> arm.setGoal(ArmState.STOW));

// Commands 工具類別：要自己把 Subsystem 傳進去
Command b = Commands.runOnce(() -> arm.setGoal(ArmState.STOW), arm);

// 忘了傳 arm：可以編譯，但排程器不知道它在用手臂
Command bad = Commands.runOnce(() -> arm.setGoal(ArmState.STOW));

兩個指令搶同一個 Subsystem

當新的指令要借用的 Subsystem 正被另一個指令使用時，結果取決於正在執行的那個指令的中斷行為。WPILib 文件說明：預設是 kCancelSelf，目前的指令會被取消，新指令排程成功；如果是 kCancelIncoming，新指令的排程會被放棄，目前的指令繼續執行[1]。文件也提醒，這個設定只影響 requirements 衝突時的處理，任何指令都還是可以被取消[1]。

// 取件中不准被打斷
Command intakeNoInterrupt = intake.runState(IntakeState.INTAKING)
    .withInterruptBehavior(Command.InterruptBehavior.kCancelIncoming);

預設指令

WPILib 文件說明，預設指令會在它的 Subsystem 沒被使用時自動排程[3]。適合用來放「沒人要用時該做的事」，例如滾輪停止、底盤由搖桿控制：

// RobotContainer 建構子裡
intake.setDefaultCommand(intake.run(() -> intake.setState(IntakeState.NONE)));
drive.setDefaultCommand(
    drive.run(() -> drive.arcadeDrive(-controller.getLeftY(), -controller.getRightX())));

預設指令必須 require 它所屬的 Subsystem，而且通常不應該自己結束，否則 Subsystem 空下來時它會一再被重新排程。用 subsystem.run(...) 建立正好兩個條件都滿足。

Disabled 時的指令

指令預設在機器人 Disabled 時不會執行。需要在 Disabled 時也運作的（例如更新遙測資料），可以用 ignoringDisable(true)[1]。控制馬達的指令不應該這樣做。

常見錯誤

用 Commands 工具類別卻忘了傳 Subsystem指令照樣能跑，但排程器不知道它在用機構，兩個指令就可能同時控制同一個馬達。優先使用 Subsystem 自己的 factory，就不會漏。
預設指令會自己結束例如用 runOnce 當預設指令，它結束後 Subsystem 空了，下一輪又被排程，每輪重複執行 initialize 和 end。預設指令用 run。
在 execute() 裡等待和第 7 章一樣：在指令裡寫 while 迴圈或 sleep 會卡住整個主迴圈。要等某件事發生，就讓 isFinished() 回傳那個條件。
教練提醒寫任何指令前，先問自己：「它控制哪些機構？」答案就是它的 requirements。Code review 時，看到控制馬達卻沒有 requirements 的指令，一律退回。

小測驗

練習：Intake 的指令

替 IntakeSubsystem 寫一個 factory runState(IntakeState state)：執行時把狀態設為 state，結束（包括被打斷）時設回 NONE。再寫出它的預設指令。

要「開始時做一件事、結束時做另一件事」，Subsystem 有現成的 factory。

用 startEnd(開始動作, 結束動作)，被打斷時也會執行結束動作；預設指令要持續執行，用 run。

runState 回傳 startEnd(() -> setState(state), () -> setState(IntakeState.NONE))；預設指令是 intake.run(() -> intake.setState(IntakeState.NONE))。

// IntakeSubsystem 裡
public Command runState(IntakeState state) {
    return startEnd(() -> setState(state), () -> setState(IntakeState.NONE));
}

// RobotContainer 建構子裡
intake.setDefaultCommand(intake.run(() -> intake.setState(IntakeState.NONE)));

startEnd 在開始時執行第一個動作，結束時執行第二個，不管是正常結束還是被打斷。它本身不會自己結束，要靠按鍵放開或其他指令打斷，這點在第 9、10 章會用到。
