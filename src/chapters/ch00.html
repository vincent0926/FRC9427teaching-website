CAN ID 00｜準備

開發環境與專案結構：開學前的準備

寫程式之前，電腦要先準備好。這章會帶你裝軟體、建第一個專案、認識專案裡那一堆檔案，順便學會用 Git 把程式存好，最後把程式送上機器人。東西有點雜，但每一步都會用到，跳過的話後面一定會卡。

版本說明這章是照 2026 賽季的官方文件寫的（WPILib 2026.2.1、Phoenix 6 2026 版）。WPILib 已經在做 2027 年的 Systemcore 控制系統[9]，到時候安裝流程和套件名稱大概會變，看到這裡的時候如果已經是 2027 年，請以當年的文件為準。

先講個比喻：開學前的準備

想像程式組每年都會分到一間專用教室，門牌上寫著年份，像是「2026 程式教室」。上課就是要進這間，不能在自己家的書桌上課，因為家裡的書桌堆了一堆別的東西，習慣也不一樣，拿來上這門課很容易出包。去年的教室也不用拆，新舊兩間可以同時存在。

教室裡的課本、字典、計算機、印表機，學校一次幫你配好，而且跟你家裡的東西分開放。你不用自己去買，學校發了新字典也不會把你家那本換掉。

課本以外的參考書，例如某家出版社的馬達專書，不是塞在書包裡就算數，要寫進班級書單。書單是跟著班級走的，誰拿到這個班的書單，就知道要準備哪幾本、哪個版本。換新學年，書單上的版本也要重新確認一次。

教室的配置是固定的。門口有警衛室，負責開門讓大家進來，學生不用、也不該進去亂改。黑板旁邊貼著課表和鐘聲時間，決定每節課什麼時候開始和結束。講桌上有座位表和幹部名單，寫清楚誰坐哪、誰負責什麼。後面有公布欄，貼著全班都要遵守的規定。角落還有一個置物櫃，裡面的東西會跟著全班一起帶去校外教學。

作業在家寫完要交到學校，但交之前要先自己檢查有沒有錯字，檢查沒過的作業學校不收。

什麼時候上課、什麼時候下課，是導護老師用廣播決定的，學生不能自己決定。真的出事的時候，導護老師會按緊急鈴，所有活動馬上停，而且要等學校重新檢查過才能恢復。

還有一點：教室不要設在那種會自動幫你把東西搬來搬去的倉庫。你東西用到一半，它突然被搬走，那就很麻煩了。

這個比喻哪裡不準故事裡寫作業和上課在同一間教室，但實際上你是在筆電上寫程式，程式卻是跑在機器人上的 roboRIO。部署完之後程式就存在 roboRIO 裡了，筆電關機、網路線拔掉都沒差，機器人重開機還是會跑最後一次部署的那份程式。筆電上的 Driver Station 只負責下 Enable、Disable 這類指令，還有傳搖桿資料。

安裝時容易踩的雷

WPILib 會另外裝一份 VS Code，不會用你電腦原本那份。每年各一份，名稱會帶年份，像 WPILib VS Code 2026。打開專案的時候要開這一份，不是系統原本的 VS Code[1]，這個新手超常搞錯。

它附的 JDK 會和你電腦裡其他 JDK 共存，不會去動 JAVA_HOME[1]，所以你之前裝過 Java 也不用擔心。

不要用 VS Code 的設定同步功能，在一般 VS Code 和 WPILib VS Code 之間同步設定，官方說這樣可能會讓其中一邊壞掉[1]。

WPILib 每年都裝在不同資料夾，去年的版本不用先移除[1]。不過去年的專案要用匯入功能轉成今年的格式，vendor 函式庫也要重新加一次，因為去年的版本跟今年的專案不相容[1]。

建一個新專案

在 WPILib VS Code 按 Ctrl+Shift+P，打 WPILib，選 Create a new project[3]。專案類型選 Template、語言選 Java、範本選 Command Robot。Command-based 範本是建在 TimedRobot 上的，官方也很推薦新隊伍用這個[3]，我們隊上也是用這個。

建立的時候要填隊號。隊號會拿來當專案的套件名稱，部署時也是靠它找到機器人[3]，它存在專案的 .wpilib/wpilib_preferences.json 裡。

專案不要放在 OneDrive官方直接講明不支援在 OneDrive 上建專案，因為 OneDrive 的快取會干擾建置系統。麻煩的是有些 Windows 預設就把「文件」和「桌面」放在 OneDrive 上[3]，你可能自己都沒發現。最簡單的做法是開一個 C:\frc\ 之類的資料夾，機器人專案全部放那邊。

專案裡有什麼

Command-based 專案建好之後大概長這樣，我只列你現在需要知道的：

MyRobot/
├── build.gradle                  // 建置設定（GradleRIO），一般不需要改
├── .wpilib/
│   └── wpilib_preferences.json   // 隊號、年份等專案設定
├── vendordeps/
│   ├── WPILibNewCommands.json    // Command-based 函式庫
│   └── Phoenix6-(版本).json       // 加入 Phoenix 6 後才會出現
└── src/main/
    ├── deploy/                   // 會一起上傳到 roboRIO 的檔案
    └── java/frc/robot/
        ├── Main.java             // 程式進入點，不要改
        ├── Robot.java            // 控制流程，第 7 章的主角
        ├── RobotContainer.java   // 建立 Subsystem、綁定按鍵
        ├── Constants.java        // 全機共用的常數
        ├── commands/             // 自己寫的 Command
        └── subsystems/           // 自己寫的 Subsystem

四個主要類別

Command-based 範本主要是這幾個類別[4]：

類別官方定位比喻
Main程式的主應用程式（只有 Java 有）。新手不應該修改警衛室
Robot負責程式的主要控制流程。在 Command-based 專案裡應該幾乎是空的課表和鐘聲
RobotContainer放置 Subsystem 和 Command，大部分的設定（例如按鍵綁定）都在這裡座位表和幹部名單
Constants放整個機器人都能使用的常數公布欄

Main 裡的 main() 不要碰。除非你非常確定自己在幹嘛，否則就讓它保持原樣[3]。

vendordeps：班級書單

像 CTRE 的 Phoenix 6 這種第三方函式庫，是用一個 JSON 檔來描述的。加進專案的時候，這個 JSON 會被複製到 vendordeps 資料夾，專案就會把它當成依賴[5]。WPILib 自己的新版 Command 函式庫其實也拆成了 vendor 函式庫，所以 Command-based 專案一開始就會有一個 WPILibNewCommands.json[5]。

加 Phoenix 6 的方法：點 WPILib VS Code 左側邊欄的 WPILib 圖示，在 Available Dependencies 找到 CTRE-Phoenix (v6)，按 Install。之後要更新也是在同一頁按 To Latest[6]。

書單是跟著專案走的，隊友從 Git 拉專案下來的時候 vendordeps 會一起下來，大家的版本自然就一樣。這也是 vendor 函式庫要每個專案各加一次的原因。

deploy 資料夾：跟著去校外教學的置物櫃

放在 src/main/deploy 裡的檔案，部署的時候會一起傳到 roboRIO 的 /home/lvuser/deploy[8]。第 16 章的自動路徑檔就是放這裡。程式裡要拿這個資料夾的位置，用 Filesystem.getDeployDirectory()，不要自己把路徑寫死[8]。

編譯與部署

在 WPILib 選單選 Deploy Robot Code，或直接按 Shift+F5。它會視需要先編譯，再把程式送到 roboRIO。成功的話會看到 Build Successful，接著跳出 RioLog 顯示機器人程式的輸出[7]。部署到一半千萬不要把機器人電源關掉[7]。

Build 和 Deploy 有個差別要知道：Build Robot Code 會上網下載依賴、跑單元測試，Deploy Robot Code 不會[7]。所以你新增或更新 vendordep 之後，要找有網路的地方先 Build 一次。

教練提醒：出發比賽前，在家 Build 一次比賽場館的網路很不可靠，而且機器人連的是場地的無線網路。出發前一定要在有網路的地方把專案完整 Build 過，確定依賴都下載到筆電上了，不然到現場你會發現怎麼樣都部署不上去。

用 Git 和 GitHub 管程式

隊上的程式都放在 GitHub。在開始寫程式之前，先學會怎麼把程式存好、分享給別人，這比你想的重要很多。

假設全班共用一本作業本，正本鎖在導師辦公室的櫃子裡，每個人可以借一份影本回家寫。

作業本最後一頁是日誌。每寫完一段，就記下日期、誰寫的、改了什麼，像是「修正手臂角度上限」。之後發現哪裡錯了，就翻日誌找是哪一次改壞的，需要的話把那段恢復成改之前的樣子。

在家寫完、日誌也記好了，要把改動交回辦公室併進正本，別人才看得到。反過來，開始寫之前也要先去辦公室拿最新版，不然你就是在舊影本上寫。

如果兩組人同時在改不同章節，就各自先寫草稿，寫好、檢查過再合併進正本。這樣一組寫到一半的東西不會把另一組搞亂。

草稿紙、計算用的便條紙這種每個人自己產生的東西，不用收進正本。學校有一張清單列出哪些不收，這張清單不要自己去改。

比喻Git指令
辦公室裡的正本GitHub 上的遠端儲存庫（remote）
借一份影本回家複製（clone）git clone 網址
寫一行日誌提交（commit）git add . 再 git commit -m "說明"
交回正本推送（push）git push
拿最新版本拉取（pull）git pull
分組寫草稿分支（branch）git branch 名稱、git checkout 名稱
草稿合併進正本合併（merge）git merge 名稱
不收進作業本的清單.gitignore

WPILib 建出來的專案本來就附一個 .gitignore，裡面列了不需要提交的檔案（例如編譯產生的東西）。這個檔案絕對不要改，官方特別強調過[11]。上面表格的指令也都是從 WPILib 的 Git 入門文件來的[11]。WPILib VS Code 左邊的「原始檔控制」面板，大部分操作按按鈕就能做完，不過還是建議先搞懂指令在做什麼，出問題的時候才知道怎麼救。

這個比喻哪裡不準作業本的日誌只是一筆紀錄，但 Git 的每個 commit 存的是當下「所有檔案的完整狀態」，所以你可以整個退回任何一個 commit。還有，commit 只存在你自己的電腦上，push 之後 GitHub 上才會有。電腦壞掉的話，還沒 push 的 commit 就一起沒了。
教練提醒：部署前先 commit每次部署到機器人之前都先 commit 一次，訊息寫清楚改了什麼。比賽中機器人突然怪怪的時候，你才知道現在機器人上跑的是哪一版，必要時可以馬上退回上一個會動的版本。每天練完一定要 push，不要讓全隊唯一的一份程式只存在某一台筆電裡。

Driver Station：導護老師

Driver Station 是 FRC Game Tools 的一部分，只能在 Windows 上跑[2]。選模式、Enable 和 Disable 機器人、傳搖桿資料，都是它在做。模式的部分第 7 章會細講，現在先把這幾個快捷鍵記起來[10]：

按鍵功能
[ ] \ 同時按Enable 機器人
EnterDisable 機器人
空白鍵緊急停止（E-Stop）。觸發後必須重新啟動 roboRIO 才能再次 Enable

要注意，比賽時連上 FMS 之後，這些 Enable、Disable、E-Stop 快捷鍵通通沒用，要停只能按場地操作台上的 E-Stop 按鈕[10]。

教練提醒：Enable 前一定要喊每次 Enable 前都大聲喊「Enable！」，確定機器人旁邊沒有人、沒有人的手在機構裡，手指隨時放在空白鍵或 Enter 上。這是隊上的安全規定，沒有例外，學長姐也一樣要喊。

常見錯誤

開錯 VS Code用系統原本的 VS Code 開機器人專案，會找不到 WPILib 選單，也沒辦法建置。看一下標題列或開始選單，確定開的是 WPILib VS Code 2026。
忘了加 vendordepimport com.ctre.phoenix6... 出現紅色底線、編譯失敗，通常就是這個專案還沒加 Phoenix 6。去 vendordeps 資料夾看有沒有對應的 JSON。
隊號打錯部署時找不到機器人，先打開 .wpilib/wpilib_preferences.json 看隊號是不是 9427。

小測驗

練習：建你的第一個專案

照著這章做一遍，最後回答問題：

在 C:\frc\（或任何不在 OneDrive 上的資料夾）建一個 Java 的 Command Robot 專案，隊號填 9427。用 Dependency Manager 加入 CTRE-Phoenix (v6)，然後跑一次 Build Robot Code。跑完之後打開 vendordeps 資料夾，裡面有幾個 JSON？分別是什麼？

建專案用 WPILib 指令面板（Ctrl+Shift+P → WPILib: Create a new project），加函式庫用 Dependency Manager。

Phoenix 6 在 Dependency Manager 裡叫 CTRE-Phoenix (v6)，加完之後描述檔會出現在專案的 vendordeps 資料夾。

Command-based 範本本來就附一個 JSON，加完 Phoenix 6 應該要多一個。如果還是只有一個，就是沒加成功。

應該有兩個：一個是 Command-based 範本本來就有的 WPILibNewCommands.json，另一個是剛加的 Phoenix 6 JSON（檔名看版本）。只有一個的話，代表 Phoenix 6 沒加成功；如果 Build 失敗而且提到下載錯誤，確認電腦有連網路再試一次。
