Phoenix 6 與 TalonFX：班長的工作手冊

讀完這章，你會知道怎麼在 CANivore「9427」上建立 TalonFX、怎麼寫一份完整的設定、各種控制請求的差別、沒有 Pro 授權時 FOC 會怎樣，以及 Phoenix Tuner X 能幫你做什麼。

版本說明本章依據 Phoenix 6 的 2026 版（26.x）文件。CTRE 網站上標示 latest 的文件已經是 2027 年版本，查資料時請看 stable 版。

生活比喻：班長的工作手冊

班長很能幹。第 6 章說過，班長（TalonFX）自己會控制怎麼帶隊。導師只要說「去禮堂」，走多快、怎麼轉彎，班長自己處理，而且反應比導師快得多。

上任時發一整本工作手冊。班長上任時，導師發給他一整本工作手冊：往哪個方向算前進、休息時要站好還是可以放鬆、最多能讓同學跑多累、帶隊的速度規定。手冊裡沒寫到的項目，一律照學校的預設規定。所以不需要先把舊手冊撕掉再發新的，發一本完整的新手冊，就等於所有舊規定都被換掉了。

交代事情用固定格式的單子。平常導師交代班長，是用學校統一格式的交辦單：「用這個力道帶隊」、「帶到這個位置」、「用這個速度走」。同一種單子印一張就好，每次改上面的數字再交出去，不用每次重印。

力道的說法有好幾種。「用全力的六成」，這個說法會受當天體力影響，同學累的時候六成就沒那麼快。「用固定的力氣」，不管累不累都一樣，比較穩定。還有一種最精準的「直接控制出多少力」，但只有拿到進階證照的班長才能用。

沒有進階證照也不會出錯。交辦單上如果勾了「用進階技巧」，但班長沒有進階證照，他會自動改用一般的方法完成，不會因此拒絕做事。

兩條廣播線。學校舊大樓有一條共用的廣播線，新大樓另外拉了一條速度更快的專線，這條專線有自己的名字，叫「9427」。導師找班長時，要說清楚班長在哪一條線上。同一條線上，每個班長的代號不能重複，不然廣播叫號時兩個人會同時回應。

學務處有一套幹部管理系統。學務處可以用這套系統幫班長設定代號和名字、讓某個班長舉手讓你找到他在哪裡、更新他的訓練、做健康檢查、畫出他最近的表現紀錄，也可以直接下指令測試。

建立 TalonFX：指定 CAN bus

Phoenix 6 的 2026 年更新說明寫明，用字串指定 CAN bus 的建構子已被標為 deprecated，預計 2027 年移除，應改用傳入 CANBus 物件的建構子[4]。只給 CAN ID、不給 bus 的建構子，會使用系統預設的 CAN bus，在 roboRIO 上就是內建的 CAN[5]。

import com.ctre.phoenix6.CANBus;
import com.ctre.phoenix6.hardware.TalonFX;

public final class CANBuses {
    private CANBuses() {}

    /** 隊上的 CANivore，名稱必須和 Tuner X 裡設定的一致。 */
    public static final CANBus CANIVORE = new CANBus("9427");
}

// 在 CANivore 上
TalonFX armLeader = new TalonFX(21, CANBuses.CANIVORE);  // TODO: 依接線
// 在 roboRIO 內建 CAN 上
TalonFX other = new TalonFX(5);                          // TODO: 依接線

把 CANBus 集中宣告在一個地方，名字打錯的機會就只有一次。第 5 章的 Constants 也可以用同樣的方式。

寫一份完整的設定

CTRE 文件說明，新建立的設定物件本身就包含裝置的所有預設值，所以在套用修改過的完整設定之前，不需要先恢復出廠設定；想要恢復出廠設定，只要套用一個全新的設定物件[1]。遷移指南也寫明，完整設定物件中沒有修改的項目會被自動恢復為預設值[2]。

TalonFXConfiguration config = new TalonFXConfiguration();

// 方向與休息狀態
config.MotorOutput.Inverted = InvertedValue.CounterClockwise_Positive; // TODO: 上機確認
config.MotorOutput.NeutralMode = NeutralModeValue.Brake;

// 電流限制：保護馬達、電池和斷路器
config.CurrentLimits.StatorCurrentLimit = 0.0;        // TODO
config.CurrentLimits.StatorCurrentLimitEnable = true;
config.CurrentLimits.SupplyCurrentLimit = 0.0;        // TODO
config.CurrentLimits.SupplyCurrentLimitEnable = true;

// 齒輪比：之後讀到的位置、速度都是機構端
config.Feedback.SensorToMechanismRatio = 1.0;         // TODO

// 只在建構時套用一次
armLeader.getConfigurator().apply(config);

CTRE 文件提醒，apply() 是會等待裝置回應的阻塞呼叫[1]，所以絕對不要放進 periodic。也可以只套用其中一組，例如 armLeader.getConfigurator().apply(config.MotorOutput)，這時只有那一組會被改動[1]，第 6 章的 setBrakeMode 就是這樣做的。

完整設定會覆蓋所有東西如果程式裡有兩個地方各套用一次「完整」的 TalonFXConfiguration，後套用的那一份會把前一份的所有設定蓋回預設值，而不是只加上自己改的部分。同一顆馬達的完整設定只寫在一個地方。

控制請求：交辦單

控制請求物件建立一次，之後用 with... 方法修改數值再送出，這是 CTRE 官方範例的寫法[9]。常用的請求：

請求做什麼本課程用在
DutyCycleOut輸出百分比（-1 到 1）很少用
VoltageOut輸出指定電壓滾輪、SysId
PositionVoltage控制器內 PID 追蹤位置第 13 章
VelocityVoltage控制器內 PID 追蹤速度飛輪（第 13 章）
MotionMagicVoltage產生梯形或 S-curve 軌跡並追蹤手臂（第 6、14 章）
NeutralOut停止輸出，依 NeutralMode 煞車或滑行停止
Follower跟隨另一顆馬達手臂 follower（第 6 章 C 部分）
TorqueCurrentFOC 等直接控制轉矩電流需要 Pro 授權

CTRE 文件說明，電壓類控制請求的輸出通常不受供電電壓影響（輸出電壓上限仍受供電電壓限制），所以比 DutyCycle 類請求更穩定、結果更容易重現；TorqueCurrentFOC 則需要 Pro 授權[3]。所以本課程一律用 Voltage 類的請求。

EnableFOC 與 Pro 授權

FOC（Field Oriented Control）是一種換相方式，CTRE 說明它能讓峰值功率提高約 15%，而支援 FOC 的控制請求都有一個 EnableFOC 欄位[3]。這個欄位在 API 裡的預設值是 true，使用 FOC 需要 Phoenix Pro 授權[6]。

第 6 章留下的問題在這裡有了答案：CTRE 文件寫明，控制未授權的裝置時，支援 EnableFOC 的控制請求會自動退回一般（非 FOC）換相[3]。所以沒有 Pro 授權時，不改 EnableFOC 也能正常運作，只是沒有 FOC 的效能提升。只有 TorqueCurrentFOC 這類本身就依賴 FOC 的請求，才真的需要 Pro。

模擬時要對應第 6 章 D 部分提過：CTRE 的模擬範例用 DCMotor.getKrakenX60Foc。沒有 Pro 授權的隊伍，實機跑的是一般換相，模擬時就應該用 DCMotor.getKrakenX60，兩邊才一致。

讀取感測資料

TalonFX 的讀值是用 StatusSignal 取得的。第 6 章 C 部分已經示範完整寫法：把訊號存成欄位，每個週期用 BaseStatusSignal.refreshAll(...) 一次刷新，再用 getValueAsDouble() 取值[8]。要記得兩件事：Phoenix 6 的位置單位是轉數（rotations）、速度是每秒轉數；設定了 SensorToMechanismRatio 之後，讀到的就是機構端的數值。

Phoenix Tuner X

CTRE 的說明文章列出 Tuner X 能做的事：設定裝置的名稱與 ID、讓裝置閃燈以便在機器人上找到它、把所有裝置的韌體更新到最新版、在 Windows 或 Android 上直接控制單顆馬達、畫出速度與位置等訊號，以及對裝置做 Self Test[7]。

新機器人第一次通電時，建議的順序是：

  1. 用 Tuner X 找到所有裝置，逐一閃燈，確認每一顆在機器人上的位置。
  2. 設定 CAN ID，同一條 bus 上不可重複；隊上可以約定編號規則，例如手臂用 20 幾號。
  3. 把 CANivore 命名為「9427」，和程式裡的 new CANBus("9427") 一致。
  4. 把所有裝置的韌體更新到最新版。
  5. 用低電壓手動轉動每顆馬達，確認方向，再把結果寫進程式的 Inverted 設定。
  6. 把 CAN ID 對照表寫進 Constants，並貼在機器人上。
教練提醒：在 Tuner X 手動轉馬達前先確認機構周圍沒有人、機構不會撞到極限位置，並從很低的輸出開始。手臂這類有重力的機構，放開控制時可能會掉下來。

常見錯誤

CAN bus 名稱打錯new CANBus("9247") 這種錯字不會編譯失敗，但程式找不到裝置，讀值全部失敗、馬達不動。把名稱集中在一個常數裡，並和 Tuner X 顯示的名稱對照。
CAN ID 重複同一條 bus 上兩顆裝置 ID 相同，會互相干擾，Tuner X 會標示重複的裝置。模擬時更嚴格：第 6 章 D 部分提過，模擬時所有 bus 會合併，ID 必須全機唯一。
在 periodic 裡套用設定apply() 會等待裝置回應，放在 periodic 裡會拖慢每一輪，還可能造成 loop overrun（第 7 章）。
用 DutyCycleOut 做需要重現的控制電池從滿電到快沒電時，同樣的百分比會得到不同的速度，調好的參數會跟著失準。用 Voltage 類請求。

小測驗

練習：幫 Intake 滾輪寫硬體層

替第 6 章練習的 RollerIO 寫 RollerIOHardware：滾輪馬達在 CANivore「9427」上、CAN ID 待定；設定為 Coast、開啟供電電流限制（數值待定）；setVoltage 使用重複使用的 VoltageOut；updateInputs 讀取速度、輸出電壓、供電電流。

照第 6 章 ArmIOHardware 的結構：欄位裡建立 TalonFX、控制請求和要讀的訊號，建構子套用設定。

CANivore 用 new TalonFX(id, CANBuses.CANIVORE)；請求用 new VoltageOut(0.0) 建一次；訊號用 getVelocity()、getMotorVoltage()、getSupplyCurrent()。

updateInputs 裡先 BaseStatusSignal.refreshAll(...)，用 .isOK() 填 connected，再用 getValueAsDouble() 取值；setVoltage 寫 motor.setControl(request.withOutput(volts))。

public class RollerIOHardware implements RollerIO {
    private final TalonFX motor = new TalonFX(0, CANBuses.CANIVORE); // TODO: CAN ID
    private final VoltageOut request = new VoltageOut(0.0);

    private final StatusSignal<AngularVelocity> velocity = motor.getVelocity();
    private final StatusSignal<Voltage> appliedVolts = motor.getMotorVoltage();
    private final StatusSignal<Current> supplyCurrent = motor.getSupplyCurrent();

    public RollerIOHardware() {
        TalonFXConfiguration config = new TalonFXConfiguration();
        config.MotorOutput.NeutralMode = NeutralModeValue.Coast;
        config.MotorOutput.Inverted = InvertedValue.CounterClockwise_Positive; // TODO: 上機確認
        config.CurrentLimits.SupplyCurrentLimit = 0.0;                         // TODO
        config.CurrentLimits.SupplyCurrentLimitEnable = true;
        motor.getConfigurator().apply(config);
    }

    @Override
    public void updateInputs(RollerIOInputs inputs) {
        inputs.connected = BaseStatusSignal.refreshAll(velocity, appliedVolts, supplyCurrent).isOK();
        inputs.velocityRps = velocity.getValueAsDouble();
        inputs.appliedVolts = appliedVolts.getValueAsDouble();
        inputs.supplyCurrentAmps = supplyCurrent.getValueAsDouble();
    }

    @Override
    public void setVoltage(double volts) {
        motor.setControl(request.withOutput(volts));
    }
}

滾輪用 Coast：停止時讓滾輪自然停下，不會卡住遊戲物件。手臂則用 Brake（第 6 章），因為手臂要撐住重力。這是隊上依機構決定的，不是固定規則。
