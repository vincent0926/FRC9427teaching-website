CAN ID 11｜硬體

Phoenix 6 與 TalonFX：班長的工作手冊

隊上的馬達幾乎都是 TalonFX，所以這章會常常用到。內容包括怎麼在 CANivore「9427」上建立 TalonFX、怎麼寫一份完整的設定、各種控制請求差在哪、沒有 Pro 授權的時候 FOC 會怎樣，最後介紹 Phoenix Tuner X。

版本說明這章是照 Phoenix 6 的 2026 版（26.x）文件寫的。CTRE 網站上標 latest 的已經是 2027 年版了，查資料記得切到 stable。

比喻：班長的工作手冊

第 6 章說過，班長（TalonFX）自己會處理怎麼帶隊。導師只要講「去禮堂」，走多快、怎麼轉彎都是班長的事，而且他反應比導師快很多。

班長上任的時候，導師會發一整本工作手冊給他：哪個方向算前進、休息時要站好還是可以放鬆、最多能讓同學跑多累、帶隊速度的規定。手冊沒寫到的，就照學校的預設。所以不用先把舊手冊撕掉再發新的，直接發一本完整的新手冊，舊規定就全部被換掉了。

平常導師交代事情，是用學校統一格式的交辦單：「用這個力道帶隊」、「帶到這個位置」、「用這個速度走」。同一種單子印一張就夠了，每次改上面的數字再交出去，不用每次重印。

講力道有好幾種說法。「用全力的六成」會受當天體力影響，同學累的時候六成就沒那麼快。「用固定的力氣」就不管累不累都一樣，比較穩。還有一種最精準的「直接控制出多少力」，不過只有拿到進階證照的班長能用。

交辦單上如果勾了「用進階技巧」，可是班長沒有進階證照，他會自己改用一般的方法做完，不會因此拒絕做事。

學校的舊大樓有一條共用的廣播線，新大樓另外拉了一條更快的專線，名字叫「9427」。導師找班長的時候要講清楚他在哪一條線上。同一條線上每個班長的代號不能重複，不然一叫號兩個人會同時回應。

另外學務處有一套幹部管理系統，可以幫班長設定代號和名字、叫某個班長舉手讓你找到他、更新他的訓練、做健康檢查、畫出他最近的表現，也可以直接下指令測試。

建立 TalonFX：指定 CAN bus

Phoenix 6 在 2026 年把「用字串指定 CAN bus」的建構子標成 deprecated，預計 2027 年拿掉，要改用傳 CANBus 物件的版本[4]。如果只給 CAN ID、不給 bus，就會用系統預設的 CAN bus，在 roboRIO 上就是內建那條[5]。

import com.ctre.phoenix6.CANBus;
import com.ctre.phoenix6.hardware.TalonFX;

public final class CANBuses {
    private CANBuses() {}

    /** 隊上的 CANivore，名稱必須和 Tuner X 裡設定的一致。 */
    public static final CANBus CANIVORE = new CANBus("9427");
}

// 在 CANivore 上
TalonFX armLeader = new TalonFX(21, CANBuses.CANIVORE);  // TODO: 依接線
// 在 roboRIO 內建 CAN 上
TalonFX other = new TalonFX(5);                          // TODO: 依接線

把 CANBus 集中宣告在一個地方，名字就只有一次打錯的機會。跟第 5 章的 Constants 是同一個道理。

寫一份完整的設定

新 new 出來的設定物件本身就帶著裝置的所有預設值，所以套用完整設定之前不用先恢復出廠設定；真的想恢復出廠，套用一個全新的設定物件就好[1]。完整設定物件裡你沒改到的項目，都會被自動設回預設值[2]。

TalonFXConfiguration config = new TalonFXConfiguration();

// 方向與休息狀態
config.MotorOutput.Inverted = InvertedValue.CounterClockwise_Positive; // TODO: 上機確認
config.MotorOutput.NeutralMode = NeutralModeValue.Brake;

// 電流限制：保護馬達、電池和斷路器
config.CurrentLimits.StatorCurrentLimit = 0.0;        // [CONSTRAINT] TODO
config.CurrentLimits.StatorCurrentLimitEnable = true;
config.CurrentLimits.SupplyCurrentLimit = 0.0;        // [CONSTRAINT] TODO
config.CurrentLimits.SupplyCurrentLimitEnable = true;

// 齒輪比：之後讀到的位置、速度都是機構端
config.Feedback.SensorToMechanismRatio = 1.0;         // TODO

// 只在建構時套用一次
armLeader.getConfigurator().apply(config);

apply() 會卡住等裝置回應[1]，所以絕對不要放進 periodic。你也可以只套用其中一組，像 armLeader.getConfigurator().apply(config.MotorOutput)，這樣就只會改到那一組[1]，第 6 章的 setBrakeMode 就是這樣寫的。

完整設定會蓋掉所有東西程式裡如果有兩個地方各套用一次「完整」的 TalonFXConfiguration，後套用的會把前一份的設定通通蓋回預設值，不是只加上自己改的部分。同一顆馬達的完整設定，只寫在一個地方。

控制請求：交辦單

控制請求物件 new 一次，之後用 with... 改數字再送出，CTRE 的範例都是這樣寫[9]。常用的有這些：

請求做什麼本課程用在
DutyCycleOut輸出百分比（-1 到 1）很少用
VoltageOut輸出指定電壓滾輪、SysId
PositionVoltage控制器內 PID 追蹤位置第 13 章
VelocityVoltage控制器內 PID 追蹤速度飛輪（第 13 章）
MotionMagicVoltage產生梯形或 S-curve 軌跡並追蹤手臂（第 6、14 章）
NeutralOut停止輸出，依 NeutralMode 煞車或滑行停止
Follower跟隨另一顆馬達手臂 follower（第 6 章 C 部分）
TorqueCurrentFOC 等直接控制轉矩電流需要 Pro 授權

電壓類的控制請求，輸出通常不會受供電電壓影響（但輸出電壓的上限還是被供電電壓限制住），所以比 DutyCycle 類穩定、結果比較好重現；TorqueCurrentFOC 則要 Pro 授權[3]。所以這個課程一律用 Voltage 類。

EnableFOC 與 Pro 授權

FOC（Field Oriented Control）是一種換相方式，CTRE 說它可以讓峰值功率多大約 15%。支援 FOC 的控制請求都有一個 EnableFOC 欄位[3]，API 裡預設是 true，但要用 FOC 得有 Phoenix Pro 授權[6]。

那沒有 Pro 怎麼辦？第 6 章留下的問題在這裡解答：控制沒授權的裝置時，支援 EnableFOC 的請求會自動退回一般（非 FOC）換相[3]。所以不改 EnableFOC 也能正常跑，只是沒有 FOC 的效能加成。只有 TorqueCurrentFOC 這種本身就靠 FOC 的請求，才真的非 Pro 不可。

模擬時要對應第 6 章 D 部分提過，CTRE 的模擬範例用的是 DCMotor.getKrakenX60Foc。沒有 Pro 的話，實機跑的是一般換相，模擬就該用 DCMotor.getKrakenX60，兩邊才對得上。

讀取感測資料

TalonFX 的讀值是用 StatusSignal 拿的。完整寫法第 6 章 C 部分示範過了：訊號存成欄位，每個週期用 BaseStatusSignal.refreshAll(...) 一次刷新，再用 getValueAsDouble() 取值[8]。兩件事要記得：Phoenix 6 的位置單位是轉數（rotations）、速度是每秒轉數；設了 SensorToMechanismRatio 之後，讀到的就是機構端的數值。

Phoenix Tuner X

Tuner X 可以做的事很多：設定裝置的名稱和 ID、讓裝置閃燈好在機器人上找到它、把所有裝置的韌體更新到最新、在 Windows 或 Android 上直接控制單顆馬達、畫出速度和位置這些訊號，還有對裝置做 Self Test[7]。

新機器人第一次通電，建議照這個順序：

  1. 用 Tuner X 找到所有裝置，逐一閃燈，確認每一顆在機器人上的位置。
  2. 設定 CAN ID，同一條 bus 上不可重複；隊上可以約定編號規則，例如手臂用 20 幾號。
  3. 把 CANivore 命名為「9427」，和程式裡的 new CANBus("9427") 一致。
  4. 把所有裝置的韌體更新到最新版。
  5. 用低電壓手動轉動每顆馬達，確認方向，再把結果寫進程式的 Inverted 設定。
  6. 把 CAN ID 對照表寫進 Constants，並貼在機器人上。
教練提醒：用 Tuner X 手動轉馬達之前先確定機構旁邊沒人、機構不會撞到極限位置，而且從很低的輸出開始。手臂這種有重力的機構，一放開控制就可能掉下來。

常見錯誤

CAN bus 名稱打錯new CANBus("9247") 這種錯字不會編譯失敗，但程式找不到裝置，讀值全部失敗、馬達完全不動。名稱集中在一個常數，再跟 Tuner X 上顯示的名稱對一下。
CAN ID 重複同一條 bus 上兩顆裝置 ID 一樣，會互相干擾，Tuner X 會標出重複的裝置。模擬時更嚴格：第 6 章 D 部分講過，模擬時所有 bus 會合成一條，ID 必須全機唯一。
在 periodic 裡套用設定apply() 會等裝置回應，放在 periodic 裡會拖慢每一輪，還可能 loop overrun（第 7 章）。
需要重現的控制用了 DutyCycleOut電池從滿電用到快沒電，同樣的百分比會跑出不同的速度，調好的參數也跟著跑掉。用 Voltage 類的請求。

小測驗

練習：幫 Intake 滾輪寫硬體層

幫第 6 章練習的 RollerIO 寫一個 RollerIOHardware：滾輪馬達在 CANivore「9427」上，CAN ID 先待定；設定成 Coast、開供電電流限制（數值待定）；setVoltage 用重複使用的 VoltageOut；updateInputs 讀速度、輸出電壓、供電電流。

照第 6 章 ArmIOHardware 的結構寫：欄位裡建 TalonFX、控制請求和要讀的訊號，建構子裡套設定。

CANivore 用 new TalonFX(id, CANBuses.CANIVORE)；請求用 new VoltageOut(0.0) 建一次；訊號用 getVelocity()、getMotorVoltage()、getSupplyCurrent()。

updateInputs 裡先 BaseStatusSignal.refreshAll(...)，用 .isOK() 填 connected，再用 getValueAsDouble() 取值；setVoltage 寫 motor.setControl(request.withOutput(volts))。

public class RollerIOHardware implements RollerIO {
    private final TalonFX motor = new TalonFX(0, CANBuses.CANIVORE); // TODO: CAN ID
    private final VoltageOut request = new VoltageOut(0.0);

    private final StatusSignal<AngularVelocity> velocity = motor.getVelocity();
    private final StatusSignal<Voltage> appliedVolts = motor.getMotorVoltage();
    private final StatusSignal<Current> supplyCurrent = motor.getSupplyCurrent();

    public RollerIOHardware() {
        TalonFXConfiguration config = new TalonFXConfiguration();
        config.MotorOutput.NeutralMode = NeutralModeValue.Coast;
        config.MotorOutput.Inverted = InvertedValue.CounterClockwise_Positive; // TODO: 上機確認
        config.CurrentLimits.SupplyCurrentLimit = 0.0;                         // [CONSTRAINT] TODO
        config.CurrentLimits.SupplyCurrentLimitEnable = true;
        motor.getConfigurator().apply(config);
    }

    @Override
    public void updateInputs(RollerIOInputs inputs) {
        inputs.connected = BaseStatusSignal.refreshAll(velocity, appliedVolts, supplyCurrent).isOK();
        inputs.velocityRps = velocity.getValueAsDouble();
        inputs.appliedVolts = appliedVolts.getValueAsDouble();
        inputs.supplyCurrentAmps = supplyCurrent.getValueAsDouble();
    }

    @Override
    public void setVoltage(double volts) {
        motor.setControl(request.withOutput(volts));
    }
}

滾輪用 Coast：停的時候讓它自己慢慢停，不會卡住遊戲物件。手臂則用 Brake（第 6 章），因為要撐住重力。這是依機構決定的，不是固定規則。
