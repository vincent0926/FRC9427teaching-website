CAN ID 02｜Java 與物件導向

封裝：成績簿不能放在講台上

讀完這章，你會知道為什麼欄位幾乎都寫成 private、四種存取層級的差別，以及為什麼 Subsystem 不該讓外面直接碰馬達。

生活比喻：一本成績簿的遭遇

成績簿放在講台上。某一班把成績簿放在講台，誰都能翻、誰都能寫。一開始相安無事，直到有人把自己的數學改成 150 分，又有人不小心把別人的分數寫進自己那一格。期末結算時，導師發現分數對不上，但完全查不出是誰、在什麼時候改的。

學校訂了新規定。從此成績簿鎖在導師的抽屜裡，學生拿不到。要登記成績，唯一的管道是交給任課老師，由老師寫進去。老師每次登記前都會檢查：分數必須在 0 到 100 之間。不合規定的分數，老師直接退回。

想知道分數，可以問。學生可以問老師「我這次考幾分？」，老師會告訴你一個數字。但老師不會把整本成績簿交給你，因為交出去之後你想怎麼寫都行，前面的規定就白訂了。

後來學校換成電子系統。成績從紙本改成校務系統，存放方式完全不同。但對學生來說什麼都沒變：一樣交給老師登記，一樣問老師查分數。內部怎麼存，外面根本不需要知道。

不是所有東西都要鎖起來。學校裡的資訊分成幾種公開程度：自己的日記只有自己能看；班級日誌只給同班看；社團的傳承筆記會留給直屬學弟妹；公布欄則是全校都能看。

這整個故事就是封裝（encapsulation）。Oracle 的官方教學把它描述為：隱藏物件內部的狀態，並要求所有互動都透過物件的方法進行[1]。

四種存取層級

Java 有四種存取層級[2]，對應故事最後一段的四種公開程度：

修飾詞同一個類別同一個套件子類別其他地方像是
private可以不行不行不行自己的日記
什麼都不寫
package-private		可以可以不行不行只給同班看的班級日誌
protected可以可以可以不行班級日誌，也留給直屬學弟妹
public可以可以可以可以公布欄

第二列不是漏寫：欄位或方法前面什麼修飾詞都不加，本身就是一種存取層級，叫 package-private（Oracle 文件稱為 no modifier），例如 int seatNumber;。它是 Java 的預設值，所以很容易在不知不覺中用到[2]。

「套件」是第 5 章的主題，「子類別」是第 3 章的主題。現在只要記得 Oracle 教學給的原則：除非有充分理由，否則使用最嚴格的存取層級，並避免 public 欄位（常數除外）[2]。

這個比喻哪裡不準日記是「每個人」的，但 Java 的 private 是以「類別」為單位，不是以物件為單位。同一個類別的程式碼，可以讀寫另一個同類別物件的 private 欄位。也就是說，在 Roller 類別裡面，intake 的方法其實看得到 feeder 的 voltage。

換成機器人：沒有封裝的 Intake

public class IntakeSubsystem extends SubsystemBase {
    public final TalonFX roller = new TalonFX(21); // 成績簿放在講台上
}

// 某個 Command 裡
intake.roller.setControl(new VoltageOut(12)); // 繞過了所有規則

問題有兩個。第一，電壓上限、方向這些規則沒有地方放，每個用到的人都得自己記得。第二，Command-based 架構靠「這個指令需要哪個 Subsystem」來避免兩個指令同時搶同一個機構（第 8 章細講）；如果指令能直接拿到馬達，這個保護就失效了。

封裝後的 Intake

WPILib 的 Command-based 範本在 Subsystem 裡就寫著註解：馬達控制器、感測器這些元件一般應該宣告為 private，只透過 public 方法對外開放[3]。

import com.ctre.phoenix6.controls.VoltageOut;
import com.ctre.phoenix6.hardware.TalonFX;
import edu.wpi.first.math.MathUtil;
import edu.wpi.first.wpilibj2.command.SubsystemBase;

public class IntakeSubsystem extends SubsystemBase {
    private static final double MAX_VOLTS = 10.0; // TODO: 依機構實測調整

    private final TalonFX roller = new TalonFX(21);    // 鎖在抽屜裡
    private final VoltageOut request = new VoltageOut(0);

    // 唯一的登記窗口，而且一定會檢查
    public void setRollerVoltage(double volts) {
        double clamped = MathUtil.clamp(volts, -MAX_VOLTS, MAX_VOLTS);
        roller.setControl(request.withOutput(clamped));
    }

    public void stopRoller() {
        setRollerVoltage(0.0);
    }

    // 問分數：只給數字，不給成績簿
    public double getRollerVelocityRps() {
        return roller.getVelocity().getValueAsDouble();
    }
}

外面只看得到三個方法，電壓一定先被限制。明年想把開迴路改成閉迴路，只要改這個類別裡面，呼叫的人完全不用動，這就是「紙本換成電子系統」。

private 和 final 不一樣private 管的是「誰看得到」，final 管的是「能不能換掉」。private final TalonFX roller 的意思是：外人看不到這顆馬達，而且這個欄位永遠指向同一顆馬達。

常見錯誤

把整本成績簿交出去寫了 private TalonFX roller，又加一個 public TalonFX getRoller()。外面拿到物件後一樣可以直接 setControl，封裝等於沒做。getter 應該回傳資料（轉速、位置），不該回傳可以被操作的硬體物件。
教練提醒Code review 時我第一眼看的就是 Subsystem 裡有沒有 public 的硬體欄位或回傳硬體的 getter。有的話，這個 Subsystem 的規則遲早會被某個 Command 繞過。

小測驗

練習：封裝一支手臂

寫一個純 Java 的 Arm 類別：private 欄位 goalDegrees；方法 setGoal(double degrees) 把目標限制在 0 到 110 度；方法 getGoal() 回傳目前目標。上下限寫成 private static final 常數，並加上 TODO 註解提醒要實測。

看參考答案 
public class Arm {
    private static final double MIN_DEGREES = 0.0;   // TODO: 依機構實測
    private static final double MAX_DEGREES = 110.0; // TODO: 依機構實測

    private double goalDegrees = MIN_DEGREES;

    public void setGoal(double degrees) {
        goalDegrees = Math.max(MIN_DEGREES, Math.min(MAX_DEGREES, degrees));
    }

    public double getGoal() {
        return goalDegrees;
    }
}
