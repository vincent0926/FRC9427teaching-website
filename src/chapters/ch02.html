CAN ID 02｜Java 與物件導向

封裝：成績簿不能放在講台上

你會發現隊上的程式裡，欄位幾乎都寫成 private。這章講為什麼要這樣，順便把四種存取層級講清楚，最後回到機器人：為什麼 Subsystem 不能讓外面直接碰馬達。

比喻：一本成績簿的遭遇

有一班把成績簿放在講台上，誰都能翻、誰都能寫。一開始沒事，後來有人把自己的數學改成 150 分，又有人不小心把別人的分數寫進自己那格。期末算成績的時候，導師發現分數兜不起來，但根本查不出是誰、什麼時候改的。

學校只好訂新規定：成績簿鎖進導師的抽屜，學生拿不到。要登記成績只有一個管道，就是交給任課老師，由老師寫進去。老師每次登記前都會檢查分數是不是在 0 到 100 之間，不對就直接退回。

想知道自己幾分可以問老師，老師會告訴你一個數字。但老師不會把整本成績簿拿給你，因為一交出去你想寫什麼都行，前面的規定就白訂了。

後來學校改用電子校務系統，成績的存法完全不一樣了。可是對學生來說什麼都沒變，一樣交給老師登記、一樣問老師查分數。裡面怎麼存，外面根本不用知道。

當然也不是什麼都要鎖起來。學校的資訊本來就有不同的公開程度：日記只有自己能看，班級日誌給同班看，社團的傳承筆記會留給直屬學弟妹，公布欄則是全校都看得到。

這整個故事講的就是封裝（encapsulation）。Oracle 的 Java 教學是這樣說的：把物件內部的狀態藏起來，所有互動都要透過物件的方法來做[1]。

四種存取層級

Java 有四種存取層級[2]，剛好對到故事最後那四種公開程度：

修飾詞同一個類別同一個套件子類別其他地方像是
private可以不行不行不行自己的日記
什麼都不寫
package-private		可以可以不行不行只給同班看的班級日誌
protected可以可以可以不行班級日誌，也留給直屬學弟妹
public可以可以可以可以公布欄

第二列不是漏寫。欄位或方法前面什麼都不加，本身就是一種存取層級，叫 package-private（Oracle 文件叫它 no modifier），例如 int seatNumber;。因為它是預設值，很容易不知不覺就用到了[2]。

「套件」第 5 章才會講，「子類別」是第 3 章。現在只要記住 Oracle 教學給的原則：沒有好理由的話，就用最嚴格的那一層；除了常數以外，不要有 public 欄位[2]。

這個比喻哪裡不準日記是「每個人」各自的，但 Java 的 private 是以「類別」為單位，不是以物件為單位。同一個類別裡的程式碼，可以讀寫另一個同類別物件的 private 欄位。換句話說，在 Roller 類別裡面，intake 的方法其實看得到 feeder 的 voltage。

換成機器人：沒有封裝的 Intake

public class IntakeSubsystem extends SubsystemBase {
    public final TalonFX roller = new TalonFX(21); // 成績簿放在講台上
}

// 某個 Command 裡
intake.roller.setControl(new VoltageOut(12)); // 繞過了所有規則

這樣寫有兩個問題。一是電壓上限、方向這些規則沒地方放，每個用到的人都要自己記得。二是 Command-based 架構是靠「這個指令需要哪個 Subsystem」來避免兩個指令同時搶同一個機構（第 8 章會講）；指令如果能直接拿到馬達，這層保護就沒用了。

封裝後的 Intake

WPILib 的 Command-based 範本裡，Subsystem 本身就有一行註解：馬達控制器、感測器這類元件一般要宣告成 private，只透過 public 方法對外開放[3]。照這個原則改寫：

import com.ctre.phoenix6.controls.VoltageOut;
import com.ctre.phoenix6.hardware.TalonFX;
import edu.wpi.first.math.MathUtil;
import edu.wpi.first.wpilibj2.command.SubsystemBase;

public class IntakeSubsystem extends SubsystemBase {
    private static final double MAX_VOLTS = 10.0; // TODO: 依機構實測調整

    private final TalonFX roller = new TalonFX(21);    // 鎖在抽屜裡
    private final VoltageOut request = new VoltageOut(0);

    // 唯一的登記窗口，而且一定會檢查
    public void setRollerVoltage(double volts) {
        double clamped = MathUtil.clamp(volts, -MAX_VOLTS, MAX_VOLTS);
        roller.setControl(request.withOutput(clamped));
    }

    public void stopRoller() {
        setRollerVoltage(0.0);
    }

    // 問分數：只給數字，不給成績簿
    public double getRollerVelocityRps() {
        return roller.getVelocity().getValueAsDouble();
    }
}

現在外面只看得到三個方法，而且電壓一定會先被 MathUtil.clamp 限制住[4]。明年想把開迴路改成閉迴路，只要改這個類別裡面，呼叫的人一行都不用動，這就是故事裡的「紙本換成電子系統」。

private 和 final 是兩回事private 管「誰看得到」，final 管「能不能換掉」。private final TalonFX roller 的意思是：外人看不到這顆馬達，而且這個欄位永遠指向同一顆馬達。

常見錯誤

把整本成績簿交出去欄位寫了 private TalonFX roller，結果又加一個 public TalonFX getRoller()。外面拿到物件一樣可以直接 setControl，等於白封裝。getter 應該回傳資料（轉速、位置），不要回傳可以被操作的硬體物件。
教練提醒Code review 時，第一個要看的就是 Subsystem 裡有沒有 public 的硬體欄位，或是會回傳硬體的 getter。有的話，這個 Subsystem 的規則遲早會被某個 Command 繞過去。

小測驗

練習：封裝一支手臂

寫一個純 Java 的 Arm 類別：一個 private 欄位 goalDegrees；setGoal(double degrees) 把目標限制在 0 到 110 度；getGoal() 回傳目前目標。上下限寫成 private static final 常數，並加 TODO 註解提醒之後要實測。

不想讓外面直接改的欄位就設 private，外面真的要用的功能才開 public 方法。

上下限是這個類別自己用的常數，所以是 private static final。限制範圍用 Math.max 和 Math.min。

setGoal 裡寫 goalDegrees = Math.max(MIN_DEGREES, Math.min(MAX_DEGREES, degrees));，初始值可以直接用 MIN_DEGREES。

public class Arm {
    private static final double MIN_DEGREES = 0.0;   // TODO: 依機構實測
    private static final double MAX_DEGREES = 110.0; // TODO: 依機構實測

    private double goalDegrees = MIN_DEGREES;

    public void setGoal(double degrees) {
        goalDegrees = Math.max(MIN_DEGREES, Math.min(MAX_DEGREES, degrees));
    }

    public double getGoal() {
        return goalDegrees;
    }
}
