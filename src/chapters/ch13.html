CAN ID 13｜控制

PID 與前饋：推書車上斜坡

進階控制從這章開始。你大概聽過 PID，但只用 PID 的手臂常常會「差一點點就是到不了」。這章講 P、I、D 各自在幹嘛，kS、kV、kA、kG 這些前饋又是什麼，最後照順序手動調出第一組能用的參數。

版本說明這章是照 WPILib 2026 和 Phoenix 6 的 2026 版（26.x）文件寫的。裡面出現的增益數字都只是示範，你的機構一定要自己調，不要抄。

先講個比喻：推書車上斜坡

圖書股長要把書車推到坡道中間的一個記號。坡道通往圖書館，記號畫在半路上，書車很重，一放手就會滑下來。

最直覺的推法是：離記號越遠推越用力，快到了就輕輕推。問題是快到記號的時候「差很少」，他就只推一點點，可是坡道一直在把車往下拉。結果書車停在記號下面一點點：推的力剛好等於往下滑的力，就是永遠差那一點。

如果推太猛，書車會衝過記號、又被拉回來，來回晃好幾次。比較聰明的是看書車現在跑多快：跑太快就先收一點力，像門上的緩衝器那樣，讓車子穩穩地停下來。

還有一招：只要書車一直停在記號下面，就每秒多加一點力，加到真的推到為止。這招有用，但反應很慢，而且一開始如果差很多，累積的力會太大，衝過頭之後要很久才收得回來。

真正有經驗的股長會事先知道要多少力：在這個坡道上，光是「不讓書車滑下來」就要一定的力，坡越陡要越多；起步要先多出一點力，克服輪子卡住那一下；想維持某個速度，就要對應的力。這些力不用等看到誤差才出，一開始就先給。剩下那一點點誤差，再靠「看距離」和「看速度」去修。

比喻控制
坡道上的記號目標（setpoint）
記號減掉書車現在的位置誤差 e = 目標 − 量測
離記號越遠推得越用力P：kP × 誤差
看速度踩煞車，像門的緩衝器D：kD × 誤差的變化率
一直差一點就慢慢加力I：kI × 誤差的累積
累積的力太大，衝過頭收不回來積分飽和（integral windup）
停在記號下面一點點穩態誤差
「讓書車不滑下來」要的力kG（重力前饋）
起步時克服輪子卡住的那一下kS（靜摩擦前饋）
維持某個速度要的力kV（速度前饋）
加速要多出的力kA（加速度前饋）
這個比喻哪裡不準斜坡的坡度是固定的，所以推書車的重力前饋是一個定值，跟升降機構一樣。手臂就不一樣了：水平的時候重力影響最大，垂直時幾乎是零，所以手臂的 kG 要乘上 cos(角度)。另外，PID 輸出的單位是伏特（或 duty cycle、安培），不是真的「力」，只是在馬達上電壓大致對應到力矩和速度。

回饋與前饋

控制大概分兩種想法：

  • 回饋（feedback）：看誤差來修，看到差多少才出力。PID 就是回饋控制器。
  • 前饋（feedforward）：照機構的物理特性，事先算好「要到目標狀態大概需要多少輸出」，不用等誤差出現。

WPILib 拿垂直手臂比較過三種做法。只用前饋：慢慢平順地動還追得上，但離目標遠就不太行，有干擾也修不回來。只用 PID：官方直接說「沒有好的調法」，因為手臂就算到了目標也要持續出力撐住，純回饋會停在目標旁邊的某個平衡點。兩個一起用才是正解[1]。

P、I、D 各自做什麼

簡單講：P 想讓位置誤差變 0，D 想讓速度誤差變 0，I 想讓累積的誤差變 0，三項加起來就是控制輸出[2]。

項輸出像什麼太大會怎樣
PkP × e軟體彈簧：把機構拉向目標衝過頭、來回振盪
DkD × de/dt軟體阻尼：像門上的緩衝器，速度越快阻力越大輸出抖動（對雜訊很敏感）
IkI × ∫e dt「一直差一點就慢慢加力」積分飽和，衝過頭很久才回來

「軟體彈簧」和「軟體阻尼」是 WPILib 自己用的比喻：P 就像彈簧的 F = −kx，D 就像門的緩衝器，速度越快阻力越大[2]。

至於 I，kI 太大會造成積分飽和（windup）。處理方式照順序是：先把 kI 調小，能調到 0 最好；誤差太大的時候把積分歸零（setIZone）；限制積分的上下限（setIntegratorRange）[3]。老實說，前饋做好之後，大部分時候根本用不到 I。

前饋：kS、kV、kA、kG

WPILib 是用永磁直流馬達的「電壓平衡方程式」來描述前饋的[4]：

簡單馬達：V = kS·sgn(v) + kV·v + kA·a
升降機構：V = kG + kS·sgn(v) + kV·v + kA·a
手臂：    V = kG·cos(θ) + kS·sgn(ω) + kV·ω + kA·α
  • kS：克服靜摩擦、讓機構剛好開始動的電壓，跟速度無關。
  • kV：維持某個固定速度要的電壓（主要是抵銷馬達的反電動勢）。對 FRC 的零件來說，電壓跟速度幾乎是線性關係。
  • kA：產生某個加速度要的電壓。
  • kG：抵銷重力。升降機構是定值，手臂要乘 cos(θ)，因為重力不是直接作用在馬達上的。

這幾個定義都出自 WPILib 文件[4]。注意 cos(θ) 的 θ 是「跟水平的夾角」，所以第 6 章和第 12 章才會一直碎念「0 度一定要是水平」。

在 TalonFX 上設定

第 6 章的手臂已經把這些增益放在 TalonFX 的 Slot0 裡了。在控制器裡跑閉迴路沒有感測延遲，更新頻率是 1 kHz，反應比在 roboRIO 上跑快[5]。

Slot0Configs slot0 = config.Slot0;
slot0.GravityType = GravityTypeValue.Arm_Cosine; // 預設是 Elevator_Static
slot0.kG = 0.0; // [MODEL→SYSID] TODO: 讓手臂水平停住的電壓
slot0.kS = 0.0; // [MEASURED／SYSID] TODO
slot0.kV = 0.0; // [MODEL→SYSID] TODO: 單位 V / (rot/s)
slot0.kA = 0.0; // [MODEL→SYSID] TODO: 單位 V / (rot/s²)
slot0.kP = 0.0; // [TUNED] TODO: 單位 V / rot
slot0.kI = 0.0; // [TUNED] 前饋做好後通常維持 0
slot0.kD = 0.0; // [TUNED] TODO: 單位 V / (rot/s)

單位要特別小心。Phoenix 6 的增益是「機構單位」：CTRE 舉的例子是 100:1 減速時，kP = 1 代表機構差 1 圈輸出 1 V，也就是馬達要差 100 圈才輸出 1 V[6]。WPILib 的 ArmFeedforward、PIDController 則是你餵什麼單位它就用什麼單位，第 6 章 D-3 用的是弧度。所以同一組數字不能直接在兩邊換來換去。

kP 不知道從多少開始的話，CTRE 有個估法：手臂離目標 0.1 圈的時候，如果 1 V 就能讓它慢慢動，那 kP = 1 V ÷ 0.1 rot = 10 V/rot，這是個安全的起點[6]。

kS 的正負號

摩擦永遠跟運動方向相反，所以 kS 的正負號要看往哪邊動。Phoenix 6 的 StaticFeedforwardSign 有兩種：預設的 UseVelocitySign 看速度目標的正負，速度閉迴路一定用它，MotionMagic 也建議用它；UseClosedLoopSign 看誤差的正負，適合沒有速度目標的單純位置閉迴路，但 kS 不能太大，不然在目標附近會抖[5]。

動手試：調一支手臂

下面這支模擬手臂從 0 度（水平）出發，目標是往上 72 度（0.2 圈）。模擬裡有重力、摩擦，還有 10 ms 的量測延遲。調三個增益，按「執行」看 2 秒內角度怎麼變。

建議照這個順序玩：先只給 P，看手臂停在目標下面；再加 kG，誤差馬上小很多；把 kP 拉很大，看它衝過頭；最後加一點 kD 把過衝壓下來。模擬裡真正的 kG 是 0.6 V，你故意把 kG 調過頭會怎樣？

手動調參的順序

CTRE 建議的手動調參順序是這樣[5]：

  1. 所有增益歸零。
  2. 升降或手臂先找 kG。
  3. 選好 kS 的正負號模式。
  4. 慢慢加 kS，加到馬達「差一點就要動了」。
  5. 有速度目標的話，加 kV 到實際速度貼著目標速度。
  6. 加 kP，加到開始在目標附近晃。
  7. 在不會抖的範圍內，kD 盡量加。

kG 怎麼找：升降機構用開迴路找出「剛好能停在某個高度」的輸出；手臂則是找「剛好能水平向前停住」的輸出[5]。WPILib 的手臂教學也特別提醒，kG 要調得滿精準的[1]。

飛輪這種速度機構，CTRE 建議在低速（大約最大速度的 10%）調 kS、在高速（大約 80%）調 kV，兩個輪流調到不再變，最後才加 kP[6]。手動調出來的數字能用，但第 15 章的 SysId 可以直接從量測資料算出 kS、kV、kA、kG，比用猜的準多了。

教練提醒：調參時的安全每次改完增益，先用小目標試，手指放在 Enter（Disable）或空白鍵（緊急停止）上（第 0 章）。手臂 kG 正負號弄反的話，手臂會被往下推而不是撐住。調參的時候電流限制和軟體極限（第 6 章）一定要開著，不要為了「看清楚一點」把它關掉。

參數從哪裡來

不是每個參數都能用公式算準。重點是每個數字你都要知道它是怎麼來的，下次機構改了，才知道要重做哪一步。這個課程跟電梯／手臂調參工作站用的是同一套分類：

參數來源怎麼得到
kG[MODEL→SYSID]用質量、力臂、齒輪比、馬達常數估計初始值，再用 SysId 或開迴路量出實際值（第 15 章）
kS[MEASURED／SYSID]摩擦幾乎無法從模型算準，直接量或用 SysId 擬合
kV、kA[MODEL→SYSID]由馬達常數與齒輪比估計，再用 SysId 修正（效率、摩擦、慣量都會讓實際值不同）
kP、kI、kD[TUNED]上機依回饋調整；SysId 的回饋建議值只是起點
巡航速度、加速度、jerk[CONSTRAINT]依機構能力（扣掉 kG、kS 後）與安全需求決定（第 14 章）
電流限制、軟體極限[CONSTRAINT] [MEASURED]電流限制是保護用的決定；軟體極限要依實際量到的機械極限設在內側
上面實驗裡的「真實 kG 0.6 V」[SIM]只是模擬器的設定，和任何真實機構無關

把這張表串起來，就是調參的完整流程：

  1. 理論／模型：先算出大概的預期，確認數量級沒錯。
  2. 系統鑑別（SysId）：量出真實機構的 kS、kG、kV、kA。
  3. 閉迴路調參：前饋對了之後，再調 kP、kD。
  4. 實機驗證：用日誌確認實際位置有貼著目標，而且換電池、換負載也一樣成立。

程式碼裡每個參數後面的小標籤就是這個分類，滑鼠移上去可以看說明。

常見錯誤

拿 I 來補重力手臂停在目標下面，很多人第一個反應是加 kI。它確實會慢慢推上去，但反應慢又容易飽和。真正缺的是 kG。
忘了改 GravityTypePhoenix 6 預設是 Elevator_Static，手臂忘了改成 Arm_Cosine 的話，kG 在任何角度都一樣大，手臂抬高時反而會被推過頭。
增益單位搞錯把網路上別隊用弧度調的 kP 直接填進 Phoenix 的 Slot0（單位是圈），差了 2π 倍；或是忘了 Phoenix 的增益已經是機構端單位。
kD 加太多D 對雜訊很敏感，太大的話馬達會嗡嗡叫或抖，也會比較燙。

小測驗

練習：飛輪的速度控制

幫射球飛輪寫 TalonFX 設定：用 VelocityVoltage 控制，Slot0 放 kS、kV、kP（數值待定），然後在 Subsystem 寫 setVelocityGoal(double rps) 和 atSpeed()（誤差小於 2 rps 就算到速）。順便想一下：飛輪需要 kG 嗎？需要 kA 嗎？

先想這個機構需要哪些前饋：飛輪是水平轉的，重力會讓它加速或減速嗎？

用 VelocityVoltage(0.0).withSlot(0)；Slot0 放 kS、kV、kP，飛輪用 Coast。Subsystem 記住目標轉速，在 periodic 送出。

atSpeed() 回傳 Math.abs(inputs.velocityRps - goalRps) < TOLERANCE_RPS；kG 不需要，kA 只在目標速度一直變化時才有幫助。

public class FlywheelIOHardware implements FlywheelIO {
    private final TalonFX motor = new TalonFX(0, CANBuses.CANIVORE); // TODO: CAN ID
    private final VelocityVoltage request = new VelocityVoltage(0.0).withSlot(0);

    public FlywheelIOHardware() {
        TalonFXConfiguration config = new TalonFXConfiguration();
        config.MotorOutput.NeutralMode = NeutralModeValue.Coast;
        config.Feedback.SensorToMechanismRatio = 1.0; // TODO: 齒輪比
        config.Slot0.kS = 0.0; // [MEASURED／SYSID] TODO: SysId，或照 CTRE 飛輪步驟在低速時手動調
        config.Slot0.kV = 0.0; // [MODEL→SYSID] TODO: SysId，或在高速時手動調，單位 V/(rot/s)
        config.Slot0.kP = 0.0; // [TUNED] TODO: 最後才加
        config.CurrentLimits.SupplyCurrentLimit = 0.0; // [CONSTRAINT] TODO
        config.CurrentLimits.SupplyCurrentLimitEnable = true;
        motor.getConfigurator().apply(config);
    }

    // updateInputs 寫法同第 11 章的練習

    @Override
    public void setVelocity(double rps) {
        motor.setControl(request.withVelocity(rps));
    }
}

// FlywheelSubsystem 裡
private static final double TOLERANCE_RPS = 2.0; // TODO: 依射球需求調整
private double goalRps = 0.0;

@Override
public void periodic() {
    io.updateInputs(inputs);
    io.setVelocity(goalRps); // 和第 6 章一樣，只在 periodic 裡送輸出
}

public void setVelocityGoal(double rps) {
    goalRps = rps;
}

public boolean atSpeed() {
    return Math.abs(inputs.velocityRps - goalRps) < TOLERANCE_RPS;
}

飛輪水平轉，重力不會讓它加速或減速，所以不用 kG。kA 只有在「目標速度一直在變」的時候才有用；飛輪通常就是一個固定目標，CTRE 的速度閉迴路範例也只用 kS、kV、kP[7]。滾輪和飛輪用 Coast：停的時候讓它自己慢慢減速，不要急煞。
