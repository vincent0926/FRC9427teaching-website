CAN ID 18｜上場

模擬、日誌與重播：比賽錄影和賽後檢討

讀完這章，你會知道模擬、日誌、重播三者差在哪裡，怎麼從機器人取出日誌、用 AdvantageScope 看資料，重播的完整步驟，哪些寫法會讓重播失準，以及怎麼讓每一場比賽的程式版本都找得回來。

版本說明本章依據 AdvantageKit 2026 版（v26.0.2）的文件。AdvantageKit 網站和 GitHub main 分支已經開始出現 2027 版的內容（例如類別改名），查資料時要確認版本。第 6 章 E 部分已經介紹過 @AutoLog、Logger.processInputs 和三種模式，本章接著講怎麼用。

生活比喻：比賽錄影和賽後檢討

體育課的練習賽全程錄影。每一場練習賽，攝影機都把「場上發生的事」完整錄下來：誰在哪裡、球往哪裡飛、裁判吹了什麼哨。另外，每個球員也把「自己當時怎麼想、決定做什麼」寫在筆記上。

賽後一起看錄影。教練把錄影和筆記放在同一個時間軸上，一格一格看：球員在第 12 秒為什麼沒有傳球？原來他當時以為隊友被擋住了。

重新推演：換一套想法會怎樣？教練還可以說：「用同一段錄影，照新的戰術重新想一次，每一格你會怎麼決定？」因為看到的畫面完全一樣，新的決定可以和原本的決定逐格比較。

但推演改變不了錄影。在推演裡決定「這時候往左跑」，錄影裡的你還是往右跑了，之後的畫面也不會因此改變。推演只能回答「看到這些畫面時，新想法會怎麼決定」，不能回答「照新想法打，比賽會變成怎樣」。

錄影要標上是哪一版戰術。戰術本每場之間都在改，如果錄影沒標註當時用的是哪一版，事後就不知道要拿哪一版來推演。

比喻AdvantageKit
錄下場上發生的事記錄輸入（inputs）：感測器、Driver Station、儀表板
球員寫下自己的決定記錄輸出（outputs）：Logger.recordOutput
放在同一個時間軸上看用 AdvantageScope 看日誌
用同一段錄影、新想法重新推演重播（replay）
推演改變不了錄影重播的限制（replay bubble）
錄影標上戰術版本日誌 metadata 記錄 Git commit
這個比喻哪裡不準錄影只能看到鏡頭拍到的東西；AdvantageKit 的重播要求程式讀到的每一個外部資料都被記錄下來，只要漏了一個，重播出來的決定就可能和當時不同。這就是本章後半「確定性」要講的。

取得日誌

AdvantageKit 文件說明，在 roboRIO 上 WPILOGWriter 預設寫到 USB 隨身碟（/U/logs），所以 roboRIO 上必須插一支 FAT32 格式的隨身碟[1]。取出日誌最方便的方法是 AdvantageScope：在偏好設定填好機器人位址與日誌資料夾，然後用 File → Download Logs 下載，最新的日誌會排在最上面[2]。

AdvantageScope 能開的格式包括 WPILib 與 AdvantageKit 產生的 .wpilog，以及 Phoenix 6 SignalLogger 的 .hoot（第 15 章）。同時開啟多個檔案時，時間會自動對齊[2]，所以可以把 AdvantageKit 日誌和 hoot 放在一起看。

AdvantageKit 會自動記錄一些東西，不需要設定：時間戳、Driver Station 與搖桿的所有資料、透過 AdvantageKit 儀表板類別讀的輸入、WPILib Alert 的狀態（第 12 章）、Console 輸出，以及預設 CAN ID 的 PDP / PDH 各通道電流[3]。

要記錄哪些輸出

AdvantageKit 文件把輸出定義為「能在模擬中重新算出的值」，例如里程計位置、馬達電壓、內部狀態、給駕駛的狀態資訊。雖然這些值重播時算得出來，但實機上還是應該記錄重要的輸出，因為比賽之間通常來不及重播[4]。Pose2d 這類 WPILib 幾何物件可以直接記錄，在 2D Field 分頁顯示[4]。

Logger.recordOutput("Arm/Goal", goal);                 // enum
Logger.recordOutput("Drive/Pose", drivetrain.getState().Pose);
Logger.recordOutput("Vision/Accepted", acceptedCount);  // 第 17 章的練習

AdvantageKit 2026 版新增了單位資訊的記錄，例如 Logger.recordOutput("MyAngle", 3.141, "radians")，AdvantageScope 畫圖時就能正確換算單位[5]。

重播的完整步驟

  1. 找到當時的程式版本。在 AdvantageScope 的 Metadata 分頁找到 GitSHA，用 git checkout 回到那個 commit[6]（怎麼記錄 GitSHA 見下一節）。
  2. 切換成重播模式。AdvantageKit 範本專案只要把 Constants.java 的 simMode 改成 REPLAY[7]（第 6 章 E-4）。
  3. 指定日誌。LogFileUtil.findReplayLog() 依序使用：環境變數 AKIT_LOG_PATH、AdvantageScope 目前開著的檔案、執行時跳出的選擇視窗[7]。最簡單的做法是先在 AdvantageScope 開好那份日誌。
  4. 用模擬模式執行程式。WPILib 的 Simulate Robot Code，不要開模擬 GUI（範本預設已關閉）[7]。
  5. 看結果。產生的新日誌會自動在 AdvantageScope 開啟。重播算出的輸出在 ReplayOutputs 表，原本的輸入與輸出保持不變，可以直接對照[7]。

第 6 章 E-5 的 setUseTiming(false) 讓重播盡快跑完，文件特別說明這不會影響重播的準確度[7]。

Replay Watch調整位置估計這類需要反覆嘗試的工作，可以用 ./gradlew replayWatch（Windows 是 gradle.bat replayWatch）：每次修改 src 裡的程式，重播就自動再跑一次，AdvantageScope 也會保留時間範圍和畫面。它每次會覆蓋上一次的重播結果，但不會修改原始日誌；日誌越短、電腦單核效能越好，越好用[8]。
重播的限制AdvantageKit 文件說明，重播時修改程式的輸出不能影響重播的輸入[7]。例如把手臂的 kP 改大後重播，記錄裡的手臂位置還是當時的位置，因為那是從日誌讀回來的輸入。重播適合回答「看到同樣的資料，新的邏輯會怎麼決定」，不能回答「照新的邏輯，機器人會怎麼動」；後者要用模擬。

確定性：重播準確的前提

AdvantageKit 文件說明，重播要求所有資料來源都是確定、同步的；IO 介面保證了 Subsystem 的部分，但很容易不小心讀到沒被記錄的資料，所以建議開發過程中定期測試重播[9]。文件列出的常見陷阱[9]：

陷阱改成
在 Logger.start() 之前就讀時間或 Driver Station 資料在 Robot 建構子最後才建立 RobotContainer[10]
用 FPGA 原始時間 Timer.getFPGATimestamp()用 Timer.getTimestamp()
直接從 NetworkTables / 儀表板讀值（例如 SmartDashboard.getNumber）用 AdvantageKit 的儀表板類別，或把 NT 當成硬體寫一層 IO
大型硬體函式庫直接操作硬體，例如 Phoenix 6 swerve、YAGSL改用 AdvantageKit 的 swerve 範本專案
讀 roboRIO 上的檔案讀進來的資料要當成輸入處理
亂數、走訪無序集合（例如 HashMap）避免，或把結果當輸入記錄

另外，主要的機器人邏輯必須是單執行緒；真的需要執行緒時，只能放在 IO 實作裡。recordOutput、processInputs 也不是執行緒安全的，只能在主執行緒呼叫[11]。

第 16、17 章的 CTRE swerve 怎麼辦

上面表格的第四條要特別說明：第 16、17 章用的是 Tuner X 產生的 CTRE swerve，它直接操作硬體，沒有經過 IO 層，所以底盤的部分無法準確重播[9]。手臂、Intake 等照第 6 章寫的 Subsystem 不受影響。

如果隊上需要底盤也能重播，AdvantageKit 提供 TalonFX swerve 範本專案：一樣可以用 Tuner X 的 swerve 產生器設定，並提供高頻里程計、斷線警告、位置估計器整合、模擬，以及保證準確的重播[12]。要不要換，是隊上在賽季開始前就要決定的事，不要在比賽前換。

自動程式選單也是輸入

第 16 章用 SmartDashboard.putData 放的自動程式選單，是從 NetworkTables 讀值，重播時讀不到當時選了什麼。AdvantageKit 提供 LoggedDashboardChooser，可以直接包住 PathPlanner 的 buildAutoChooser()[13]：

private final LoggedDashboardChooser<Command> autoChooser;

public RobotContainer() {
    // ...Subsystem 與 Named Commands（第 16 章）
    autoChooser = new LoggedDashboardChooser<>("Auto Routine", AutoBuilder.buildAutoChooser());
}

public Command getAutonomousCommand() {
    return autoChooser.get();
}

讓每一場的程式版本找得回來

重播需要當時在機器人上跑的程式。AdvantageKit 範本已經裝好兩個工具[6]：

  • Gversion：編譯時產生 BuildConstants.java，裡面有 Git commit 的 hash，以及是否有尚未 commit 的修改（dirty）。在 Robot 建構子裡用 Logger.recordMetadata("GitSHA", BuildConstants.GIT_SHA) 記進日誌。BuildConstants.java 要加進 .gitignore。
  • Event Deploy：比賽期間程式一直在改，常常帶著沒 commit 的修改就部署。這個 Gradle 任務會在部署前，把目前的修改自動 commit 到名稱以 event 開頭的分支。

比賽時的流程[6]：

  1. 出發前建立並切換到 event_ 開頭的分支，例如 event_2026twcmp，每個賽事（例如一場區域賽）一個分支。
  2. 照平常方式部署，每次部署前會自動產生一個 commit。
  3. 比賽結束後，把分支 squash and merge 回開發分支，保持歷史乾淨。
  4. 要重播時，從日誌的 metadata 找到 hash，git checkout 回去；即使之後被 squash，只要 event 分支還在，原本的 commit 就找得回來，所以 event 分支不要刪。
教練提醒：隨身碟也是檢查項目沒插隨身碟、隨身碟滿了、格式不是 FAT32，日誌就不會寫進去，出問題時什麼都查不到。把「隨身碟有插、有空間」放進第 19 章的賽前檢查。

常見錯誤

重播時開著模擬 GUI文件明確要求重播時關閉模擬 GUI。
拿錯版本的程式重播程式已經改過還直接重播舊日誌，輸出對不上，還以為找到了 bug。先確認 GitSHA，並注意 dirty 標記。
在 Robot 欄位裡直接 new Subsystem欄位初始化會在 Logger.start() 之前執行，Subsystem 建構子讀到的時間和 DS 資料就不是確定的。
用 SmartDashboard.getNumber 調參數重播時讀不到當時的值。改用 LoggedNetworkNumber 等 AdvantageKit 的儀表板類別[13]。
以為改了 kP 重播就能看到新的動作重播改變不了輸入，要看新的動作請用模擬。

小測驗

練習：賽後找出為什麼沒射球

比賽中有一次，操作手按了射球鍵，但機器人沒有射。日誌裡有 Flywheel/VelocityRps（輸入）和 Flywheel/AtSpeed（輸出），但射球的判斷條件是 flywheel.atSpeed() && arm.atGoal()，Arm/AtGoal 當時沒有記錄（假設這支程式還沒加上第 6 章 E-3 的那幾行 recordOutput）。你會怎麼查？

先確定時間點，再一個一個條件檢查：哪個條件有記錄、哪個沒有？

用 Joysticks 分頁找到按鍵時間，Line Graph 看 Flywheel/AtSpeed。沒記錄的條件，可以用重播補記錄。

checkout 當時的 GitSHA，在 ArmSubsystem.periodic 加 Logger.recordOutput("Arm/AtGoal", atGoal())，用 REPLAY 執行，在 ReplayOutputs 表看結果。

  1. 在 AdvantageScope 的 Joysticks 分頁找到按下射球鍵的時間點。
  2. 在 Line Graph 看那段時間的 Flywheel/AtSpeed。如果它是 false，原因就在飛輪（第 13 章）。
  3. 如果飛輪到速了，懷疑是手臂。這時用重播：checkout 當時的 GitSHA，在 ArmSubsystem.periodic 補上 Logger.recordOutput("Arm/AtGoal", atGoal())，切換成 REPLAY 執行。
  4. 在 ReplayOutputs 表看 Arm/AtGoal。因為手臂的位置是從日誌讀回來的輸入，重播算出的 atGoal() 就和當時完全一樣。

這正是重播最擅長的事：補記錄當時忘了記錄的輸出。只要手臂是照第 6 章用 IO 層寫的，重播的結果就是準確的。找到原因後，把這行 recordOutput 留在程式裡，下次就不用重播了。
