CAN ID 18｜上場

模擬、日誌與重播：比賽錄影和賽後檢討

比賽中機器人出包，賽後你只能靠記憶猜嗎？不用，只要有日誌。這章講模擬、日誌、重播三個差在哪，怎麼從機器人拿出日誌、在 AdvantageScope 裡看資料，重播怎麼做，哪些寫法會讓重播不準，還有怎麼讓每一場比賽的程式版本都找得回來。

版本說明這章是照 AdvantageKit 2026 版（v26.0.2）的文件寫的。AdvantageKit 網站和 GitHub main 分支已經開始出現 2027 版的東西（像類別改名），查資料要確認版本。@AutoLog、Logger.processInputs 和三種模式在第 6 章 E 部分講過了，這章講怎麼用。

先講個比喻：比賽錄影和賽後檢討

體育課的每一場練習賽都全程錄影，攝影機把場上發生的事完整錄下來：誰在哪、球往哪飛、裁判吹了什麼哨。另外每個球員也會把「自己當時怎麼想、決定做什麼」寫在筆記上。

賽後教練把錄影跟筆記放在同一條時間軸上，一格一格看：第 12 秒他為什麼沒傳球？喔，原來他以為隊友被擋住了。

教練還可以說：「用同一段錄影，照新戰術重想一次，每一格你會怎麼決定？」因為看到的畫面完全一樣，新的決定可以跟原本的逐格比較。

但推演改變不了錄影。你在推演裡決定「這時候往左跑」，錄影裡的你還是往右跑了，後面的畫面也不會變。推演只能回答「看到這些畫面，新想法會怎麼決定」，回答不了「照新想法打，比賽會變怎樣」。

最後，戰術本每場之間都在改，錄影如果沒標當時用的是哪一版，事後就不知道該拿哪一版來推演。

比喻AdvantageKit
錄下場上發生的事記錄輸入（inputs）：感測器、Driver Station、儀表板
球員寫下自己的決定記錄輸出（outputs）：Logger.recordOutput
放在同一個時間軸上看用 AdvantageScope 看日誌
用同一段錄影、新想法重新推演重播（replay）
推演改變不了錄影重播的限制（replay bubble）
錄影標上戰術版本日誌 metadata 記錄 Git commit
這個比喻哪裡不準錄影只拍得到鏡頭範圍內的東西；AdvantageKit 的重播卻要求程式讀到的每一個外部資料都被記錄下來，漏一個，重播出來的決定就可能跟當時不一樣。這就是後半段「確定性」要講的。

取得日誌

在 roboRIO 上，WPILOGWriter 預設寫到 USB 隨身碟（/U/logs），所以 roboRIO 上一定要插一支 FAT32 的隨身碟[1]。拿日誌最方便的是用 AdvantageScope：在偏好設定填好機器人位址和日誌資料夾，再用 File → Download Logs 下載，最新的會排在最上面[2]。

AdvantageScope 開得了 WPILib 和 AdvantageKit 產生的 .wpilog，也開得了 Phoenix 6 SignalLogger 的 .hoot（第 15 章）。同時開好幾個檔案時間會自動對齊[2]，所以 AdvantageKit 日誌和 hoot 可以放在一起看，超方便。

有些東西 AdvantageKit 會自動記，不用設定：時間戳、Driver Station 和搖桿的所有資料、透過 AdvantageKit 儀表板類別讀的輸入、WPILib Alert 的狀態（第 12 章）、Console 輸出，還有預設 CAN ID 的 PDP / PDH 每個通道的電流[3]。

要記錄哪些輸出

所謂「輸出」，是指能在模擬裡重新算出來的值，像里程計位置、馬達電壓、內部狀態、給駕駛看的狀態資訊。這些值重播時算得出來沒錯，但實機上還是要記重要的輸出，因為兩場比賽之間通常根本來不及重播[4]。Pose2d 這類 WPILib 幾何物件可以直接記，在 2D Field 分頁就能看[4]。

Logger.recordOutput("Arm/Goal", goal);                 // enum
Logger.recordOutput("Drive/Pose", drivetrain.getState().Pose);
Logger.recordOutput("Vision/Accepted", acceptedCount);  // 第 17 章的練習

AdvantageKit 2026 版還多了單位資訊，例如 Logger.recordOutput("MyAngle", 3.141, "radians")，AdvantageScope 畫圖時就能正確換算單位[5]。

重播的完整步驟

  1. 找到當時的程式版本。在 AdvantageScope 的 Metadata 分頁找 GitSHA，用 git checkout 回到那個 commit[6]（GitSHA 怎麼記，下一節講）。
  2. 切到重播模式。AdvantageKit 範本專案只要把 Constants.java 的 simMode 改成 REPLAY[7]（第 6 章 E-4）。
  3. 指定日誌。LogFileUtil.findReplayLog() 會照順序找：環境變數 AKIT_LOG_PATH、AdvantageScope 現在開著的檔案、執行時跳出來的選擇視窗[7]。最簡單就是先在 AdvantageScope 把那份日誌開好。
  4. 用模擬模式跑。WPILib 的 Simulate Robot Code，不要開模擬 GUI（範本預設已經關了）[7]。
  5. 看結果。新產生的日誌會自動在 AdvantageScope 打開。重播算出來的輸出在 ReplayOutputs 表，原本的輸入和輸出都還在，可以直接對照[7]。

第 6 章 E-5 的 setUseTiming(false) 讓重播用最快速度跑完，這不會影響重播的準確度[7]，放心用。

Replay Watch調位置估計這種要一直試的工作，可以用 ./gradlew replayWatch（Windows 是 gradle.bat replayWatch）：只要改了 src 裡的程式，重播就自動再跑一次，AdvantageScope 的時間範圍和畫面也會保留。它每次會蓋掉上一次的重播結果，但不會動原始日誌；日誌越短、電腦單核越快，越好用[8]。
重播的限制重播時改程式，輸出不能影響重播的輸入[7]。比如把手臂的 kP 調大再重播，記錄裡的手臂位置還是當時的位置，因為那是從日誌讀回來的輸入。重播適合回答「看到同樣的資料，新邏輯會怎麼決定」，回答不了「照新邏輯，機器人會怎麼動」；後者要用模擬。

確定性：重播準確的前提

重播要求所有資料來源都是確定、同步的。IO 介面顧好了 Subsystem 的部分，但很容易一不小心就讀到沒被記錄的資料，所以要在開發過程中定期測重播[9]。常見的陷阱有這些[9]：

陷阱改成
在 Logger.start() 之前就讀時間或 Driver Station 資料在 Robot 建構子最後才建立 RobotContainer[10]
用 FPGA 原始時間 Timer.getFPGATimestamp()用 Timer.getTimestamp()
直接從 NetworkTables / 儀表板讀值（例如 SmartDashboard.getNumber）用 AdvantageKit 的儀表板類別，或把 NT 當成硬體寫一層 IO
大型硬體函式庫直接操作硬體，例如 Phoenix 6 swerve、YAGSL改用 AdvantageKit 的 swerve 範本專案
讀 roboRIO 上的檔案讀進來的資料要當成輸入處理
亂數、走訪無序集合（例如 HashMap）避免，或把結果當輸入記錄

還有，主要的機器人邏輯必須是單執行緒；真的需要執行緒，只能放在 IO 實作裡。recordOutput、processInputs 也不是執行緒安全的，只能在主執行緒呼叫[11]。

第 16、17 章的 CTRE swerve 怎麼辦

表格第四條要特別講一下：第 16、17 章用的是 Tuner X 產生的 CTRE swerve，它直接操作硬體，沒經過 IO 層，所以底盤這部分沒辦法準確重播[9]。手臂、Intake 這些照第 6 章寫的 Subsystem 則不受影響。

如果隊上希望底盤也能重播，AdvantageKit 有 TalonFX swerve 範本專案：一樣可以用 Tuner X 的 swerve 產生器設定，還有高頻里程計、斷線警告、位置估計器整合、模擬，以及保證準確的重播[12]。要不要換是賽季開始前就要決定的事，千萬不要比賽前才換。

自動程式選單也是輸入

第 16 章用 SmartDashboard.putData 放的自動程式選單是從 NetworkTables 讀值的，重播時讀不到當時選了哪個。AdvantageKit 有 LoggedDashboardChooser，可以直接包住 PathPlanner 的 buildAutoChooser()[13]：

private final LoggedDashboardChooser<Command> autoChooser;

public RobotContainer() {
    // ...Subsystem 與 Named Commands（第 16 章）
    autoChooser = new LoggedDashboardChooser<>("Auto Routine", AutoBuilder.buildAutoChooser());
}

public Command getAutonomousCommand() {
    return autoChooser.get();
}

讓每一場的程式版本找得回來

重播需要當時在機器人上跑的那份程式。AdvantageKit 範本已經幫你裝好兩個工具[6]：

  • Gversion：編譯時產生 BuildConstants.java，裡面有 Git commit 的 hash，還有有沒有沒 commit 的修改（dirty）。在 Robot 建構子裡用 Logger.recordMetadata("GitSHA", BuildConstants.GIT_SHA) 記進日誌。BuildConstants.java 要加進 .gitignore。
  • Event Deploy：比賽期間程式一直在改，常常帶著沒 commit 的東西就部署了。這個 Gradle 任務會在部署前，自動把目前的修改 commit 到名字以 event 開頭的分支。

比賽時的流程是這樣[6]：

  1. 出發前開一個 event_ 開頭的分支並切過去，例如 event_2026twcmp，一個賽事（例如一場區域賽）一個分支。
  2. 照平常那樣部署，每次部署前會自動多一個 commit。
  3. 比完之後，把分支 squash and merge 回開發分支，讓歷史乾淨一點。
  4. 要重播的時候，從日誌的 metadata 找 hash，git checkout 回去。就算之後被 squash，只要 event 分支還在，原本的 commit 就找得回來，所以 event 分支不要刪。
教練提醒：隨身碟也要檢查沒插隨身碟、隨身碟滿了、格式不是 FAT32，日誌就寫不進去，出事的時候什麼都查不到。把「隨身碟有插、有空間」放進第 19 章的賽前檢查。

常見錯誤

重播時開著模擬 GUI重播時一定要關掉模擬 GUI。
拿錯版本的程式重播程式已經改過了還直接重播舊日誌，輸出對不上，你還以為找到 bug 了。先確認 GitSHA，也要注意 dirty 標記。
在 Robot 的欄位裡直接 new Subsystem欄位初始化會在 Logger.start() 之前跑，Subsystem 建構子讀到的時間和 DS 資料就不是確定的。
用 SmartDashboard.getNumber 調參數重播時讀不到當時的值。改用 LoggedNetworkNumber 這類 AdvantageKit 的儀表板類別[13]。
以為改了 kP 重播就能看到新動作重播改不了輸入，要看新的動作請用模擬。

小測驗

練習：賽後找出為什麼沒射球

比賽中有一次操作手按了射球鍵，機器人卻沒射。日誌裡有 Flywheel/VelocityRps（輸入）和 Flywheel/AtSpeed（輸出），但射球的條件是 flywheel.atSpeed() && arm.atGoal()，而 Arm/AtGoal 當時沒記錄（假設這份程式還沒加第 6 章 E-3 那幾行 recordOutput）。你會怎麼查？

先確定時間點，再一個條件一個條件檢查：哪個有記錄、哪個沒有？

用 Joysticks 分頁找到按鍵時間，Line Graph 看 Flywheel/AtSpeed。沒記錄的條件，可以用重播補記錄。

checkout 當時的 GitSHA，在 ArmSubsystem.periodic 加 Logger.recordOutput("Arm/AtGoal", atGoal())，用 REPLAY 執行，在 ReplayOutputs 表看結果。

  1. 在 AdvantageScope 的 Joysticks 分頁找到按射球鍵的時間點。
  2. 用 Line Graph 看那段時間的 Flywheel/AtSpeed。如果是 false，問題就在飛輪（第 13 章）。
  3. 如果飛輪有到速，那就懷疑手臂。這時候用重播：checkout 當時的 GitSHA，在 ArmSubsystem.periodic 補上 Logger.recordOutput("Arm/AtGoal", atGoal())，切成 REPLAY 跑。
  4. 在 ReplayOutputs 表看 Arm/AtGoal。因為手臂位置是從日誌讀回來的輸入，重播算出的 atGoal() 會跟當時一模一樣。

這就是重播最擅長的事：把當時忘了記的輸出補記回來。只要手臂是照第 6 章用 IO 層寫的，重播的結果就是準的。找到原因之後，那行 recordOutput 就留在程式裡，下次就不用再重播了。
