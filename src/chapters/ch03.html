繼承與介面：導師是一種老師，值日生是一份職責

讀完這章，你會分得清 extends 和 implements，知道 @Override 和 super 在做什麼，並看懂 Robot extends TimedRobot、IntakeSubsystem extends SubsystemBase 和 RollerIOHardware implements RollerIO。

生活比喻一：導師也是老師

教師規章只寫一次。學校有一本教師規章：每位老師都有名字，都要上課、點名、打成績。

導師不用重抄一遍。導師也是老師，所以教師規章裡的每一條都適用。學校不會另外印一本「導師規章」把教師規章整本抄進去，而是寫：「導師適用全部教師規章，另外還要帶班、聯絡家長。」導師多出來的只有那幾條。

規章改了，導師自動跟著改。如果教師規章新增一條「每學期要參加研習」，所有導師也自動要參加，不用另外通知。因為導師不是抄了一份規章，而是「沿用」同一本。

體育老師的上課方式不一樣。體育老師也是老師，也要「上課」，但他的上課是在操場帶暖身和比賽，不是在教室講課。同樣叫「上課」，做法被換掉了。

先完成老師的報到，才輪到導師的部分。新來的導師報到時，要先辦完所有老師都要辦的手續，拿到教師證，才輪到領班級、拿學生名單。順序不能反過來。如果人事室沒特別交代，就走一般老師的標準報到流程。

一個人只能有一個「職稱」來源。在這所學校裡，一個人的身分只能從一本規章延伸出來：導師延伸自教師規章，不能同時又延伸自「工友規章」。

這就是繼承（inheritance）。子類別用 extends 沿用父類別的欄位和方法，再加上自己的[1]。體育老師換掉上課方式叫覆寫（override）[3]；先辦老師報到叫呼叫 super(...)[2]；只能有一本規章來源，對應 Java 的單一繼承[1]。

生活比喻二：值日生是一份職責

值日生不是一種人。教室後面貼著一張值日生職責表：擦黑板、倒垃圾、關窗關燈。值日生不是「一種學生」，而是一份「輪到誰就要做的事」。

職責表只寫要做什麼，不寫怎麼做。表上寫「擦黑板」，沒規定用板擦還是用濕抹布。每個人用自己的方式做，只要做到就好。

衛生股長只看職責有沒有完成。衛生股長來檢查時，他只問：「今天的值日生，黑板擦了嗎？垃圾倒了嗎？」他不在乎今天輪到的是小明還是小華。

學校買了掃地機器人。後來學校買了一台掃地機器人，設定成能擦黑板、推垃圾桶。機器人不是學生，也不是老師，但它能做職責表上的每一件事，所以它也能擔任值日生。衛生股長的檢查方式完全不用改。

一個人可以身兼多職。小明今天是值日生，同時也是風紀股長。兩份職責表他都簽了，兩邊的事都要做。

職責表可以附「預設做法」。職責表最下面寫著：「做完後在黑板右下角簽名。」這條大家照做就好，但如果有人有更好的回報方式，也可以改用自己的。

這就是介面（interface）。Oracle 教學把介面描述為類別與外界之間的契約：類別實作介面，就是承諾提供介面裡列出的行為[4]。衛生股長只看職責、不管是誰，這叫多型（polymorphism）。職責表上的預設做法，對應 Java 8 起的 default 方法[5]。

換成機器人：繼承

Robot extends TimedRobot

每個 WPILib 專案都有這一行。TimedRobot 已經處理好和 Driver Station 溝通、每 20 毫秒跑一次迴圈、切換自動與手動階段這些工作[7]。你沿用它，只要覆寫需要的方法：

public class Robot extends TimedRobot {
    @Override
    public void teleopPeriodic() {
        // 手動階段每 20 毫秒被呼叫一次（第 7 章詳述）
    }
}

@Override 不是必要的，但一定要寫。如果你把方法名打錯成 teleopPeriodc()，有 @Override 的話編譯器會報錯；沒有的話，Java 會當成你新增了一個沒人會呼叫的方法，機器人在手動階段就什麼都不做，這種 bug 很難找[3]。

SubsystemBase 與看不見的 super()

WPILib 文件說明，Subsystem 是一個介面，而建議的做法是繼承抽象類別 SubsystemBase。SubsystemBase 的建構子會自動呼叫 register() 向指令排程器註冊，這是 periodic() 會被呼叫的前提；它同時實作了 Sendable 介面，所以能把狀態送到儀表板[6]。

public class IntakeSubsystem extends SubsystemBase {
    public IntakeSubsystem() {
        // 這裡沒寫 super()，但 Java 會自動在第一行補上
    }

    @Override
    public void periodic() {
        // 因為父類別建構子已經註冊，這裡每個週期都會被呼叫
    }
}

Oracle 教學寫明：子類別建構子如果沒有明確呼叫父類別建構子，編譯器會自動插入一個呼叫父類別無參數建構子的 super()；如果要明確呼叫，必須寫在建構子第一行[2]。這就是「先辦老師報到」：你的 IntakeSubsystem 一建立，SubsystemBase 的部分就先完成註冊。

換成機器人：介面與多型

第 6 章的 IO 架構完全建立在介面上，這裡先看骨架：

// RollerIO.java：職責表
public interface RollerIO {
    void setVoltage(double volts);

    double getVelocityRps();

    // 預設做法：停止就是給 0V，實作的類別可以沿用或覆寫
    default void stop() {
        setVoltage(0.0);
    }
}

// RollerIOHardware.java：真馬達來當值日生
public class RollerIOHardware implements RollerIO {
    private final TalonFX motor = new TalonFX(21); // TODO: 依接線確認
    private final VoltageOut request = new VoltageOut(0);

    @Override
    public void setVoltage(double volts) {
        motor.setControl(request.withOutput(volts));
    }

    @Override
    public double getVelocityRps() {
        return motor.getVelocity().getValueAsDouble();
    }
}

// RollerIOSim.java：模擬器來當值日生（完整版見第 6 章）
public class RollerIOSim implements RollerIO {
    private double appliedVolts = 0.0;

    @Override
    public void setVoltage(double volts) {
        appliedVolts = volts;
    }

    @Override
    public double getVelocityRps() {
        return 0.0; // 第 6 章會換成物理模擬
    }
}

衛生股長的角色由 Subsystem 擔任，它只認得 RollerIO：

RollerIO io = new RollerIOHardware();
io.setVoltage(8.0); // 執行 RollerIOHardware 的做法：真的送電壓給馬達

io = new RollerIOSim();
io.setVoltage(8.0); // 同一行程式，這次執行 RollerIOSim 的做法
io.stop();          // 兩個實作都沒寫 stop()，用的是介面的預設做法

常見錯誤

implements 了介面卻沒寫完方法介面裡沒有 default 的方法，實作的類別都必須寫出來，少一個就編譯失敗。錯誤訊息通常是「is not abstract and does not override abstract method ...」，看到它就去對照介面，找出漏了哪一個。
教練提醒每個覆寫的方法前面都加 @Override，這是隊上的規定，不是選擇。它是編譯器免費幫你做的檢查。

小測驗

練習：定義一份機構的契約

寫一個介面 Mechanism，規定兩件事：void stop() 和 boolean isAtGoal()。再讓第 1 章練習的 Flywheel 實作它：stop() 把目標轉速設為 0；isAtGoal() 需要知道目前轉速，所以先加一個欄位 currentRpm 和方法 updateCurrentRpm(double rpm)。

介面只寫「要做什麼」，不寫怎麼做；類別用 implements 承諾做到。

介面裡的方法宣告成 void stop(); 與 boolean isAtGoal();，實作時加 @Override。

isAtGoal 需要目前轉速：加一個 private double currentRpm 與 updateCurrentRpm(double rpm)，判斷方式和第 1 章的 isAtSpeed 一樣。

// Mechanism.java
public interface Mechanism {
    void stop();
    boolean isAtGoal();
}

// Flywheel.java
public class Flywheel implements Mechanism {
    public static final double MAX_RPM = 6000.0;
    public static final double TOLERANCE_RPM = 50.0;

    private double targetRpm = 0.0;
    private double currentRpm = 0.0;

    public void setTargetRpm(double rpm) {
        targetRpm = Math.max(0.0, Math.min(MAX_RPM, rpm));
    }

    public void updateCurrentRpm(double rpm) {
        currentRpm = rpm;
    }

    @Override
    public void stop() {
        targetRpm = 0.0;
    }

    @Override
    public boolean isAtGoal() {
        return Math.abs(currentRpm - targetRpm) < TOLERANCE_RPM;
    }
}
