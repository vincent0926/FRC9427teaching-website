繼承與介面：導師是一種老師，值日生是一份職責

打開任何一個機器人專案，第一眼就會看到 Robot extends TimedRobot。這章把 extends 和 implements 講清楚，順便講 @Override 和 super，看完你就看得懂 IntakeSubsystem extends SubsystemBase、RollerIOHardware implements RollerIO 這種寫法在幹嘛。

比喻一：導師也是老師

學校有一本教師規章，寫著每位老師都有名字，都要上課、點名、打成績。

導師也是老師，所以規章裡每一條都適用。學校不會另外印一本「導師規章」把教師規章整本抄一遍，而是寫一句「導師適用全部教師規章，另外還要帶班、聯絡家長」。導師多出來的就只有那幾條。

這樣有個好處：哪天教師規章多一條「每學期要參加研習」，所有導師也自動要去，不用另外通知。因為導師沒有抄一份規章，是直接沿用同一本。

體育老師也是老師，也要「上課」，可是他上課是在操場帶暖身、打比賽，不是在教室講課。名字一樣叫上課，做法被換掉了。

新導師報到的時候，要先把所有老師都要辦的手續辦完、拿到教師證，才輪到領班級、拿學生名單，順序不能反過來。人事室沒特別交代的話，就走一般老師的標準流程。

還有一條規矩：在這間學校，一個人的身分只能從一本規章延伸出來。導師延伸自教師規章，就不能同時又延伸自「工友規章」。

這就是繼承（inheritance）：子類別用 extends 沿用父類別的欄位和方法，再加上自己的東西[1]。體育老師把上課方式換掉，叫覆寫（override）[3]。先辦老師的報到手續，就是呼叫 super(...)[2]。只能有一本規章當來源，就是 Java 的單一繼承[1]。

比喻二：值日生是一份職責

教室後面貼著一張值日生職責表：擦黑板、倒垃圾、關窗關燈。值日生不是「某一種學生」，而是「輪到誰誰就要做的事」。

表上只寫要做什麼，沒寫怎麼做。寫「擦黑板」，沒規定要用板擦還是濕抹布，你用自己的方法，做到就好。

衛生股長來檢查的時候只會問：「今天值日生黑板擦了沒？垃圾倒了沒？」他才不管今天輪到小明還是小華。

後來學校買了一台掃地機器人，設定成會擦黑板、會推垃圾桶。它不是學生也不是老師，但職責表上的事它都做得到，所以它也可以當值日生，衛生股長的檢查方式一點都不用改。

一個人也可以身兼多職。小明今天是值日生，同時也是風紀股長，兩張職責表他都簽了，兩邊的事都要做。

職責表最下面還有一行：「做完在黑板右下角簽名。」這條大家照做就好，但如果有人有更好的回報方式，也可以用自己的。

這就是介面（interface）。Oracle 教學把介面形容成類別和外界之間的契約：類別實作一個介面，就是承諾會提供介面裡列出的那些行為[4]。衛生股長只看職責、不管是誰在做，這叫多型（polymorphism）。最後那行「做完簽名」，就是 Java 8 開始有的 default 方法[5]。

這兩個比喻哪裡不準第一，真的職責表上可以留空格讓人填，但 Java 介面不能有一般欄位，只能有常數（自動就是 public static final）。介面規定的是「能做什麼」，不負責存每個物件的狀態。第二，「導師是一種老師」很好懂，但寫程式的時候不要為了少打幾行就亂用繼承。判斷方法很簡單：講得出「A 是一種 B」才用 extends；只講得出「A 能做 B 規定的事」，就用介面。

換成機器人：繼承

Robot extends TimedRobot

每個 WPILib 專案都有這行。跟 Driver Station 溝通、每 20 毫秒跑一次迴圈、切換自動和手動階段，這些麻煩事 TimedRobot 都幫你做好了[7]。你繼承它，只要覆寫自己需要的方法就好：

public class Robot extends TimedRobot {
    @Override
    public void teleopPeriodic() {
        // 手動階段每 20 毫秒被呼叫一次（第 7 章詳述）
    }
}

@Override 不寫也能編譯，但請一定要寫。假設你手滑打成 teleopPeriodc()：有 @Override，編譯器會直接報錯；沒有的話，Java 會以為你新增了一個沒人會呼叫的方法，結果機器人在手動階段什麼都不做，而且你會找很久才發現是少一個 i[3]。

SubsystemBase 與看不見的 super()

在 WPILib 裡，Subsystem 其實是一個介面，建議的寫法是去繼承抽象類別 SubsystemBase。SubsystemBase 的建構子會自動呼叫 register() 向指令排程器註冊，沒有註冊的話 periodic() 根本不會被呼叫。它也實作了 Sendable，所以狀態可以送到儀表板[6]。

public class IntakeSubsystem extends SubsystemBase {
    public IntakeSubsystem() {
        // 這裡沒寫 super()，但 Java 會自動在第一行補上
    }

    @Override
    public void periodic() {
        // 因為父類別建構子已經註冊，這裡每個週期都會被呼叫
    }
}

規則是這樣：子類別的建構子如果沒有自己呼叫父類別建構子，編譯器會偷偷在第一行補一個 super()，呼叫父類別的無參數建構子；如果你要自己寫，就一定要寫在第一行[2]。這就是「先辦老師報到」：IntakeSubsystem 一建立，SubsystemBase 那部分就先把註冊做完了。

換成機器人：介面與多型

第 6 章的 IO 架構整個都是靠介面撐起來的，這裡先看個骨架就好：

// RollerIO.java：職責表
public interface RollerIO {
    void setVoltage(double volts);

    double getVelocityRps();

    // 預設做法：停止就是給 0V，實作的類別可以沿用或覆寫
    default void stop() {
        setVoltage(0.0);
    }
}

// RollerIOHardware.java：真馬達來當值日生
public class RollerIOHardware implements RollerIO {
    private final TalonFX motor = new TalonFX(21); // TODO: 依接線確認
    private final VoltageOut request = new VoltageOut(0);

    @Override
    public void setVoltage(double volts) {
        motor.setControl(request.withOutput(volts));
    }

    @Override
    public double getVelocityRps() {
        return motor.getVelocity().getValueAsDouble();
    }
}

// RollerIOSim.java：模擬器來當值日生（完整版見第 6 章）
public class RollerIOSim implements RollerIO {
    private double appliedVolts = 0.0;

    @Override
    public void setVoltage(double volts) {
        appliedVolts = volts;
    }

    @Override
    public double getVelocityRps() {
        return 0.0; // 第 6 章會換成物理模擬
    }
}

衛生股長就是 Subsystem，它只認 RollerIO，不管背後是誰：

RollerIO io = new RollerIOHardware();
io.setVoltage(8.0); // 執行 RollerIOHardware 的做法：真的送電壓給馬達

io = new RollerIOSim();
io.setVoltage(8.0); // 同一行程式，這次執行 RollerIOSim 的做法
io.stop();          // 兩個實作都沒寫 stop()，用的是介面的預設做法

常見錯誤

implements 了介面，方法卻沒寫完介面裡沒有 default 的方法，實作的類別全部都要寫出來，少一個就編譯失敗。錯誤訊息通常長這樣：「is not abstract and does not override abstract method ...」。看到就回去對照介面，找漏掉的是哪一個。
教練提醒每個覆寫的方法前面都要加 @Override。這是隊上的規定，不是看心情。編譯器免費幫你檢查，不用白不用。

小測驗

練習：定義一份機構的契約

寫一個介面 Mechanism，規定兩件事：void stop() 和 boolean isAtGoal()。然後讓第 1 章練習寫的 Flywheel 去實作它。stop() 就是把目標轉速設成 0；isAtGoal() 要知道目前轉速，所以先幫它加一個欄位 currentRpm 和方法 updateCurrentRpm(double rpm)。

介面只寫「要做什麼」，不管怎麼做；類別用 implements 承諾自己做得到。

介面裡的方法宣告成 void stop(); 與 boolean isAtGoal();，實作時加 @Override。

isAtGoal 需要目前轉速：加一個 private double currentRpm 和 updateCurrentRpm(double rpm)，判斷方法跟第 1 章的 isAtSpeed 一模一樣。

// Mechanism.java
public interface Mechanism {
    void stop();
    boolean isAtGoal();
}

// Flywheel.java
public class Flywheel implements Mechanism {
    public static final double MAX_RPM = 6000.0;
    public static final double TOLERANCE_RPM = 50.0;

    private double targetRpm = 0.0;
    private double currentRpm = 0.0;

    public void setTargetRpm(double rpm) {
        targetRpm = Math.max(0.0, Math.min(MAX_RPM, rpm));
    }

    public void updateCurrentRpm(double rpm) {
        currentRpm = rpm;
    }

    @Override
    public void stop() {
        targetRpm = 0.0;
    }

    @Override
    public boolean isAtGoal() {
        return Math.abs(currentRpm - targetRpm) < TOLERANCE_RPM;
    }
}
