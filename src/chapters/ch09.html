CAN ID 09｜WPILib 基礎

Trigger 與按鍵綁定：對講機、門鈴和電燈開關

指令寫好了，接下來要決定「什麼時候跑」。這章講 onTrue、whileTrue、toggleOnTrue 三種綁定差在哪，怎麼用感測器或任意條件做 Trigger、怎麼把條件組起來，還有為什麼按鍵綁定只能在 RobotContainer 裡寫一次。

先講個比喻：學校裡的三種按鈕

學校裡至少有三種按鈕。第一種是警衛室的門鈴：按一下警衛就出來開門，你按完放手，他照樣把門開完；按住不放也不會讓他開比較久。

第二種是廣播的對講機：要按住才能講話，一放開聲音就斷，不管你話講完了沒。

第三種是教室的電燈開關：按一下開、再按一下關。如果燈自己壞掉熄了，下次按就是重新開燈。

按鈕也不一定是人按的。下雨偵測器偵測到下雨，就會自動觸發「把操場的器材收回來」，這個按鈕是天氣在按。

條件還可以組合。「下雨而且正在上體育課」才需要改到室內；「火警或地震」只要一個發生就要疏散。

另外總是有人會狂按門鈴，所以警衛室的門鈴裝了防連按：要連續按住一小段時間才算一次。

最後，哪個按鈕對應哪件事，是開學就訂好貼在牆上的，不會每節課重新規定一次。

比喻WPILib
門鈴：按下開始，放開不影響onTrue
對講機：按住進行，放開就停whileTrue
電燈開關：按一下切換toggleOnTrue
下雨偵測器用 BooleanSupplier 建立的 Trigger
「而且」、「或」and()、or()、negate()
防連按debounce()
開學時訂好的規則在 RobotContainer 建構子裡宣告一次
這個比喻哪裡不準門鈴按一下只會叫一次警衛。但 onTrue 在指令還在跑的時候又被觸發，WPILib 會試著再排程同一個指令；它已經在跑了，所以這次排程沒有任何效果，指令不會重來。想要「再按一次就重新開始」，得自己先取消再排程，或換別的綁定方式。

綁定只宣告一次

除了自動階段開始時排的自動指令、Subsystem 空著時自動排的預設指令，最常見的跑指令方式就是綁到某個觸發事件上，例如操作手按下按鈕。這種綁定是宣告式的，機器人初始化時「宣告」一次就好，靠的是 Trigger 類別[1]。所以綁定全部寫在 RobotContainer 的建構子（或它呼叫的 configureBindings()），絕對不要寫進 periodic。

取得 Trigger

private final CommandXboxController driver = new CommandXboxController(0);   // Driver Station 的 0 號控制器
private final CommandXboxController operator = new CommandXboxController(1);

// 按鈕
driver.a();              // A 鍵
driver.leftBumper();     // 左肩鍵
driver.povUp();          // 十字鍵上
// 扳機（類比值）超過門檻就算按下
operator.rightTrigger(0.5);

// 任意條件：只要能回答 true 或 false
Trigger armAtGoal = new Trigger(arm::atGoal);

任意條件的 Trigger 收一個 BooleanSupplier，就是第 4 章那張「看一下有沒有下雨」的字條。綁控制器按鍵最常見，但其實任何觸發事件都可以綁[1]。控制器上有哪些按鍵方法，翻 CommandXboxController 的 API 文件最快[3]；and、or、negate、debounce 這些組合方法則在 Trigger 的 API 文件裡[2]。

三種主要綁定

綁定變成 true 時變成 false 時適合
onTrue排程指令什麼都不做會自己結束的動作，例如手臂移到定點
whileTrue排程指令取消指令按住才做的動作，例如按住吸入
toggleOnTrue指令沒在執行就排程，正在執行就取消什麼都不做開與關，例如切換某個模式

三種都有 false 的版本：onFalse、whileFalse、toggleOnFalse。而且綁定方法會回傳原本那個 Trigger，所以可以一路串下去，同一顆鍵的按下和放開綁不同指令[1]。

private void configureBindings() {
    // 門鈴：按一下，手臂移到得分位置，自己到定位就結束
    operator.y().onTrue(arm.goTo(ArmState.SCORE));

    // 對講機：按住吸入，放開停止（runState 結束時會設回 NONE）
    operator.rightTrigger(0.5).whileTrue(intake.runState(IntakeState.INTAKING));

    // 同一顆鍵串接：按下吐出，放開收手臂
    operator.leftBumper()
        .whileTrue(intake.runState(IntakeState.SCORING))
        .onFalse(arm.goTo(ArmState.STOW));
}

動手試：三種按鈕

同一個「吸入」指令分別綁在三種綁定上。按下、放開，看三個的狀態有什麼不一樣。多按幾次 toggle 那顆試試看。

組合條件與防連按

// 而且：手臂在取件位置，而且按住扳機，才吸入
new Trigger(arm::atGoal).and(operator.rightTrigger(0.5))
    .whileTrue(intake.runState(IntakeState.INTAKING));

// 或：兩位操作手任何一個按下 back 鍵，都收回手臂
driver.back().or(operator.back()).onTrue(arm.goTo(ArmState.STOW));

// 防連按：必須穩定為 true 0.1 秒才算
new Trigger(limitSwitch::get).debounce(0.1).onTrue(arm.goTo(ArmState.STOW));

Trigger 可以用 debounce（背後是 Debouncer 類別）防止快速重複觸發，數位輸入來的 Trigger 特別需要[1]。上面的 limitSwitch 是假設的 DigitalInput；照第 6 章的原則，正式的程式應該由 Subsystem 從輸入物件提供這個狀態，不要在 RobotContainer 直接讀硬體。

常見錯誤

不會自己結束的指令綁了 onTrue把 intake.runState(...) 這種不會自己停的指令綁在 onTrue，放開按鍵之後滾輪還是一直轉，轉到有別的指令來打斷為止。按住才做的動作請用 whileTrue。
綁定寫在 periodic 裡每 20 毫秒就多綁一次，按一下就排程成百上千次，而且這些綁定永遠不會被移掉。綁定只在 RobotContainer 建構時做一次。
兩顆鍵搶同一個 SubsystemA 鍵和 B 鍵的指令都 require 手臂，同時按的話，後排上的會打斷先排的（第 8 章）。操作手要知道這件事，排按鍵配置的時候就要避免誤觸。
教練提醒按鍵配置要跟駕駛、操作手一起討論，做成一張圖貼在 Driver Station 筆電旁邊。比賽的時候沒時間想「這顆是按一下還是要按住」，所以配置越一致越好：同一類動作就用同一種綁定。

小測驗

練習：設計一組配置

操作手（1 號控制器）想要：按住右扳機吸入、放開就停；按一下 Y 手臂到 SCORE；按一下 A 手臂到 INTAKE；按住左肩鍵吐出，放開後手臂自己回 STOW。把 configureBindings() 寫出來。

先把每個需求分類：「按住才做」「按一下就做」「放開時做」，各自對到哪種綁定？

按住：whileTrue；按一下：onTrue；放開時：onFalse。扳機用 rightTrigger(0.5) 取得 Trigger。

左肩鍵要同時做兩件事：operator.leftBumper().whileTrue(吐出指令).onFalse(arm.goTo(ArmState.STOW))。

private void configureBindings() {
    operator.rightTrigger(0.5).whileTrue(intake.runState(IntakeState.INTAKING));
    operator.y().onTrue(arm.goTo(ArmState.SCORE));
    operator.a().onTrue(arm.goTo(ArmState.INTAKE));
    operator.leftBumper()
        .whileTrue(intake.runState(IntakeState.SCORING))
        .onFalse(arm.goTo(ArmState.STOW));
}

注意每個 arm.goTo(...)、intake.runState(...) 都是呼叫一次 factory、拿到一個全新的指令物件。為什麼這很重要？第 10 章會講。
