CAN ID 09｜WPILib 基礎

Trigger 與按鍵綁定：對講機、門鈴和電燈開關

讀完這章，你會分清楚 onTrue、whileTrue、toggleOnTrue 的差別，知道怎麼用感測器或條件建立 Trigger、怎麼組合條件，以及為什麼按鍵綁定只在 RobotContainer 裡宣告一次。

生活比喻：學校裡的三種按鈕

門鈴。警衛室的門鈴按一下，警衛就會出來開門。你按完就放手，警衛照樣把門開完；按住不放也不會讓他開得比較久。

對講機。廣播用的對講機要按住才能說話，一放開聲音就斷了，不管話有沒有講完。

電燈開關。教室的電燈按一下開、再按一下關。如果燈自己壞掉熄了，下次按就是重新開燈。

不只人會按按鈕。下雨偵測器偵測到下雨時，會自動觸發「收回操場的器材」。這個按鈕是由天氣按的，不是人。

條件可以組合。「下雨，而且正在上體育課」才需要改到室內；「火警或地震」任何一個發生都要疏散。

防止連按。有些同學會一直狂按門鈴。警衛室的門鈴裝了防連按裝置：要連續按住一小段時間才算一次。

規則開學時就訂好。哪個按鈕對應哪件事，是開學時訂好、貼在牆上的，不會每節課重新規定。

比喻WPILib
門鈴：按下開始，放開不影響onTrue
對講機：按住進行，放開就停whileTrue
電燈開關：按一下切換toggleOnTrue
下雨偵測器用 BooleanSupplier 建立的 Trigger
「而且」、「或」and()、or()、negate()
防連按debounce()
開學時訂好的規則在 RobotContainer 建構子裡宣告一次
這個比喻哪裡不準門鈴按一下只會叫警衛一次。但 onTrue 如果在指令還在執行時又被觸發，WPILib 會嘗試再排程同一個指令；因為它已經在執行中，這次排程不會有效果，指令不會重新開始。想要「再按一次就重新開始」，要自己先取消再排程，或換成別的綁定方式。

綁定只宣告一次

WPILib 文件說明，除了自動階段開始時排程的自動指令，以及 Subsystem 空閒時自動排程的預設指令之外，最常見的執行指令方式是綁定到觸發事件，例如操作手按下按鈕。這種綁定是宣告式的：在機器人初始化時「宣告」一次就好，綁定是透過 Trigger 類別完成的[1]。所以綁定都寫在 RobotContainer 的建構子（或它呼叫的 configureBindings()），絕對不要寫在 periodic 裡。

取得 Trigger

private final CommandXboxController driver = new CommandXboxController(0);   // Driver Station 的 0 號控制器
private final CommandXboxController operator = new CommandXboxController(1);

// 按鈕
driver.a();              // A 鍵
driver.leftBumper();     // 左肩鍵
driver.povUp();          // 十字鍵上
// 扳機（類比值）超過門檻就算按下
operator.rightTrigger(0.5);

// 任意條件：只要能回答 true 或 false
Trigger armAtGoal = new Trigger(arm::atGoal);

任意條件的 Trigger 收一個 BooleanSupplier，也就是第 4 章「看一下有沒有下雨」的字條。WPILib 文件說明，雖然綁定到控制器按鍵最常見，但也可以綁定到任何觸發事件[1]。

三種主要綁定

綁定變成 true 時變成 false 時適合
onTrue排程指令什麼都不做會自己結束的動作，例如手臂移到定點
whileTrue排程指令取消指令按住才做的動作，例如按住吸入
toggleOnTrue指令沒在執行就排程，正在執行就取消什麼都不做開與關，例如切換某個模式

三種都有對應 false 的版本：onFalse、whileFalse、toggleOnFalse。WPILib 文件也說明，綁定方法都會回傳呼叫它的那個 Trigger，所以可以串接，在同一個按鍵的不同狀態綁上不同指令[1]。

private void configureBindings() {
    // 門鈴：按一下，手臂移到得分位置，自己到定位就結束
    operator.y().onTrue(arm.goTo(ArmState.SCORE));

    // 對講機：按住吸入，放開停止（runState 結束時會設回 NONE）
    operator.rightTrigger(0.5).whileTrue(intake.runState(IntakeState.INTAKING));

    // 同一顆鍵串接：按下吐出，放開收手臂
    operator.leftBumper()
        .whileTrue(intake.runState(IntakeState.SCORING))
        .onFalse(arm.goTo(ArmState.STOW));
}

動手試：三種按鈕

同一個「吸入」指令分別綁在三種綁定上。按下、放開，觀察三者的狀態差異。

組合條件與防連按

// 而且：手臂在取件位置，而且按住扳機，才吸入
new Trigger(arm::atGoal).and(operator.rightTrigger(0.5))
    .whileTrue(intake.runState(IntakeState.INTAKING));

// 或：兩位操作手任何一個按下 back 鍵，都收回手臂
driver.back().or(operator.back()).onTrue(arm.goTo(ArmState.STOW));

// 防連按：必須穩定為 true 0.1 秒才算
new Trigger(limitSwitch::get).debounce(0.1).onTrue(arm.goTo(ArmState.STOW));

WPILib 文件說明，Trigger 可以用 debounce 搭配 Debouncer 類別防止快速重複觸發，特別是來自數位輸入的 Trigger[1]。上面的 limitSwitch 是一個假設的 DigitalInput；依第 6 章的原則，正式程式應該讓 Subsystem 從輸入物件提供這個狀態。

常見錯誤

會一直執行的指令用了 onTrue把 intake.runState(...) 這種不會自己結束的指令綁在 onTrue，放開後滾輪還是一直轉，直到有別的指令打斷它。按住才做的動作要用 whileTrue。
把綁定寫在 periodic 裡每 20 毫秒新增一次綁定，按一下就會排程成百上千次，而且綁定永遠不會被移除。綁定只在 RobotContainer 建構時做一次。
兩顆鍵搶同一個 SubsystemA 鍵和 B 鍵的指令都 require 手臂，同時按下時，後排程的會打斷前一個（第 8 章）。操作手必須知道這個規則，按鍵配置時就要避免誤觸。
教練提醒按鍵配置要和駕駛、操作手一起決定，並做成一張圖貼在 Driver Station 筆電旁。比賽中沒有時間思考「這顆鍵是按一下還是按住」，配置越一致越好：同類動作用同一種綁定。

小測驗

練習：設計一組配置

操作手（1 號控制器）的需求：按住右扳機吸入、放開停止；按一下 Y 手臂到 SCORE；按一下 A 手臂到 INTAKE；按住左肩鍵吐出，放開後手臂自動回 STOW。寫出 configureBindings()。

看參考答案 
private void configureBindings() {
    operator.rightTrigger(0.5).whileTrue(intake.runState(IntakeState.INTAKING));
    operator.y().onTrue(arm.goTo(ArmState.SCORE));
    operator.a().onTrue(arm.goTo(ArmState.INTAKE));
    operator.leftBumper()
        .whileTrue(intake.runState(IntakeState.SCORING))
        .onFalse(arm.goTo(ArmState.STOW));
}

注意每個 arm.goTo(...)、intake.runState(...) 都是呼叫一次 factory、得到一個新的指令物件。第 10 章會說明為什麼這很重要。
