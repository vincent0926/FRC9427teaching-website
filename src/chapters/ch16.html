CAN ID 16｜上場

自動階段與路徑：校外教學的行程表

自動階段那十幾秒，沒有人能碰搖桿，機器人全靠你事先寫好的程式。這章講場地座標怎麼定、里程計怎麼估位置（還有它為什麼會飄）、PathPlanner 的路徑和 Auto 怎麼變成指令。最後是幾個上場前一定要搞定的細節：紅藍聯盟翻轉、Named Commands、自動程式選單。

版本說明這章是照 WPILib 2026 和 PathPlannerLib 2026 的文件寫的。PathPlanner 的 API 幾乎每年都會改，網路上的舊範例（像 2024 年以前的 HolonomicPathFollowerConfig）已經不能用了。這章拿 swerve 底盤當例子。

先講個比喻：校外教學的行程表

校外教學的前 15 分鐘，老師得留在學校，不能跟車，遊覽車只能照事先寫好的行程表走。路線怎麼開、哪一站下車做什麼，全部都要提前寫好。

車上沒有 GPS，司機只能記「往北開了幾公里、在哪裡左轉」，自己推算現在在哪。短程很準，但開久了，或中途被別的車擦到一下，推算就會越來越偏。

學校有紅、藍兩個校門，兩邊的路線剛好左右對稱。地圖只畫一份，原點永遠在藍色校門；從紅色校門出發，就把整份路線翻過去用。

行程表上會寫「到博物館：活動 A」。活動 A 是什麼，出發前老師就要先跟領隊講清楚。出發後才講就來不及了，領隊手上的行程表早就印好，根本不知道活動 A 要幹嘛。

老師通常會準備好幾份行程表：天氣好走 A 路線，下雨走 B 路線。出發前在黑板上選好一份，遊覽車就照那份走。

這個比喻哪裡不準遊覽車開偏了，司機會看路標修正；機器人的里程計不會自己修正，要靠第 17 章的視覺定位（AprilTag）才拉得回來。還有，路線要怎麼「翻過去」看當年的場地：FRC 場地有「鏡射」和「旋轉」兩種配置，每年不一樣[1]。上場前一定要在紅方實際跑一次，確認翻過去的路徑是對的。

場地與機器人的座標

WPILib 大部分時候用 NWU 慣例：X 往前是正、Y 往左是正、Z 往上；角度 0° 對著 +X，逆時針為正，所以 90° 就是 +Y[1]。有兩個地方特別容易出錯[1]：

  • 有些陀螺儀是順時針為正，讀值方向要確認，需要的話反過來。
  • 搖桿用的是另一套座標（NED）：往前推是負的 Y、往右推是正的 X。所以搖桿值丟給底盤之前，常常要加負號。

里程計：機器人怎麼知道自己在哪

里程計用輪子的編碼器加陀螺儀，推算機器人在場上的位置（Pose2d：x、y、朝向）。因為只靠編碼器和陀螺儀，估出來的位置會隨時間慢慢飄，跟別台機器人撞一下更明顯；不過在自動階段通常很準[2]。所以自動階段靠里程計跑路徑沒問題，前提是每次開始前位置都要設對。

如果底盤是用 CTRE Tuner X 產生的 swerve 程式，它會自己維護里程計，getState().Pose 就是目前估計的位置[3]。

PathPlanner 是什麼

PathPlanner 分兩塊：電腦上的 GUI 用來畫路徑、組 Auto；機器人程式裡的 PathPlannerLib 負責讀檔、跟著路徑跑。PathPlannerLib 用 WPILib 的 Vendor Dependency Manager 就能裝[4]（第 0 章講過的 vendordep）。

GUI 裡的 Path 就是一條路線；Auto 則是一個 sequential 指令群組，裡面可以放路徑跟隨指令、Named Commands、等待指令，還有巢狀的指令群組，同一條路徑也可以在好幾個 Auto 裡重複用[5]。說白了，Auto 就是第 10 章的組合指令，只是用 GUI 畫出來而已。

Robot Config

GUI 的設定頁要填機器人的質量、轉動慣量（MOI）、輪子和馬達這些資料，PathPlanner 會用它們限制軌跡的最大速度和加速度。這些值要盡量準：質量要包含保險桿和電池；MOI 最好用 SysId 的結果算，粗估的公式假設質量平均分布，通常不準[6]。你看，第 15 章的 SysId 又出現了。

設定 AutoBuilder

PathPlannerLib 用 AutoBuilder 把 GUI 裡的 Auto 變成指令，建議在底盤 Subsystem 的建構子裡設定[7]。下面是 CTRE 官方 swerve + PathPlanner 範例的寫法[3]：

private void configureAutoBuilder() {
    try {
        var config = RobotConfig.fromGUISettings();
        AutoBuilder.configure(
            () -> getState().Pose,   // 目前位置
            this::resetPose,         // Auto 有起始位置時，用它重設里程計
            () -> getState().Speeds, // 目前速度（機器人座標）
            (speeds, feedforwards) -> setControl(
                m_pathApplyRobotSpeeds.withSpeeds(ChassisSpeeds.discretize(speeds, 0.020))
                    .withWheelForceFeedforwardsX(feedforwards.robotRelativeForcesXNewtons())
                    .withWheelForceFeedforwardsY(feedforwards.robotRelativeForcesYNewtons())),
            new PPHolonomicDriveController(
                new PIDConstants(10, 0, 0),  // 平移 PID（範例值，要實測）
                new PIDConstants(7, 0, 0)),  // 旋轉 PID（範例值，要實測）
            config,
            () -> DriverStation.getAlliance().orElse(Alliance.Blue) == Alliance.Red, // 紅方時翻轉
            this);
    } catch (Exception ex) {
        DriverStation.reportError("Failed to load PathPlanner config and configure AutoBuilder", ex.getStackTrace());
    }
}

一項一項看：

  • 速度一定要是機器人座標（robot relative），不是場地座標[7]。
  • PID：路徑跟隨本身就有前饋，PID 只負責修「實際位置跟路徑差多少」，跟第 13 章是同一個觀念。
  • 翻轉：最後一個參數回傳 true，路徑就會翻到紅方那一側。這裡特別強調原點永遠在藍方；其他要看聯盟顏色的轉換，要自己處理[7]。
  • 最後那個 this：讓路徑跟隨指令 require 底盤 Subsystem（第 8 章）。
DriverStation.getAlliance() 可能是空的它回傳的是 Optional，還沒連上 Driver Station 或 FMS 的時候是空的。上面用 orElse(Alliance.Blue) 預設成藍方。這也是為什麼「要不要翻轉」要寫成 lambda：在路徑開始跑的那一刻才判斷，不是開機時就決定。

Named Commands

Auto 和路徑上的事件標記（event marker）要讓機構做事的時候，是用名字找指令的。程式裡要用 NamedCommands.registerCommand 把名字跟指令對起來，名字要跟 GUI 裡的一字不差[8]。

public RobotContainer() {
    // 1. 建立 Subsystem
    // 2. 註冊 Named Commands（一定要在建立任何 Auto 或 Path 之前）
    NamedCommands.registerCommand("armScore", arm.goTo(ArmState.SCORE));
    NamedCommands.registerCommand("armStow", arm.goTo(ArmState.STOW));
    NamedCommands.registerCommand("intake", intake.intakeUntilHasPiece());
    // 3. 建立自動程式選單
    autoChooser = AutoBuilder.buildAutoChooser();
    SmartDashboard.putData("Auto Chooser", autoChooser);
    // 4. 按鍵綁定
    configureBindings();
}
順序很重要Named Commands 一定要在建立任何 PathPlanner Auto 或 Path 之前註冊；晚註冊的話，已經建好的 Auto 根本不會用到它。建議在 RobotContainer 裡、Subsystem 建好之後、其他指令建立之前註冊[8]。

事件標記還有一條很容易漏掉的規則：路徑跑到終點時，所有事件標記觸發的指令都會被要求結束。如果你想在路徑結束後才開始某個動作，要放在 Auto 裡，或放到下一條路徑的開頭[5]。

intake.intakeUntilHasPiece() 只是示範名字，意思是「吸到遊戲物件才結束」的指令。Auto 是 sequential 群組，所以放進去的指令一定要會結束，不然後面的步驟永遠輪不到（第 10 章）。第 6 章的 goTo 用 until(this::atGoal) 結束，剛好適合。

自動程式選單與載入時機

AutoBuilder.buildAutoChooser() 會做出一個包含專案裡所有 Auto 的 SendableChooser，預設選項是 Commands.none()，也可以傳名字指定預設的 Auto[7]。然後第 7 章的 getAutonomousCommand() 回傳選到的那個就好：

public Command getAutonomousCommand() {
    return autoChooser.getSelected();
}
  • 開機時就載入。官方很強烈建議在程式啟動時就把所有 Auto 建好，不要等到要跑才建，因為載入複雜的路徑可能卡很久[7]。在建構子裡呼叫 buildAutoChooser 本身就符合這點。
  • 刪掉的 Auto 還在選單裡？它會載入 deploy 資料夾裡所有的 Auto；build.gradle 要有 deleteOldFiles = true，不然你刪掉的檔案不會從 roboRIO 上清掉[7]。

上場前的自動程式檢查

  1. 選單選的是這一場要跑的 Auto，而且不是預設的「None」。（真的有隊伍這樣上場過。）
  2. 機器人擺的位置跟 Auto 的起始位置一樣（Auto 有設起始位置的話，會用 resetPose 重設里程計）。
  3. Driver Station 上的聯盟顏色是對的，路徑才會往正確的那邊翻。
  4. 在練習場或模擬（第 6 章 D 部分）裡，紅藍兩邊都實際跑過一次。

常見錯誤

Named Command 名字對不上GUI 裡叫 ArmScore，程式註冊的是 armScore，大小寫不一樣就對不上，Auto 跑到那一步什麼都不做。
Auto 裡放了不會結束的指令像是用 run(...) 做的預設指令，整個 Auto 就卡死在那一步。
陀螺儀方向反了順時針為正的陀螺儀沒反過來，里程計的朝向就跟實際相反，路徑一轉彎就走錯邊，場地導向駕駛也會亂掉。
開機時就判斷聯盟顏色在 RobotContainer 建構子裡讀 getAlliance()，那時候可能還沒連上 FMS，拿到的是空值或錯的顏色。
Robot Config 亂填質量、MOI、輪徑填錯，PathPlanner 產生的軌跡會超過機器人實際做得到的加速度，路徑越跑越偏。

小測驗

練習：兩段式自動程式

不用 GUI，純用程式組一個 Auto：先把手臂移到 SCORE，手臂到位之後跑一條叫 "Leave" 的路徑，同時把手臂收回 STOW。給你一個線索：AutoBuilder.followPath(PathPlannerPath.fromPathFile("Leave")) 會回傳跟隨這條路徑的指令，而 fromPathFile 可能會丟例外。

整個動作分兩段：先手臂到位，再同時「走路徑」跟「收手臂」。載入路徑可能失敗，例外要處理。

用 Commands.sequence 與 Commands.parallel；路徑用 PathPlannerPath.fromPathFile("Leave")，再交給 AutoBuilder.followPath(...)。

把整段包在 try 裡；catch 時用 DriverStation.reportError 回報，並回傳 Commands.none()，讓程式不會當掉。

private Command buildLeaveAuto() {
    try {
        PathPlannerPath leave = PathPlannerPath.fromPathFile("Leave");
        return Commands.sequence(
            arm.goTo(ArmState.SCORE),
            Commands.parallel(
                AutoBuilder.followPath(leave),
                arm.goTo(ArmState.STOW)))
            .withName("LeaveAuto");
    } catch (Exception e) {
        DriverStation.reportError("Failed to load path Leave: " + e.getMessage(), e.getStackTrace());
        return Commands.none();
    }
}

// RobotContainer 建構子裡，buildAutoChooser 之後
autoChooser.addOption("Leave（程式）", buildLeaveAuto());

講幾個重點：sequence 等手臂到位才出發；parallel 讓走路徑跟收手臂一起進行，兩個都結束才算完成（第 10 章）；手臂和底盤是不同的 Subsystem，不會互相打斷。載入失敗時回傳 Commands.none() 並回報錯誤，總比整支程式掛掉好。這個 Auto 在建構子裡就建好，符合「開機時載入」的建議。

還有，這條路徑沒有經過 PathPlannerAuto，所以不會自動重設起始位置；真的要用的話，要確定出發前里程計已經設對了。
