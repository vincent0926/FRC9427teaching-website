CAN ID 06｜架構

IO 架構：導師只看點名表

這章是整個課程最長的一章，也是隊上程式最核心的部分。我們拿一支手臂（Arm）從頭走到尾：每一層管什麼、資料怎麼流、硬體跟模擬怎麼互換，最後升級成 AdvantageKit 的寫法。內容切成六塊，不用一口氣讀完，A 先讀，其他看需要。

版本說明這章是照 WPILib 2026.2.2、Phoenix 6 26.3.0、AdvantageKit 2026 的文件寫的。有個坑先講：WPILib 和 CTRE 網站上標 latest 的文件已經是 2027 年版了（WPILib 的 Java 套件名稱也改了），查資料記得切到 stable。程式裡要實測的數字我都標了 TODO，拜託不要照抄。

A-1　先講個比喻：導師、班長和點名表

每節課開始前，導師會決定全班要去哪：回教室、去操場，還是到禮堂。導師只要說一句「去禮堂」，這就是班級的目標。

至於怎麼走、走多快、轉彎要不要放慢，是班長在現場自己處理的，導師不會跟在旁邊每一步都下指令。班長手上有一本「帶隊守則」，寫著最快能走多快、起步跟停下要多平順。這本守則開學就交給班長了，不會每節課重發一次。

導師只看點名表。每節課一開始，班長點一次名，把點名表交給導師：誰在、大家現在在哪、有沒有人不舒服。導師就看這張表判斷「到禮堂了沒」。這一節課裡導師都用這一張，不會每五分鐘跑去重問一次。

主任想讓這個班去禮堂，會去跟導師講，不會自己跑去叫班長。這樣導師永遠知道自己的班在幹嘛。

颱風停課的時候改成線上上課，點名變成系統自動記錄，但交出來的點名表格式一模一樣，導師的判斷方式一個字都不用改。

學期末要檢討某一天發生什麼事，導師就把那天的點名簿翻出來，照紀錄把當天的判斷重想一遍。這時候不需要任何人再點一次名。

最後一個細節：主任在這節課上到一半交代「下一節去禮堂」，導師會等到下一節開始才把新目標告訴班長。

比喻程式
導師ArmSubsystem：保存目標、做判斷
「去教室／操場／禮堂」ArmState：STOW、INTAKE、SCORE
班長這個職位的工作說明ArmIO 介面
實體課的班長ArmIOHardware：兩顆 TalonFX
班長自己控制怎麼走TalonFX 內建的 MotionMagic 閉迴路
開學時交給班長的帶隊守則建構時套用一次的 TalonFXConfiguration
點名表輸入物件 ArmIOInputs
主任透過導師找班級Command 只呼叫 Subsystem 的方法
線上系統點名ArmIOSim
翻點名簿AdvantageKit 重播，IO 是空實作
下一節才開始走新目標在下一個 20 ms 週期才送到硬體
這個比喻哪裡不準故事裡是班長「交一張點名表」給導師，但 AdvantageKit 的寫法方向剛好反過來：Subsystem 先拿一張空白表格交給 IO 層去填，也就是 updateInputs(inputs)。表格從頭到尾都是 Subsystem 手上的同一張，每個週期重填一次[1]。

A-3　各層職責

AdvantageKit 的想法是把傳統的 Subsystem 拆成三塊：對外的公開方法、控制邏輯、操作硬體的程式碼。輸入資料要在「控制邏輯」和「硬體」之間記錄下來，所以碰硬體的部分要搬到獨立的 IO 物件裡[1]。套到手臂上就是這樣：

層應該做不該做
Robot在 robotPeriodic() 呼叫 CommandScheduler.getInstance().run()；AdvantageKit 版在建構子先設定 Logger放機構邏輯、碰馬達
RobotContainer依模式選擇 IO 實作並傳給 Subsystem；綁定按鍵呼叫 IO 方法、保存機構狀態
ArmSubsystem持有 IO 與輸入物件；保存目前目標；在 periodic() 讀輸入、送目標；提供 atGoal() 和 Command factoryimport CTRE 的類別、直接操作 TalonFX、在 periodic 反覆套用設定
ArmIO定義硬體能做的事，每個方法都有 default 空實作決定目標角度這類邏輯
ArmIOInputs純資料，單位固定方法、硬體物件
ArmIOHardware建立 TalonFX、套用一次設定、設定 Follower、刷新訊號、換算單位、送出控制請求決定目標、寫等待迴圈
ArmIOSim用物理模型產生讀值，填進同一種輸入物件使用和實機不同的單位
ArmState列出目標，每個帶目標角度放感測器讀值
Command只呼叫 Subsystem 的公開方法，宣告 requirements拿到 ArmIO 或 TalonFX

閉迴路要放在哪裡

IO 的輸出可以是電壓、設定點，也可以是 PID 常數，每種用一個簡單的方法表示就好[1]。AdvantageKit 官方的 TalonFX swerve 範本是把回授放在馬達控制器裡跑，齒輪比也交給 TalonFX 韌體處理，不在 roboRIO 上算[4]。我們的手臂偏好用 MotionMagic，它本來就是在 TalonFX 裡面產生軌跡、跑閉迴路，所以這章的 ArmIO 主要輸出是 setPositionGoal(弧度)，setVoltage 只留給 SysId 和手動測試。

當然也可以反過來，在 roboRIO 上用 ProfiledPIDController 加 ArmFeedforward 算電壓，再呼叫 setVoltage。好處是連控制邏輯都能被 AdvantageKit 重播；壞處是少了控制器內部那個高頻迴路，增益也要另外調。兩種都有人用，這是取捨，官方沒有說哪個才對。

單位在哪裡換算

AdvantageKit 記錄的值用弧度，Phoenix 卻要用轉數（rotations）[4]，所以一定要決定在哪裡換。這章的規矩是：IO 介面和輸入物件一律用手臂端的弧度，跟 WPILib 模擬器一樣；轉數只會出現在 ArmIOHardware 裡面。這是範本和社群的習慣，不是 Phoenix 規定的，但整個專案統一一種就不會亂。

A-4　每 20 ms 的資料流

排程器每一輪的順序是：先跑每個已註冊 Subsystem 的 periodic()，再輪詢按鈕，最後照排程順序跑指令的 execute()、檢查 isFinished()[18]。放到手臂上：

順序發生什麼事
1robotPeriodic() 呼叫 CommandScheduler.run()
2ArmSubsystem.periodic()：io.updateInputs(inputs) →（AdvantageKit 版）Logger.processInputs → 用目前保存的目標呼叫 io.setPositionGoal()
3輪詢按鈕：按下的按鍵排程指令，並呼叫它的 initialize()，例如 setGoal(SCORE)
4執行指令的 execute()、檢查 isFinished()
5下一輪回到第 2 步，新目標這時才送到 TalonFX

所以指令設的新目標，最多大概晚 20 ms 才送出去。對手臂來說這點延遲可以忽略，換來的好處是「所有 IO 呼叫都集中在 periodic、每輪只讀一次輸入」，AdvantageKit 重播要能對得上，靠的就是這個[1]。

哪些是推論「按鍵排程的指令，同一輪就會跑 execute」是我從 WPILib 原始碼的順序推出來的，官方文件沒有明講，不要把它當成保證。

B-1　ArmState：目標

package frc.robot.subsystems.arm;

import edu.wpi.first.math.util.Units;

/** 目標狀態，不是感測器讀值。角度是手臂端的弧度，0 = 手臂水平向前。 */
public enum ArmState {
    STOW(Units.degreesToRadians(0.0)),   // TODO: 實測
    INTAKE(Units.degreesToRadians(0.0)), // TODO: 實測
    SCORE(Units.degreesToRadians(0.0));  // TODO: 實測

    public final double angleRad;

    ArmState(double angleRad) {
        this.angleRad = angleRad;
    }
}

0 度一定要是手臂水平，因為 Phoenix 的 Arm_Cosine 重力補償是拿位置的餘弦去乘 kG（C 部分會細講）[10]。零點定錯，補償就整個算錯。

B-2　ArmIO：簡易版

package frc.robot.subsystems.arm;

public interface ArmIO {
    /** 點名表：純資料。單位：手臂端弧度、rad/s、伏特、安培、攝氏。 */
    class ArmIOInputs {
        public boolean leaderConnected = false;
        public boolean followerConnected = false;
        public double positionRad = 0.0;
        public double velocityRadPerSec = 0.0;
        public double appliedVolts = 0.0;
        public double[] supplyCurrentAmps = new double[] {0.0, 0.0}; // [leader, follower]
        public double[] statorCurrentAmps = new double[] {0.0, 0.0};
        public double[] tempCelsius = new double[] {0.0, 0.0};
    }

    default void updateInputs(ArmIOInputs inputs) {}

    /** 交給控制器內部 MotionMagic 追蹤的目標（手臂端弧度）。 */
    default void setPositionGoal(double positionRad) {}

    /** 開迴路電壓：只給 SysId 和手動測試用。 */
    default void setVoltage(double volts) {}

    default void stop() {}

    default void setBrakeMode(boolean enabled) {}

    /** 把兩顆馬達的編碼器重設為指定角度。 */
    default void resetPosition(double positionRad) {}
}

每個方法都寫成 default 空實作。這些空實作在模擬時會用到，重播的時候也可以直接 new ArmIO() {} 做出一個什麼都不做的實作[1]。簡易版還用不到重播，但先寫成這樣，之後升級就不用改。

B-3　ArmSubsystem：導師

package frc.robot.subsystems.arm;

import edu.wpi.first.wpilibj.DriverStation;
import edu.wpi.first.wpilibj2.command.Command;
import edu.wpi.first.wpilibj2.command.SubsystemBase;

public class ArmSubsystem extends SubsystemBase {
    private static final double TOLERANCE_RAD = 0.03; // TODO: 實測

    private enum ControlMode { POSITION, VOLTAGE }

    private final ArmIO io;
    private final ArmIO.ArmIOInputs inputs = new ArmIO.ArmIOInputs();

    private ArmState goal = ArmState.STOW;
    private ControlMode mode = ControlMode.POSITION;
    private double manualVolts = 0.0;

    public ArmSubsystem(ArmIO io) {
        this.io = io;
    }

    @Override
    public void periodic() {
        io.updateInputs(inputs); // 1. 點名：本輪唯一一次讀硬體

        if (DriverStation.isDisabled()) {
            io.stop();
            return;
        }

        switch (mode) { // 2. 依模式送出本輪的輸出
            case POSITION -> io.setPositionGoal(goal.angleRad);
            case VOLTAGE -> io.setVoltage(manualVolts);
        }
    }

    // ---- 公開方法：Command 只能用這些 ----
    public void setGoal(ArmState newGoal) {
        goal = newGoal;
        mode = ControlMode.POSITION;
    }

    public ArmState getGoal() {
        return goal;
    }

    public double getPositionRad() {
        return inputs.positionRad; // 讀點名表，不直接問硬體
    }

    public boolean atGoal() {
        return Math.abs(inputs.positionRad - goal.angleRad) < TOLERANCE_RAD;
    }

    // ---- Command factory ----
    /** 設定目標，等到抵達才結束。適合放在 sequence 裡。 */
    public Command goTo(ArmState target) {
        return run(() -> setGoal(target)).until(this::atGoal).withName("Arm.goTo(" + target + ")");
    }

    /** 設定目標後立刻結束。目標保存在 Subsystem 裡，手臂會持續保持。 */
    public Command setGoalCommand(ArmState target) {
        return runOnce(() -> setGoal(target));
    }

    /** 手動測試：按住時給固定電壓，放開歸零。 */
    public Command manualVoltage(double volts) {
        return startEnd(
            () -> { mode = ControlMode.VOLTAGE; manualVolts = volts; },
            () -> manualVolts = 0.0);
    }
}

講幾個重點。run、runOnce、startEnd 是 WPILib Subsystem 提供的 factory，用它們做出來的指令會自動 require 這個 Subsystem[19]。ControlMode 是為了讓 IO 只在 periodic 裡被呼叫：如果 manualVoltage 直接去呼叫 io.setVoltage，下一輪 periodic 的 setPositionGoal 馬上就把它蓋掉了。

教練提醒：重新 Enable 的瞬間手臂會動這個寫法在 Disabled 時會停止輸出，但目標還留著。所以重新 Enable 的那一刻，手臂會直接往那個目標衝過去。要改成 Disabled 時把目標設回 STOW 也可以，看隊上需求，但不管怎麼寫，Enable 前都要喊。

B-4　兩種 Command 寫法

factory 的寫法上面已經有了，這裡是獨立類別的寫法：

package frc.robot.commands;

import edu.wpi.first.wpilibj2.command.Command;
import frc.robot.subsystems.arm.ArmState;
import frc.robot.subsystems.arm.ArmSubsystem;

public class MoveArmToState extends Command {
    private final ArmSubsystem arm;
    private final ArmState target;

    public MoveArmToState(ArmSubsystem arm, ArmState target) {
        this.arm = arm;
        this.target = target;
        addRequirements(arm);
    }

    @Override
    public void initialize() {
        arm.setGoal(target);
    }

    @Override
    public boolean isFinished() {
        return arm.atGoal();
    }
}

兩種寫法做的事一樣：都只呼叫 ArmSubsystem 的公開方法、都 require arm，而且都不知道 ArmIO 的存在，就像主任只會透過導師找班級。那要選哪個？WPILib 的建議是：只用到一個 Subsystem 的指令，寫成那個 Subsystem 的 factory 比較省事；跨好幾個 Subsystem 的指令，塞進哪一個都怪，就放到外面的類別[20]。

B-5　RobotContainer：決定誰來點名

import edu.wpi.first.wpilibj.RobotBase;
import edu.wpi.first.wpilibj2.command.button.CommandXboxController;

public class RobotContainer {
    private final ArmSubsystem arm;
    private final CommandXboxController controller = new CommandXboxController(0);

    public RobotContainer() {
        arm = new ArmSubsystem(RobotBase.isReal() ? new ArmIOHardware() : new ArmIOSim());

        controller.a().onTrue(arm.goTo(ArmState.INTAKE));               // factory 寫法
        controller.b().onTrue(new MoveArmToState(arm, ArmState.SCORE)); // 類別寫法
        controller.x().onTrue(arm.setGoalCommand(ArmState.STOW));
    }
}

整個專案裡，只有這一行知道現在用的是哪一個 IO 實作。其他地方都不知道，也不需要知道。

C-1　ArmIOHardware 全文

先把整份看完，下面再一項一項講為什麼這樣寫。

package frc.robot.subsystems.arm;

import com.ctre.phoenix6.BaseStatusSignal;
import com.ctre.phoenix6.CANBus;
import com.ctre.phoenix6.StatusCode;
import com.ctre.phoenix6.StatusSignal;
import com.ctre.phoenix6.configs.TalonFXConfiguration;
import com.ctre.phoenix6.controls.Follower;
import com.ctre.phoenix6.controls.MotionMagicVoltage;
import com.ctre.phoenix6.controls.NeutralOut;
import com.ctre.phoenix6.controls.VoltageOut;
import com.ctre.phoenix6.hardware.ParentDevice;
import com.ctre.phoenix6.hardware.TalonFX;
import com.ctre.phoenix6.signals.GravityTypeValue;
import com.ctre.phoenix6.signals.InvertedValue;
import com.ctre.phoenix6.signals.MotorAlignmentValue;
import com.ctre.phoenix6.signals.NeutralModeValue;
import edu.wpi.first.math.util.Units;
import edu.wpi.first.units.measure.Angle;
import edu.wpi.first.units.measure.AngularVelocity;
import edu.wpi.first.units.measure.Current;
import edu.wpi.first.units.measure.Temperature;
import edu.wpi.first.units.measure.Voltage;
import java.util.function.Supplier;

public class ArmIOHardware implements ArmIO {
    protected static final CANBus CAN_BUS = new CANBus("9427");
    protected static final int LEADER_ID = 0;      // TODO: 依接線
    protected static final int FOLLOWER_ID = 0;    // TODO: 依接線
    protected static final double GEAR_RATIO = 1.0; // TODO: 馬達轉數 / 手臂轉數

    protected final TalonFX leader = new TalonFX(LEADER_ID, CAN_BUS);
    protected final TalonFX follower = new TalonFX(FOLLOWER_ID, CAN_BUS);

    // 控制請求：建立一次，重複使用
    // EnableFOC 預設為 true；沒有 Pro 授權時會自動退回一般換相（第 11 章）
    private final MotionMagicVoltage mmRequest = new MotionMagicVoltage(0.0).withSlot(0);
    private final VoltageOut voltageRequest = new VoltageOut(0.0);
    private final NeutralOut neutralRequest = new NeutralOut();

    private final TalonFXConfiguration config = new TalonFXConfiguration();

    private final StatusSignal<Angle> position = leader.getPosition();
    private final StatusSignal<AngularVelocity> velocity = leader.getVelocity();
    private final StatusSignal<Voltage> appliedVolts = leader.getMotorVoltage();
    private final StatusSignal<Current> leaderSupply = leader.getSupplyCurrent();
    private final StatusSignal<Current> leaderStator = leader.getStatorCurrent();
    private final StatusSignal<Temperature> leaderTemp = leader.getDeviceTemp();
    private final StatusSignal<Current> followerSupply = follower.getSupplyCurrent();
    private final StatusSignal<Current> followerStator = follower.getStatorCurrent();
    private final StatusSignal<Temperature> followerTemp = follower.getDeviceTemp();

    public ArmIOHardware() {
        // ---- 共用設定（隊上慣例：同一份套用到兩顆）----
        config.MotorOutput.NeutralMode = NeutralModeValue.Brake;
        config.MotorOutput.Inverted = InvertedValue.CounterClockwise_Positive; // TODO: 依機構確認

        config.Feedback.SensorToMechanismRatio = GEAR_RATIO; // 只放齒輪比

        config.Slot0.kP = 0.0; // [TUNED] TODO
        config.Slot0.kI = 0.0; // [TUNED] TODO
        config.Slot0.kD = 0.0; // [TUNED] TODO
        config.Slot0.kS = 0.0; // [MEASURED／SYSID] TODO
        config.Slot0.kV = 0.0; // [MODEL→SYSID] TODO
        config.Slot0.kA = 0.0; // [MODEL→SYSID] TODO
        config.Slot0.kG = 0.0; // [MODEL→SYSID] TODO
        config.Slot0.GravityType = GravityTypeValue.Arm_Cosine;

        // 單位：手臂端 rot/s、rot/s²、rot/s³（因為設定了 SensorToMechanismRatio）
        config.MotionMagic.MotionMagicCruiseVelocity = 0.0; // [CONSTRAINT] TODO
        config.MotionMagic.MotionMagicAcceleration = 0.0;   // [CONSTRAINT] TODO
        config.MotionMagic.MotionMagicJerk = 0.0;           // [CONSTRAINT] TODO: 非 0 才是 S-curve

        config.SoftwareLimitSwitch.ForwardSoftLimitEnable = true;
        config.SoftwareLimitSwitch.ForwardSoftLimitThreshold = 0.0; // [MEASURED] TODO: 手臂端 rotations
        config.SoftwareLimitSwitch.ReverseSoftLimitEnable = true;
        config.SoftwareLimitSwitch.ReverseSoftLimitThreshold = 0.0; // [MEASURED] TODO: 手臂端 rotations

        config.CurrentLimits.StatorCurrentLimit = 0.0; // [CONSTRAINT] TODO
        config.CurrentLimits.StatorCurrentLimitEnable = true;
        config.CurrentLimits.SupplyCurrentLimit = 0.0; // [CONSTRAINT] TODO
        config.CurrentLimits.SupplyCurrentLimitEnable = true;

        retry(() -> leader.getConfigurator().apply(config, 0.25));
        retry(() -> follower.getConfigurator().apply(config, 0.25));

        // Follower：2026 API
        follower.setControl(new Follower(leader.getDeviceID(), MotorAlignmentValue.Aligned)); // TODO: Aligned 或 Opposed

        // 兩顆都歸零（隊上慣例）
        resetPosition(ArmState.STOW.angleRad);

        // Follower 需要 leader 的輸出訊號，要在 optimize 之前明確設定（至少 20 Hz）
        BaseStatusSignal.setUpdateFrequencyForAll(
            50.0, position, velocity, appliedVolts, leader.getDutyCycle(),
            leaderSupply, leaderStator, leaderTemp, followerSupply, followerStator, followerTemp);
        ParentDevice.optimizeBusUtilizationForAll(leader, follower);
    }

    @Override
    public void updateInputs(ArmIOInputs inputs) {
        StatusCode leaderStatus = BaseStatusSignal.refreshAll(
            position, velocity, appliedVolts, leaderSupply, leaderStator, leaderTemp);
        StatusCode followerStatus = BaseStatusSignal.refreshAll(
            followerSupply, followerStator, followerTemp);

        inputs.leaderConnected = leaderStatus.isOK();
        inputs.followerConnected = followerStatus.isOK();
        inputs.positionRad = Units.rotationsToRadians(position.getValueAsDouble());
        inputs.velocityRadPerSec = Units.rotationsToRadians(velocity.getValueAsDouble());
        inputs.appliedVolts = appliedVolts.getValueAsDouble();
        inputs.supplyCurrentAmps = new double[] {leaderSupply.getValueAsDouble(), followerSupply.getValueAsDouble()};
        inputs.statorCurrentAmps = new double[] {leaderStator.getValueAsDouble(), followerStator.getValueAsDouble()};
        inputs.tempCelsius = new double[] {leaderTemp.getValueAsDouble(), followerTemp.getValueAsDouble()};
    }

    @Override
    public void setPositionGoal(double positionRad) {
        leader.setControl(mmRequest.withPosition(Units.radiansToRotations(positionRad)));
    }

    @Override
    public void setVoltage(double volts) {
        leader.setControl(voltageRequest.withOutput(volts));
    }

    @Override
    public void stop() {
        leader.setControl(neutralRequest);
    }

    @Override
    public void setBrakeMode(boolean enabled) {
        config.MotorOutput.NeutralMode = enabled ? NeutralModeValue.Brake : NeutralModeValue.Coast;
        retry(() -> leader.getConfigurator().apply(config.MotorOutput, 0.25));
        retry(() -> follower.getConfigurator().apply(config.MotorOutput, 0.25));
    }

    @Override
    public void resetPosition(double positionRad) {
        double rot = Units.radiansToRotations(positionRad);
        retry(() -> leader.setPosition(rot, 0.25));
        retry(() -> follower.setPosition(rot, 0.25));
    }

    /** 失敗時重試一次，總共最多兩次。 */
    protected static void retry(Supplier<StatusCode> action) {
        if (!action.get().isOK()) {
            action.get();
        }
    }
}

C-2　逐項說明

CANivore：用 CANBus 物件

Phoenix 6 2026 年把「用字串指定 CAN bus」的建構子標成 deprecated 了，預計 2027 年移除，要改用傳 CANBus 物件的版本[8]。所以我們的 CANivore「9427」寫成 new CANBus("9427")，而且集中宣告在一個地方，不要到處 new。

Follower：2026 年改用 MotorAlignmentValue

Phoenix 6 26.3.0 的 Follower 只剩一個建構子：Follower(int LeaderID, MotorAlignmentValue MotorAlignment)。Aligned 是方向跟 leader 設定的 Invert 一樣，Opposed 是相反[9]。重點來了：follower 的方向是相對於 leader 的 Invert 來決定的，跟 follower 自己的 Inverted 無關。以前那個 boolean 參數已經被換掉了[8]，看到舊範例別照抄。

另外，leader 對應輸出類型的狀態訊號（DutyCycle、MotorVoltage 這些）一定要開著，它的更新頻率就是 follower 輸出的更新速度，不能低於 20 Hz[9]。所以程式在 optimizeBusUtilizationForAll 之前，先把 leader 的 getMotorVoltage() 和 getDutyCycle() 設成 50 Hz。

設定要不要也套到 follower 上？Follower 在跟隨的時候不會用自己的 PID 增益。不過 CTRE 員工在 Chief Delphi 回覆過（社群來源，2026-02-25），至少 neutral mode 和電流限制還是要套。我們「同一份設定兩顆都套、兩顆都重設編碼器」的做法剛好符合，兩顆的位置讀數也會一致。

重力補償：kG 與 Arm_Cosine

重力補償會隨角度變的機構（像手臂），GravityType 要選 Arm_Cosine。預設值是 Elevator_Static，忘了改就是錯的[10]。kG 是讓手臂水平向前停住所需要的輸出，這也是 0 度一定要是水平的原因。重心有偏的話，可以用 GravityArmPositionOffset 修正[10]。

MotionMagic 與 S-curve

MotionMagic 會產生梯形或 S-curve 的速度曲線，jerk 設成非 0，曲線就從梯形變成連續的 S-curve[11]。MotionMagicVoltage 的目標位置單位是 rotations，隨時都可以改[11]。控制請求物件 new 一次就好，之後用 withPosition 重複用[15]。順便一提，DynamicMotionMagicVoltage 要 Phoenix Pro 加 CANivore，這章不會用到。

SensorToMechanismRatio 只放齒輪比

這個設定是「感測器轉數對機構輸出的比例」，大於 1 就是減速。CTRE 明講不建議拿它來做別的單位換算，單位換算應該在程式裡用單位函式庫做[12]。所以這裡只放齒輪比，轉數換弧度在 Java 這邊做。

訊號刷新：refreshAll

多個訊號用 BaseStatusSignal.refreshAll(...) 一次刷新，不要一個一個 refresh。timeout 設 0 的 waitForAll() 跟 refreshAll() 其實一樣，而 CANivore 的時間同步要 Pro 授權[13]。我們沒有 Pro，就用不會卡住的 refreshAll，免得拖慢主迴圈。

設定只在建構時套用

套用設定會卡住等回應（範例的 timeout 是 0.25 秒），所以只能在建構子裡做。setBrakeMode 這種執行中切換的方法，也只在狀態改變時呼叫一次，千萬不要放進 periodic。至於要重試幾次：CTRE 員工在同一則回覆說重試一次（總共兩次）沒問題，第二次還失敗的話，再多試通常也沒用（社群來源），所以 retry 只重試一次。

package frc.robot.subsystems.arm;

import com.ctre.phoenix6.sim.ChassisReference;
import com.ctre.phoenix6.sim.TalonFXSimState;
import edu.wpi.first.math.system.plant.DCMotor;
import edu.wpi.first.math.util.Units;
import edu.wpi.first.wpilibj.RobotController;
import edu.wpi.first.wpilibj.simulation.SingleJointedArmSim;

/** 沿用 ArmIOHardware 的設定與控制請求，只多了「物理模型 → SimState」這一步。 */
public class ArmIOSim extends ArmIOHardware {
    private static final double ARM_LENGTH_M = 0.5; // TODO
    private static final double ARM_MASS_KG = 3.0;  // TODO
    private static final double MIN_ANGLE_RAD = Units.degreesToRadians(-30.0); // TODO
    private static final double MAX_ANGLE_RAD = Units.degreesToRadians(120.0); // TODO

    private final SingleJointedArmSim armSim = new SingleJointedArmSim(
        DCMotor.getKrakenX60(2),      // 兩顆 Kraken X60 一起驅動
        GEAR_RATIO,
        SingleJointedArmSim.estimateMOI(ARM_LENGTH_M, ARM_MASS_KG),
        ARM_LENGTH_M,
        MIN_ANGLE_RAD,
        MAX_ANGLE_RAD,
        true,                         // 模擬重力
        ArmState.STOW.angleRad);      // 起始角度：和 resetPosition 一致

    public ArmIOSim() {
        super();
        leader.getSimState().Orientation = ChassisReference.CounterClockwise_Positive; // TODO: 對應 Inverted
    }

    @Override
    public void updateInputs(ArmIOInputs inputs) {
        TalonFXSimState sim = leader.getSimState();
        sim.setSupplyVoltage(RobotController.getBatteryVoltage());

        armSim.setInputVoltage(sim.getMotorVoltage());
        armSim.update(0.02);

        // 物理模型是手臂端；SimState 要的是轉子端（乘以齒輪比）
        double mechRot = Units.radiansToRotations(armSim.getAngleRads() - ArmState.STOW.angleRad);
        sim.setRawRotorPosition(mechRot * GEAR_RATIO);
        sim.setRotorVelocity(Units.radiansToRotations(armSim.getVelocityRadPerSec()) * GEAR_RATIO);

        super.updateInputs(inputs); // 用同一組 StatusSignal 讀回
    }
}

依據與注意事項

模擬裡的 PID 和電流限制要正常運作，一定要設 RawRotorPosition 和 RotorVelocity，而且給的是齒輪比之前的轉子數值。CTRE 範例的流程就是：設供電電壓 → 讀馬達電壓 → 更新物理模型 → 寫回轉子位置和速度[14]。

有一個限制要特別注意：模擬目前不支援多條 CAN bus，所有裝置都會跑到同一條 bus 上，所以 CAN ID 在所有 bus 之間都不能重複[14]。如果 CANivore 和 roboRIO bus 上剛好有同 ID 的裝置，模擬時就會打架。

SingleJointedArmSim 在 WPILib 2026.2.2 的建構子參數順序是：馬達模型、齒輪比、轉動慣量、手臂長度、最小角度、最大角度、要不要模擬重力、起始角度[16]。它會照手臂角度去算重力[17]。CTRE 範例用的是 getKrakenX60Foc，我們沒有 Pro、不用 FOC，所以用 getKrakenX60。

SimState 更新得越頻繁，模擬的 PID 就越接近實機，CTRE 的建議是用 WPILib 的 Notifier 另外開一個比較快的迴圈[14]。這章為了簡單，就每 20 ms 更新一次。

這個模擬沒有模擬到的Follower 的 SimState 沒有更新，所以模擬裡 follower 的電流和溫度都是 0。不影響手臂位置就是了，因為位置只從 leader 讀。

D-3　做法 (a)：roboRIO 控制器

// ArmIOSimRio implements ArmIO（重點片段）
private final ProfiledPIDController pid = new ProfiledPIDController(
    0.0, 0.0, 0.0,                                   // [TUNED] TODO: kP、kI、kD
    new TrapezoidProfile.Constraints(0.0, 0.0));     // [CONSTRAINT] TODO: rad/s、rad/s²
private final ArmFeedforward ff = new ArmFeedforward(0.0, 0.0, 0.0); // [MODEL→SYSID] TODO: kS、kG、kV（弧度單位）
private Double goalRad = null;

@Override
public void setPositionGoal(double positionRad) {
    goalRad = positionRad;
}

@Override
public void updateInputs(ArmIOInputs inputs) {
    double volts = 0.0;
    if (goalRad != null) {
        volts = pid.calculate(armSim.getAngleRads(), goalRad)
              + ff.calculate(pid.getSetpoint().position, pid.getSetpoint().velocity);
    }
    armSim.setInputVoltage(MathUtil.clamp(volts, -12.0, 12.0));
    armSim.update(0.02);
    inputs.positionRad = armSim.getAngleRads();
    inputs.velocityRadPerSec = armSim.getVelocityRadPerSec();
    inputs.appliedVolts = volts;
    inputs.leaderConnected = true;
    inputs.followerConnected = true;
}
ArmFeedforward 有幾個方法被棄用了WPILib 2026.2.2 裡，ArmFeedforward 帶加速度的三參數 calculate，和帶 dt 的四參數版本，都從 2025 年起標成棄用、之後會移除，要改用 calculateWithVelocities[22]。上面用的兩參數 calculate(位置, 速度) 沒被棄用，可以放心。

小測驗

練習：為 Intake 滾輪寫 IO

照這章的結構，幫 Intake 滾輪寫三樣東西：IntakeState（NONE、INTAKING、SCORING，每個帶一個電壓）、RollerIO（輸入物件至少要有 velocityRps、appliedVolts、supplyCurrentAmps，輸出方法是 setVoltage），還有 IntakeSubsystem 的 periodic()。滾輪用開迴路電壓控制就好。

拆成三塊寫：狀態（enum）、IO 介面（輸入物件＋輸出方法）、Subsystem 的 periodic。滾輪是開迴路，所以輸出就是電壓。

IntakeState 的每個值帶一個 volts；RollerIO 裡放一個 RollerIOInputs 類別，方法都寫成 default 空實作。

periodic 的順序：io.updateInputs(inputs)；Disabled 時 io.setVoltage(0.0) 並 return；否則 io.setVoltage(state.volts)。

// IntakeState.java
public enum IntakeState {
    NONE(0.0),
    INTAKING(0.0), // TODO: 實測
    SCORING(0.0);  // TODO: 實測

    public final double volts;

    IntakeState(double volts) {
        this.volts = volts;
    }
}

// RollerIO.java
public interface RollerIO {
    class RollerIOInputs {
        public boolean connected = false;
        public double velocityRps = 0.0;
        public double appliedVolts = 0.0;
        public double supplyCurrentAmps = 0.0;
    }

    default void updateInputs(RollerIOInputs inputs) {}

    default void setVoltage(double volts) {}
}

// IntakeSubsystem.java 的 periodic()
@Override
public void periodic() {
    io.updateInputs(inputs);
    if (DriverStation.isDisabled()) {
        io.setVoltage(0.0);
        return;
    }
    io.setVoltage(state.volts);
}

滾輪不需要閉迴路，IO 的輸出就是 setVoltage。拿來跟手臂比：手臂的閉迴路在 TalonFX 裡面跑，所以輸出是 setPositionGoal；滾輪是開迴路，輸出直接就是電壓。IO 介面長怎樣，看的是控制在哪裡跑。
