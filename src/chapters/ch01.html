類別與物件：從一張學籍資料表開始

讀完這章，你會知道類別和物件的差別，看懂 new TalonFX(21) 做了什麼，也能自己寫出一個有欄位、建構子和方法的類別。

生活比喻：開學報到

教務處先設計表格。開學前，教務處要決定學籍資料表長什麼樣子：要有姓名、座號、班級這幾格，還要附一份說明，寫清楚學生可以做哪些事，例如交作業、自我介紹、請假。這份「規格」只有一份，放在教務處。它本身不是任何一個學生，它只規定「學生」這種東西該有什麼。

報到時，每人拿一張新表。開學那天，小明走進註冊組，組長照著規格拿出一張全新的表格，當場請他填上姓名和座號。組長不會收一張空白的表，因為規定就是報到時一定要填這兩格。填好的那一張，才是「小明」。

每張表各管各的。三十個同學就有三十張表。小明交了作業，他那張表上的「作業次數」加一，小華那張不會跟著變。大家的表格長得一樣，但內容各自獨立。

表格上寫著「本人」。表格有一格叫「本人姓名」。小明填的時候，「本人」指的是小明；小華填的時候，「本人」指的是小華。同樣兩個字，指的永遠是填這張表的那個人。

校名印在表頭。每張表最上面都印著校名，這不是每個學生自己填的，而是全校共用的一個值。哪天學校改名，只要改一次，所有表格都跟著變。

點名冊上的空座號。點名冊上列到 30 號，但 30 號其實沒人報到。老師如果叫「30 號起來回答問題」，沒有人站起來，這堂課就卡住了。

同一個座號發給兩個人。如果註冊組出錯，把 7 號同時發給兩個人，點名時兩個人都會說「有」，老師叫 7 號做事，兩個人同時跑上台。

Oracle 官方教學把物件描述為「相關的狀態與行為」包在一起的軟體單位，把類別描述為建立物件的藍圖[1]。上面故事裡，表格上的格子就是狀態，說明書上寫的「可以做的事」就是行為。

這個比喻哪裡不準紙本表格只能存資料，但物件除了存資料還「會做事」。另外，做事的方式（方法）是寫在類別裡、所有物件共用的一份，並不是每張表格各抄一份說明書；每個物件各自一份的只有欄位的值。

換成機器人：一個模擬的滾輪

先不碰真正的硬體，用純 Java 寫一個滾輪類別。對照上面的故事讀：

public class Roller {
    // 表頭的校名：全部 Roller 共用一份
    public static final double MAX_VOLTS = 12.0;

    // 表格上的格子：每個 Roller 各自一份
    private final String name;
    private double voltage = 0.0;

    // 報到規定：建立 Roller 時一定要給名字
    public Roller(String name) {
        this.name = name;
    }

    // 說明書上寫的「可以做的事」
    public void run(double volts) {
        voltage = Math.max(-MAX_VOLTS, Math.min(MAX_VOLTS, volts));
    }

    public void stop() {
        voltage = 0.0;
    }

    public double getVoltage() {
        return voltage;
    }

    public String getName() {
        return name;
    }
}

用這個類別建立兩個物件：

Roller intake = new Roller("Intake");
Roller feeder = new Roller("Feeder");

intake.run(8.0);
System.out.println(intake.getVoltage()); // 8.0
System.out.println(feeder.getVoltage()); // 0.0

欄位

name 和 voltage 是欄位，每個物件各有一份，所以 intake.run(8.0) 不會改到 feeder。final 表示設定後不能再改，名字給了就固定。前面的 private 是第 2 章的主題，現在先記得它代表「只有這個類別自己能直接碰」。

建構子與 new

建構子的名字和類別相同，而且沒有回傳型別。new Roller("Intake") 會先配置一個新物件，再執行建構子設定欄位[2]。因為唯一的建構子要求傳入名字，所以程式裡不可能出現沒有名字的 Roller，這就是「報到時一定要填」。

this

建構子的參數叫 name，欄位也叫 name。在建構子裡直接寫 name，Java 會當成參數；要指欄位就寫 this.name，意思是「這個物件自己的 name」[3]。

static

MAX_VOLTS 加了 static，它屬於類別本身，所有物件共用同一份[4]。再加上 final 就是常數，慣例是全部大寫、單字用底線隔開。

動手試：兩個物件，各自的狀態

下面兩個物件都是從 Roller 建立的。按按鈕呼叫方法，看欄位怎麼變。最後一個按鈕示範對「空座號」點名。

注意 intake.run(20.0)：你要 20V，物件只給 12V。限制寫在方法裡，呼叫的人繞不過去。

對照真正的 FRC 程式

import com.ctre.phoenix6.controls.VoltageOut;
import com.ctre.phoenix6.hardware.TalonFX;

public class RollerIOHardware {
    private static final int LEADER_ID = 21; // TODO: 依實際接線確認

    private final TalonFX leader = new TalonFX(LEADER_ID);
    private final VoltageOut voltageRequest = new VoltageOut(0);

    public void setVoltage(double volts) {
        leader.setControl(voltageRequest.withOutput(volts));
    }
}

leader 是欄位，裝著一個 TalonFX 物件；voltageRequest 也是物件，代表「用電壓控制」這個請求；setVoltage() 是方法。withOutput(volts) 修改請求物件裡的輸出值後，回傳同一個物件，所以能直接交給 setControl()。CTRE 官方文件的範例就是把控制請求宣告成欄位，再用 withOutput 改數值送出[5]，這樣每 20 毫秒一次的迴圈不必一直建立新物件。

常見錯誤

空座號：宣告了卻沒有 new寫了 private TalonFX leader; 卻忘記 = new TalonFX(21)，欄位的值是 null。編譯會過，但執行到 leader.setControl(...) 時丟出 NullPointerException，機器人程式直接崩潰。
同一座號發給兩個人：同一顆硬體建立兩次在兩個不同類別裡各寫一次 new TalonFX(21)，兩個物件都以為自己在控制 21 號馬達，指令會互相覆蓋。一顆硬體只該有一個物件，其他地方要用就把這個物件傳過去。
教練提醒新手最常問「為什麼要 new？」答案就是報到：沒有 new，就只有一個名字，沒有真的人。看到 NullPointerException，第一件事就是找「哪個欄位只宣告沒有 new」。

小測驗

練習：寫一個 Flywheel 類別

照著 Roller 的結構，寫一個模擬砲台飛輪的類別：建構子接收名稱；欄位 targetRpm 預設 0；方法 setTargetRpm(double rpm) 把目標限制在 0 到 6000；方法 isAtSpeed(double currentRpm) 在實際轉速與目標相差小於 50 RPM 時回傳 true。上限與容許誤差寫成 static 常數。

看參考答案 
public class Flywheel {
    public static final double MAX_RPM = 6000.0;
    public static final double TOLERANCE_RPM = 50.0;

    private final String name;
    private double targetRpm = 0.0;

    public Flywheel(String name) {
        this.name = name;
    }

    public void setTargetRpm(double rpm) {
        targetRpm = Math.max(0.0, Math.min(MAX_RPM, rpm));
    }

    public boolean isAtSpeed(double currentRpm) {
        return Math.abs(currentRpm - targetRpm) < TOLERANCE_RPM;
    }

    public double getTargetRpm() {
        return targetRpm;
    }
}
