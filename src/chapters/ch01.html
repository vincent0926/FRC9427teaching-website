CAN ID 01｜Java 與物件導向

類別與物件：從一張學籍資料表開始

你之後每天都會看到 new TalonFX(21) 這種程式。這章要搞懂它到底做了什麼：類別跟物件差在哪、欄位和方法是什麼，最後自己寫一個完整的類別出來。

先講個比喻：開學報到

開學前，教務處要先決定學籍資料表長怎樣：要有姓名、座號、班級這幾格，再附一份說明，寫學生可以做哪些事，像交作業、自我介紹、請假。這份規格只有一份，放在教務處。它不是任何一個學生，它只是規定「學生」這種東西該有哪些東西。

開學那天小明去註冊組報到，組長照規格拿出一張新表，叫他當場填姓名和座號。空白的表組長不收，因為規定報到時這兩格一定要填。填好的那一張，才是「小明」。

三十個同學就有三十張表。小明交了作業，他那張的「作業次數」加一，小華那張不會跟著變。表格長得一樣，內容各管各的。

表格上有一格叫「本人姓名」。小明填的時候「本人」就是小明，小華填的時候就是小華。同樣兩個字，永遠指填這張表的人。

每張表最上面都印著校名。這不是學生自己填的，是全校共用的。哪天學校改名，改一次，所有表格就都變了。

然後是兩個會出事的狀況。第一個：點名冊列到 30 號，可是 30 號根本沒人報到。老師叫「30 號起來回答」，沒人站起來，整堂課就卡住了。

第二個：註冊組出包，把 7 號同時發給兩個人。點名時兩個人都喊「有」，老師叫 7 號上台，結果兩個人一起衝上去。

Oracle 的 Java 教學是這樣定義的：物件是把相關的「狀態」和「行為」包在一起的東西，類別則是用來做出物件的藍圖[1]。對回故事，表格上的格子是狀態，說明書寫的「可以做的事」是行為。

這個比喻哪裡不準紙本表格只能存資料，物件除了存資料還「會做事」。另外，做事的方法是寫在類別裡、所有物件共用一份的，不是每張表都抄一份說明書。每個物件自己一份的，只有欄位的值。

換成機器人：一個模擬的滾輪

先不碰真的硬體，用純 Java 寫一個滾輪類別。可以一邊對照上面的故事看：

public class Roller {
    // 表頭的校名：全部 Roller 共用一份
    public static final double MAX_VOLTS = 12.0;

    // 表格上的格子：每個 Roller 各自一份
    private final String name;
    private double voltage = 0.0;

    // 報到規定：建立 Roller 時一定要給名字
    public Roller(String name) {
        this.name = name;
    }

    // 說明書上寫的「可以做的事」
    public void run(double volts) {
        voltage = Math.max(-MAX_VOLTS, Math.min(MAX_VOLTS, volts));
    }

    public void stop() {
        voltage = 0.0;
    }

    public double getVoltage() {
        return voltage;
    }

    public String getName() {
        return name;
    }
}

拿這個類別做出兩個物件：

Roller intake = new Roller("Intake");
Roller feeder = new Roller("Feeder");

intake.run(8.0);
System.out.println(intake.getVoltage()); // 8.0
System.out.println(feeder.getVoltage()); // 0.0

欄位

name 和 voltage 是欄位，每個物件各一份，所以 intake.run(8.0) 不會動到 feeder。final 的意思是設定之後就不能改，名字給了就定了。前面那個 private 是第 2 章要講的，現在先知道它是「只有這個類別自己可以直接碰」就好。

建構子與 new

建構子的名字跟類別一樣，而且沒有回傳型別。new Roller("Intake") 會先生出一個新物件，再跑建構子把欄位設好[2]。因為唯一的建構子規定一定要給名字，程式裡就不可能出現沒名字的 Roller，這就是「報到時一定要填」。

this

建構子的參數叫 name，欄位也叫 name，撞名了。在建構子裡直接寫 name，Java 會當成參數；要指欄位就寫 this.name，也就是「我這個物件自己的 name」[3]。

static

MAX_VOLTS 有加 static，所以它是屬於類別本身的，所有物件共用同一份[4]。再加上 final 就變成常數。習慣上常數名稱全部大寫，單字中間用底線。

動手試：兩個物件，各自的狀態

下面兩個物件都是用 Roller 做出來的。按按鈕呼叫方法，看欄位怎麼變。最後一顆紅色按鈕就是對「空座號」點名，按下去看看會怎樣。

試試 intake.run(20.0)：你要 20V，它只給你 12V。限制寫在方法裡面，呼叫的人怎樣都繞不過去。

對照真正的 FRC 程式

import com.ctre.phoenix6.controls.VoltageOut;
import com.ctre.phoenix6.hardware.TalonFX;

public class RollerIOHardware {
    private static final int LEADER_ID = 21; // TODO: 依實際接線確認

    private final TalonFX leader = new TalonFX(LEADER_ID);
    private final VoltageOut voltageRequest = new VoltageOut(0);

    public void setVoltage(double volts) {
        leader.setControl(voltageRequest.withOutput(volts));
    }
}

leader 是欄位，裡面裝一個 TalonFX 物件。voltageRequest 也是物件，代表「用電壓控制」這個請求。setVoltage() 是方法。withOutput(volts) 改掉請求裡的輸出值之後，會把同一個物件回傳，所以可以直接丟給 setControl()。CTRE 文件的範例也是這樣寫：控制請求宣告成欄位，要送的時候用 withOutput 改數字[5]。這樣每 20 毫秒跑一次的迴圈就不用一直 new 新物件。

常見錯誤

空座號：宣告了卻沒有 new寫了 private TalonFX leader;，卻忘了 = new TalonFX(21)，這個欄位就是 null。編譯會過，但跑到 leader.setControl(...) 就會丟 NullPointerException，整個機器人程式直接掛掉。
同一座號發給兩個人：同一顆硬體 new 兩次兩個不同的類別裡各寫了一次 new TalonFX(21)，兩個物件都覺得自己在控制 21 號馬達，指令會互相蓋掉。一顆硬體只能有一個物件，別的地方要用，就把那個物件傳過去。
教練提醒新手很常問「為什麼一定要 new？」想想報到就懂了：沒有 new，就只有一個名字，沒有真的人。以後看到 NullPointerException，第一個反應就是去找「哪個欄位只宣告、沒有 new」。

小測驗

練習：寫一個 Flywheel 類別

照 Roller 的寫法，做一個模擬砲台飛輪的類別。建構子收一個名稱；欄位 targetRpm 預設是 0；setTargetRpm(double rpm) 要把目標限制在 0 到 6000；isAtSpeed(double currentRpm) 在實際轉速跟目標差不到 50 RPM 時回傳 true。上限和容許誤差都寫成 static 常數。

先照 Roller 把骨架寫出來：欄位、建構子、方法。上限和容許誤差是「所有飛輪共用、而且不會變」的值。

共用又不會變，就是 public static final。限制範圍可以用 Math.max 和 Math.min，算差距用 Math.abs。

setTargetRpm 的核心是 targetRpm = Math.max(0.0, Math.min(MAX_RPM, rpm));，isAtSpeed 回傳 Math.abs(currentRpm - targetRpm) < TOLERANCE_RPM。

public class Flywheel {
    public static final double MAX_RPM = 6000.0;
    public static final double TOLERANCE_RPM = 50.0;

    private final String name;
    private double targetRpm = 0.0;

    public Flywheel(String name) {
        this.name = name;
    }

    public void setTargetRpm(double rpm) {
        targetRpm = Math.max(0.0, Math.min(MAX_RPM, rpm));
    }

    public boolean isAtSpeed(double currentRpm) {
        return Math.abs(currentRpm - targetRpm) < TOLERANCE_RPM;
    }

    public double getTargetRpm() {
        return targetRpm;
    }
}
