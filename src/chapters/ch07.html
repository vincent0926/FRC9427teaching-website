CAN ID 07｜WPILib 基礎

機器人程式的生命週期：學校的一天

程式部署上去之後，到底是誰在呼叫你寫的方法？這章講機器人程式怎麼啟動、四種模式怎麼切換、每 20 毫秒裡哪些方法照什麼順序跑，順便比較 TimedRobot 跟 AdvantageKit 的 LoggedRobot。最後會解釋為什麼在 periodic 裡寫一個 while 迴圈，整台機器人就會「當機」。

比喻：學校的一天

每天早上學校開門前，工友會先把教室的燈打開、桌椅排好、設備檢查一遍。這件事一天只做一次，而且在任何人進教室之前就做完了。

一天分成幾種時段。早自習的時候學生都到了，但還不能開始活動，只能乖乖坐好。第一節是自主學習，老師不在，學生照前一天寫好的計畫自己做事。接下來是一般上課，老師站在台上，學生照老師的指令動。偶爾還有實驗課，用來檢查器材能不能正常運作。

現在是哪個時段，學生不能自己宣布，要聽廣播。平常練習是導護老師廣播，正式考試則由考場統一廣播。

每個時段都有開始、進行中、結束三段。一進入新時段，班長會喊一次「起立、敬禮」，只在開頭喊一次。時段進行中，老師每隔固定時間巡一下教室。時段結束前大家把東西收好，這也只做一次。如果之後又回到同一個時段，例如下午又回來上課，班長就會再喊一次。

不管什麼時段，警衛都照常巡邏。老師巡完教室，警衛就接著巡整棟大樓，早自習、自主學習、上課都一樣，每一輪都巡，而且一定排在老師後面。

巡邏的時間是固定的，學校規定每 20 分鐘巡一輪。關鍵是：老師和警衛其實是同一個人輪流扮演的。他先用老師的身分巡教室，再用警衛的身分巡大樓，然後處理公布欄。如果他在某間教室停下來講了半小時，這一輪就超時了，後面的警衛巡邏、公布欄全部往後延，整棟大樓那段時間都沒人顧。

還有一個例外：只有模擬考那天，每一輪最後會多一個步驟叫「模擬閱卷」，平常上課日不會做。

這個比喻哪裡不準學校的鐘一定準時響，但 20 毫秒只是「設定的週期」，不是保證。程式跑超過 20 毫秒，那一輪就叫 overrun，控制就會延遲。另外，故事裡特別強調老師和警衛是同一個人，這點很重要：TimedRobot 主迴圈裡的 periodic 方法，全部是在同一條執行緒上「一個接一個」跑的，不是同時跑。所以只要有一個卡住，後面全部被拖住。

程式怎麼啟動

roboRIO 啟動程式的時候，先跑 Main.java，它把 Robot 類別交給 WPILib 啟動，然後 Robot 的建構子跑一次。從 2025 年開始，WPILib 範本把初始化寫在建構子裡，註解是「機器人第一次啟動時執行，用來放初始化程式」[1]。你在網路上看到舊範例用 robotInit()，那是以前的寫法。

Command-based 專案的 RobotContainer 要在 Robot 的建構子裡建立，因為大部分設定都寫在 RobotContainer 的建構子裡[3]。所以「工友開門整理」這一步，實際上就是把所有 Subsystem 建好、按鍵綁好。

四種模式與誰來切換

Driver Station 的 Operation 分頁可以選 Teleoperated、Autonomous、Practice、Test。Practice 模式按下 Enable 之後，它會照 Setup 分頁設的時間，自動跑一遍跟正式比賽一樣的模式切換[5]。正式比賽時，模式是場地系統（FMS）在控制。

自動和手動階段各有多長，每年規則不一樣，看當年的 Game Manual。

init、periodic、exit

TimedRobot 是靠一組 init()、periodic()、exit() 方法在跑的，WPILib 會在對應的狀態呼叫它們[1]。API 文件裡的定義整理如下[2]：

方法什麼時候被呼叫
disabledInit()、autonomousInit()、teleopInit()、testInit()每次從其他模式進入該模式時，呼叫一次
disabledPeriodic() 等在該模式中，每個週期呼叫一次
disabledExit() 等每次離開該模式時，呼叫一次
robotPeriodic()不論哪個模式，每個週期都呼叫

週期預設 20 毫秒，也就是一秒 50 次。可以在建構子用 super(0.03) 改成 30 毫秒，不過官方是用「Danger」等級在警告的，改週期可能造成意料之外的行為（loop overrun）[1]。沒有很好的理由就別動它。

每 20 毫秒裡的順序

翻 WPILib 原始碼的 IterativeRobotBase，每一輪的順序是這樣[4]：

順序做什麼
1如果模式改變了：先呼叫舊模式的 exit()，再呼叫新模式的 init()
2呼叫目前模式的 periodic()
3呼叫 robotPeriodic()
4更新 SmartDashboard、LiveWindow、Shuffleboard
5只在模擬時：呼叫 simulationPeriodic()
6檢查這一輪有沒有超時，超時就印出警告

動手試：一步一步跑 20 毫秒

下面這個小模擬器讓你當 Driver Station：先選模式，再按「執行下一輪」，看這一輪有哪些方法被叫到。可以試試從 Disabled 切到 Autonomous，再切到 Teleop，注意 init 和 exit 出現的時機。

Command-based 的 Robot.java

Command-based 是宣告式的寫法，所以 Robot 類別應該幾乎是空的[3]。下面是 2026 年 Command-based 範本的重點：

public class Robot extends TimedRobot {
    private Command m_autonomousCommand;
    private final RobotContainer m_robotContainer;

    public Robot() {
        m_robotContainer = new RobotContainer(); // 工友開門：建好所有 Subsystem、綁好按鍵
    }

    @Override
    public void robotPeriodic() {
        CommandScheduler.getInstance().run();   // 警衛巡邏：每一輪都要跑
    }

    @Override
    public void autonomousInit() {
        m_autonomousCommand = m_robotContainer.getAutonomousCommand();
        if (m_autonomousCommand != null) {
            CommandScheduler.getInstance().schedule(m_autonomousCommand);
        }
    }

    @Override
    public void teleopInit() {
        if (m_autonomousCommand != null) {
            m_autonomousCommand.cancel();       // 手動開始時，停掉還沒跑完的自動指令
        }
    }

    @Override
    public void testInit() {
        CommandScheduler.getInstance().cancelAll();
    }
}

整份最重要的就是 robotPeriodic() 裡那一行。CommandScheduler.getInstance().run() 一定要放在 robotPeriodic()，少了它，排程器什麼指令都不會跑[3]。排程器每次 run()，會先呼叫所有已註冊 Subsystem 的 periodic()，再檢查按鍵觸發，最後跑排程中的指令[6]。所以第 6 章寫在 Subsystem periodic() 裡的 updateInputs，其實就是被這一行帶著跑的。

teleopInit() 裡會取消自動指令，理由很實際：自動程式如果在自動階段結束前還沒跑完，進手動之後它會繼續佔著機構，駕駛手就搶不到控制權。

如果 Robot 繼承的是 LoggedRobot

用 AdvantageKit 的專案（第 6 章後半），Robot 繼承的不是 TimedRobot，而是 LoggedRobot，而且這是一定要的[7]。

好消息是這章講的生命週期全部照樣適用。LoggedRobot 跟 TimedRobot 一樣是繼承 IterativeRobotBase，一樣用固定週期呼叫 init、periodic、exit[8]，上面的模擬器兩種都通用。差在這幾個地方：

TimedRobotLoggedRobot
生命週期方法相同，都來自 IterativeRobotBase
額外的週期函式（addPeriodic）支援不支援[7]
建構子最前面建立 RobotContainer先設定並啟動 Logger，然後才建立 RobotContainer[7]
重播時不適用可用 setUseTiming(false) 讓每輪盡快執行，但讀到的時間戳仍與真機器人相同[7]
 
public class Robot extends LoggedRobot {
    private final RobotContainer m_robotContainer;

    public Robot() {
        // 一定要放在建構子最前面，在任何其他初始化之前
        Logger.recordMetadata("ProjectName", "FRC9427");
        if (isReal()) {
            Logger.addDataReceiver(new WPILOGWriter()); // 寫入 roboRIO 上的 USB 隨身碟
            Logger.addDataReceiver(new NT4Publisher()); // 即時發布到 NetworkTables
        }
        // 模擬與重播的設定見第 18 章
        Logger.start(); // 之後就不能再新增接收端或 metadata

        m_robotContainer = new RobotContainer();
    }

    @Override
    public void robotPeriodic() {
        CommandScheduler.getInstance().run(); // 和 TimedRobot 版本一樣，不能少
    }
}

順序很重要。Logger 的設定要放在 Robot 建構子最前面，比任何初始化都早；Logger.start() 之後就不能再加資料接收端、重播來源或 metadata 了[7]。如果你先建了 RobotContainer，Subsystem 可能在記錄框架還沒準備好的時候就開始讀輸入。另外 WPILOGWriter 預設寫到 USB 隨身碟，所以 roboRIO 上一定要插一支 FAT32 的隨身碟[7]。

教練提醒有用 AdvantageKit 的話，賽前檢查清單要多一項：roboRIO 上的 USB 隨身碟有插、是 FAT32、還有空間。沒日誌的話，出事的時候就什麼都不能重播，只能靠記憶猜。

Loop overrun：老師講太久

某一輪超過 20 毫秒，主控台就會跳 Loop time of 0.02s overrun，後面還會列出這一輪每個階段花多久。Command 排程器也有自己的計時，超時會印 CommandScheduler loop overrun，一樣附上每個 Subsystem 和指令的耗時[4][6]。看到這些警告，直接找列表裡時間最長的那一項，通常兇手就是它。

常見錯誤

在 periodic 裡等東西在 teleopPeriodic() 或 Subsystem 的 periodic() 裡寫 while (!sensor.get()) {} 或 Thread.sleep(500)，整個主迴圈就卡在那邊，其他 Subsystem、按鍵、指令全部停止更新，機器人看起來就像當機。periodic 的原則是「這一輪該做的做完就走」，要等的邏輯交給 Command（第 8、9 章）。
在 periodic 裡 new 東西把 new TalonFX(21) 或 new VoltageOut(0) 寫在 periodic 裡，一秒就 new 50 次。硬體物件和控制請求都應該在建構子或欄位宣告的時候建一次就好（第 1 章）。
太早讀 Driver Station 的資料聯盟顏色這種資料是從 Driver Station 來的，建構子跑的時候可能還沒連上，讀到的值不能信。IterativeRobotBase 有一個 driverStationConnected() 方法，需要知道 Driver Station 狀態的程式就放那裡[2]，不然就等到 autonomousInit() 再讀。
教練提醒每次部署完，先看 RioLog 有沒有 overrun，再 Enable。練習的時候就要養成習慣：新加的程式一讓 overrun 冒出來，就先查清楚再往下寫。比賽中 overrun 不會直接讓你輸，但會讓自動路徑跑偏、PID 抖，而且在 pit 裡很難現場查出來。

小測驗

練習：預測呼叫順序

機器人剛開機（Disabled），然後依序：切到 Autonomous 跑兩輪，再切到 Teleop 跑一輪。從開機後第一輪開始，寫出每一輪會被呼叫的方法（Dashboard 更新不用寫）。寫完再用上面的模擬器對答案。

先把三種方法分清楚：init 只出現在「進入模式的那一輪」，exit 出現在「離開模式的那一輪」，periodic 每一輪都有。

每一輪的順序是：（切換時）舊模式的 exit → 新模式的 init → 該模式的 periodic → robotPeriodic。

第 2 輪（切到 Autonomous）是 disabledExit → autonomousInit → autonomousPeriodic → robotPeriodic；建構子 Robot() 只在程式啟動時一次。

// 程式啟動
Robot()                  // 建構子，只有一次

// 第 1 輪（Disabled）
disabledInit()           // 從「沒有模式」進入 Disabled
disabledPeriodic()
robotPeriodic()

// 第 2 輪（切到 Autonomous）
disabledExit()
autonomousInit()
autonomousPeriodic()
robotPeriodic()

// 第 3 輪（Autonomous）
autonomousPeriodic()
robotPeriodic()

// 第 4 輪（切到 Teleop）
autonomousExit()
teleopInit()
teleopPeriodic()
robotPeriodic()

三個重點：init 只在切換那一輪出現；exit 一定在新模式的 init 前面；robotPeriodic() 每一輪都有，而且永遠排在模式的 periodic 後面。
