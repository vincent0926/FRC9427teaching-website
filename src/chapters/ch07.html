CAN ID 07｜WPILib 基礎

機器人程式的生命週期：學校的一天

讀完這章，你會知道機器人程式怎麼啟動、四種模式怎麼切換、每 20 毫秒裡哪些方法依什麼順序被呼叫、TimedRobot 和 AdvantageKit 的 LoggedRobot 有什麼不同，以及為什麼在 periodic 裡寫一個 while 迴圈會讓整台機器人當機。

生活比喻：學校的一天

早上工友先開門整理。每天早上學校開門前，工友會先把教室的燈打開、桌椅排好、設備檢查一遍。這件事一天只做一次，而且是在任何人進教室之前。

一天分成幾種時段。早自習的時候，學生都到了，但還不能開始活動，只能安靜坐好。第一節是自主學習時間，老師不在教室，學生照著前一天寫好的計畫自己做事。之後是一般上課，老師站在台上，學生聽老師的指令行動。偶爾還有實驗課，拿來檢查器材能不能正常運作。

現在是哪個時段，由廣播決定。學生不能自己宣布「現在開始上課」。平常練習時由導護老師廣播，正式考試時則由考場統一廣播。

每個時段有開始、進行中、結束三個階段。每次進入一個新時段，班長會喊一次「起立、敬禮」，這個動作只在時段開始時做一次。時段進行中，老師每隔固定時間巡一下教室。時段結束前，大家把東西收好，這也只做一次。只要重新進入同一個時段，例如下午又回到上課，班長就會再喊一次。

不管什麼時段，警衛都照常巡邏。老師巡完教室後，警衛會接著巡一次整棟大樓。這件事不管是早自習、自主學習還是上課，每一輪都會做，而且總是排在老師巡完之後。

巡邏的時間是固定的。學校規定每 20 分鐘巡一輪。老師和警衛是同一個人輪流扮演的：先以老師的身分巡教室，再以警衛的身分巡大樓，然後處理公布欄。如果有一位老師在某間教室停下來講了半小時，這一輪就超時了，後面的警衛巡邏和公布欄更新全部跟著延後，整棟大樓這段時間都沒人照看。

模擬考日有額外的流程。只有模擬考的日子，每一輪最後還會多一個步驟：模擬閱卷。平常上課日不會做這件事。

這個比喻哪裡不準學校的鐘聲一定準時響，但 20 毫秒只是「設定的週期」，不是保證。程式如果跑超過 20 毫秒，那一輪就是 overrun，控制就延遲了。另外，故事裡特別強調老師和警衛是同一個人輪流扮演，這一點很重要：在 TimedRobot 的主迴圈裡，所有 periodic 方法是在同一條執行緒上「依序」執行，不是同時進行。所以只要其中一個方法卡住，後面的全部都會被拖住。

程式怎麼啟動

roboRIO 啟動程式時，先執行 Main.java，它會把 Robot 類別交給 WPILib 啟動。接著 Robot 的建構子執行一次。從 2025 年起，WPILib 範本在建構子寫著「機器人第一次啟動時執行，用來放初始化程式」[1]，而不是舊範本常用的 robotInit()。

在 Command-based 專案裡，WPILib 文件說明 RobotContainer 應該在 Robot 的建構子裡建立，因為大部分的宣告式設定都寫在 RobotContainer 的建構子裡[3]。所以「工友開門整理」這一步，實際上就是把所有 Subsystem 建好、把按鍵綁好。

四種模式與誰來切換

Driver Station 的 Operation 分頁可以選 Teleoperated、Autonomous、Practice、Test。Practice 模式會在按下 Enable 後，依照 Setup 分頁設定的時間，自動走一遍和正式比賽相同的模式切換[5]。正式比賽中則由場地系統（FMS）控制模式。

自動階段和手動階段各有多長，是每年的比賽規則決定的，請以當年的 Game Manual 為準。

init、periodic、exit

TimedRobot 透過一組 init()、periodic()、exit() 方法控制程式，這些方法由 WPILib 在對應的狀態下呼叫[1]。WPILib 的 API 文件對它們的定義是[2]：

方法什麼時候被呼叫
disabledInit()、autonomousInit()、teleopInit()、testInit()每次從其他模式進入該模式時，呼叫一次
disabledPeriodic() 等在該模式中，每個週期呼叫一次
disabledExit() 等每次離開該模式時，呼叫一次
robotPeriodic()不論哪個模式，每個週期都呼叫

週期預設是 20 毫秒，也就是每秒 50 次。可以在建構子用 super(0.03) 改成 30 毫秒，但官方用「Danger」等級警告，更改週期可能造成非預期的行為（loop overrun）[1]。

每 20 毫秒裡的順序

根據 WPILib 原始碼中的 IterativeRobotBase，每一輪的執行順序是[4]：

順序做什麼
1如果模式改變了：先呼叫舊模式的 exit()，再呼叫新模式的 init()
2呼叫目前模式的 periodic()
3呼叫 robotPeriodic()
4更新 SmartDashboard、LiveWindow、Shuffleboard
5只在模擬時：呼叫 simulationPeriodic()
6檢查這一輪有沒有超時，超時就印出警告

動手試：一步一步跑 20 毫秒

用下面的模擬器扮演 Driver Station：先選模式，再按「執行下一輪」，看每一輪有哪些方法被呼叫。試試看從 Disabled 切到 Autonomous，再切到 Teleop。

Command-based 的 Robot.java

WPILib 文件說明，Command-based 是宣告式的寫法，所以 Robot 類別應該幾乎是空的[3]。以下是 2026 年 Command-based 範本的重點部分：

public class Robot extends TimedRobot {
    private Command m_autonomousCommand;
    private final RobotContainer m_robotContainer;

    public Robot() {
        m_robotContainer = new RobotContainer(); // 工友開門：建好所有 Subsystem、綁好按鍵
    }

    @Override
    public void robotPeriodic() {
        CommandScheduler.getInstance().run();   // 警衛巡邏：每一輪都要跑
    }

    @Override
    public void autonomousInit() {
        m_autonomousCommand = m_robotContainer.getAutonomousCommand();
        if (m_autonomousCommand != null) {
            CommandScheduler.getInstance().schedule(m_autonomousCommand);
        }
    }

    @Override
    public void teleopInit() {
        if (m_autonomousCommand != null) {
            m_autonomousCommand.cancel();       // 手動開始時，停掉還沒跑完的自動指令
        }
    }

    @Override
    public void testInit() {
        CommandScheduler.getInstance().cancelAll();
    }
}

最重要的是 robotPeriodic() 裡那一行。官方文件強調，CommandScheduler.getInstance().run() 一定要放在 robotPeriodic()；沒有這一行，排程器就不會執行任何指令[3]。排程器每次 run() 時，會先呼叫所有已註冊 Subsystem 的 periodic()，接著檢查按鍵觸發，再執行目前排程中的指令[6]。所以第 6 章 IO 架構裡寫在 Subsystem periodic() 的 updateInputs，其實就是被這一行帶動的。

teleopInit() 取消自動指令的理由也很實際：如果自動程式在自動階段結束前沒跑完，進入手動後它還會繼續佔用機構，駕駛就搶不到控制權。

如果 Robot 繼承的是 LoggedRobot

使用 AdvantageKit 的專案（第 6 章後半），Robot 繼承的不是 TimedRobot，而是 LoggedRobot。AdvantageKit 文件規定主要的 Robot 類別必須繼承 LoggedRobot[7]。

好消息是，本章的生命週期規則完全適用。LoggedRobot 和 TimedRobot 一樣繼承自 IterativeRobotBase，同樣的 init、periodic、exit 方法由固定週期呼叫[8]，上面的模擬器對兩者都成立。差別在於：

TimedRobotLoggedRobot
生命週期方法相同，都來自 IterativeRobotBase
額外的週期函式（addPeriodic）支援不支援[7]
建構子最前面建立 RobotContainer先設定並啟動 Logger，然後才建立 RobotContainer[7]
重播時不適用可用 setUseTiming(false) 讓每輪盡快執行，但讀到的時間戳仍與真機器人相同[7]
 
public class Robot extends LoggedRobot {
    private final RobotContainer m_robotContainer;

    public Robot() {
        // 一定要放在建構子最前面，在任何其他初始化之前
        Logger.recordMetadata("ProjectName", "FRC9427");
        if (isReal()) {
            Logger.addDataReceiver(new WPILOGWriter()); // 寫入 roboRIO 上的 USB 隨身碟
            Logger.addDataReceiver(new NT4Publisher()); // 即時發布到 NetworkTables
        }
        // 模擬與重播的設定見第 18 章
        Logger.start(); // 之後就不能再新增接收端或 metadata

        m_robotContainer = new RobotContainer();
    }

    @Override
    public void robotPeriodic() {
        CommandScheduler.getInstance().run(); // 和 TimedRobot 版本一樣，不能少
    }
}

順序很重要。AdvantageKit 文件要求 Logger 的設定放在 Robot 建構子裡、任何其他初始化之前，並且在 Logger.start() 之後就不能再加入資料接收端、重播來源或 metadata[7]。如果先建立 RobotContainer，Subsystem 可能在記錄框架還沒準備好時就開始讀取輸入。文件也提醒，WPILOGWriter 預設寫入 USB 隨身碟，roboRIO 上必須插著一支 FAT32 格式的隨身碟[7]。

教練提醒用 AdvantageKit 的隊伍，比賽前的檢查清單要多一項：roboRIO 上的 USB 隨身碟有插好、格式是 FAT32、還有空間。沒有日誌，出問題時就沒有東西可以重播。

Loop overrun：老師講太久

如果某一輪超過 20 毫秒，主控台會出現 Loop time of 0.02s overrun 的警告，後面還會列出這一輪中每個階段花了多少時間。Command 排程器也有自己的計時，超時會印出 CommandScheduler loop overrun，同樣附上每個 Subsystem 和指令的耗時[4][6]。看到這些警告時，找出列表中時間最長的那一項，通常就是元兇。

常見錯誤

在 periodic 裡等待在 teleopPeriodic() 或 Subsystem 的 periodic() 裡寫 while (!sensor.get()) {} 或 Thread.sleep(500)，整個主迴圈就停在那裡，其他 Subsystem、按鍵、指令全部不會更新，機器人看起來像當機。periodic 方法要「做完這一輪該做的事就立刻結束」，需要等待的邏輯交給 Command 處理（第 8、9 章）。
在 periodic 裡建立物件把 new TalonFX(21) 或 new VoltageOut(0) 寫在 periodic 裡，每秒就會建立 50 次。硬體物件和控制請求都應該在建構子或欄位宣告時建立一次（第 1 章）。
太早讀取 Driver Station 資料聯盟顏色這類資料來自 Driver Station，建構子執行時可能還沒連上，讀到的值不可靠。WPILib 的 IterativeRobotBase 提供 driverStationConnected() 方法，官方說明「需要知道 Driver Station 狀態的程式碼應該放在這裡」[2]，或者等到 autonomousInit() 再讀取。
教練提醒每次部署後，先看 RioLog 有沒有 overrun 警告，再 Enable。練習時養成習慣：新加的程式碼只要讓 overrun 出現，就先找出原因再繼續。比賽中 overrun 不會讓你輸，但它會讓自動路徑跑偏、PID 抖動，而且很難在 pit 裡現場查出來。

小測驗

練習：預測呼叫順序

機器人剛開機（處於 Disabled），接著依序發生：切到 Autonomous 並跑了兩輪，再切到 Teleop 並跑了一輪。請寫出從開機後第一輪開始，每一輪會被呼叫的方法（不含 Dashboard 更新）。寫完後用上面的模擬器對答案。

先分清三種方法：init 只在「進入模式的那一輪」，exit 在「離開模式的那一輪」，periodic 每一輪都有。

每一輪的順序是：（切換時）舊模式的 exit → 新模式的 init → 該模式的 periodic → robotPeriodic。

第 2 輪（切到 Autonomous）是 disabledExit → autonomousInit → autonomousPeriodic → robotPeriodic；建構子 Robot() 只在程式啟動時一次。

// 程式啟動
Robot()                  // 建構子，只有一次

// 第 1 輪（Disabled）
disabledInit()           // 從「沒有模式」進入 Disabled
disabledPeriodic()
robotPeriodic()

// 第 2 輪（切到 Autonomous）
disabledExit()
autonomousInit()
autonomousPeriodic()
robotPeriodic()

// 第 3 輪（Autonomous）
autonomousPeriodic()
robotPeriodic()

// 第 4 輪（切到 Teleop）
autonomousExit()
teleopInit()
teleopPeriodic()
robotPeriodic()

注意三件事：init 只在切換的那一輪出現；exit 一定在新模式的 init 之前；robotPeriodic() 每一輪都有，而且總是排在模式的 periodic 之後。
