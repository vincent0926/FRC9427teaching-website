CAN ID 19｜上場

上場檢查與 Pit 除錯：考試當天

讀完這章，你會知道出發前、每場比賽前、每場比賽後各要檢查什麼，怎麼從 Driver Station 看出 brownout、roboRIO 重開或網路問題，以及在兩場比賽之間的短短時間裡，照什麼順序把問題找出來、改程式時要守哪些規矩。

版本說明本章依據 WPILib 2026 文件（roboRIO 與 NI Driver Station）。2027 年起控制系統換成 SystemCore，Driver Station 與部分檢查項目會不同。本章的檢查清單結合了官方文件與一般隊伍常見的做法，隊上應依自己的機器人調整。

生活比喻：考試當天

前一晚就把文具準備好。准考證、2B 鉛筆、橡皮擦、手錶，前一晚就放進袋子裡。考試當天早上才發現鉛筆沒削，已經來不及了。

每一節考試前，再確認一次。進考場前摸一下：准考證在嗎？座位號碼對嗎？手機關了嗎？這些檢查很無聊，但一節考試只有一次機會。

考試中出狀況，先看最簡單的原因。筆寫不出來，先看是不是沒按下筆頭，再看是不是沒水了，最後才懷疑是不是桌子有問題。從最常見、最容易檢查的原因開始。

下課十分鐘只能修小東西。兩節考試之間只有十分鐘。可以換一支筆、借一個橡皮擦，但不可能重新複習一整章。

考完對答案。每節考完，把題目和自己的答案記下來，回家才知道錯在哪裡。

這個比喻哪裡不準考試出狀況通常只影響自己；機器人出狀況會影響整個聯盟。另外，考試不能在考場外練習同一份題目，但機器人可以在 Pit 裡重現問題：WPILib 文件建議在 Pit 通電、用網路線連著時搖動線材，甚至把機器人一側抬起再放下，讓問題在 Pit 裡發生，而不是在場上[1]。

出發前

Driver Station 筆電

WPILib 的 Driver Station 最佳實務文件建議[2]：

  • 準備一台專門用來開車的筆電，只裝 Driver Station 和儀表板，不拿來寫程式。
  • 電源設定改成不睡眠、關閉省電、效能最佳；確認電池在這些設定下至少撐一小時，排隊上場時沒有插座也不怕。
  • 出發前裝完所有 Windows 更新並實際連機器人測試，然後暫停更新涵蓋整個比賽期間，並設定使用時段避免比賽中安裝更新。
  • 帶一條可靠的 USB 線和網路線，用來直接連 roboRIO。
  • Driver Station 不支援 ARM 處理器的筆電。

程式與工具

  • 建立 event_ 開頭的比賽分支（第 18 章），確認部署時會自動 commit。
  • 所有 vendordep（Phoenix 6、PathPlannerLib、AdvantageKit…）更新到要用的版本並在機器人上測過。比賽場地通常沒有網路，文件也提醒不要打算在現場用網路更新軟體[2]。
  • 準備一個「已知可以動」的程式版本（例如打一個 Git tag），真的改壞時可以立刻退回。
  • FAT32 隨身碟（第 18 章）至少兩支，一支插在機器人上，一支備用。

每場比賽前

WPILib 文件對 Driver Station 的建議[2][1]：前一場結束前就把筆電開機並登入；關掉不需要的程式；一定要帶筆電充電器到場上，因為插電時 Windows 的電源管理比較不激進，Driver Station 表現比較穩定；用魔鬼氈把筆電固定在操作台上。現場要關閉 Windows 防火牆和 Wi-Fi[2]。

下面是一份程式組可以用的檢查清單：

項目怎麼確認相關章節
電池充飽、接頭鎖緊電壓表或 Battery Beak；用力扳動電池線，接頭不能動本章
程式是這一場要用的版本儀表板顯示 GitSHA，或確認最後一次部署18
自動程式選對儀表板的選單不是預設的 None16
機器人擺放位置和 Auto 起始位置一致對照 PathPlanner 的起點16
所有 CAN 裝置都在儀表板沒有斷線 Alert；有疑慮時用 Tuner X 掃描12

隨身碟有插、有空間目視；或在程式裡偵測後發 Alert18

每場比賽後

  1. 用 AdvantageScope 下載 AdvantageKit 日誌（第 18 章），檔名或資料夾標上場次。
  2. 打開 Driver Station 的 Log Viewer，看這一場的電壓、延遲、掉封包和模式。
  3. 看 Driver Station 的 CAN/Power 分頁，12V fault 計數有沒有增加（見下方 brownout）。
  4. 問駕駛和操作手：有沒有哪裡「感覺不對」？把時間點記下來，再去日誌裡找。
  5. 換電池、充電，電池編號和場次一起記錄。

看懂 Brownout

電池電壓在大電流時會瞬間掉下來。WPILib 文件說明 roboRIO（1.0）的分段保護[3]：

階段電壓發生什麼
1低於 6.8 VPWM 腳位的 6V 輸出開始下降
2低於 6.3 V進入 brownout 保護：PWM 輸出關閉、使用者電源軌關閉、CAN 馬達控制器收到停用命令；電壓回到 7.5 V 以上才恢復
3低於約 4.5 V可能直接斷電，電壓回升後重新開機

roboRIO 2.0 的第 2 階段預設門檻是 6.75 V，可以用 RobotController.setBrownoutVoltage 調整；roboRIO 1.0 固定 6.3 V[3]。發生 brownout 時，roboRIO 的電源燈變琥珀色、Driver Station 的電壓底色變紅並顯示 Voltage Brownout、CAN/Power 分頁的 12V fault 計數加一，DS 日誌也會記錄[3]。

程式能做的事：第 11 章的電流限制是最直接的預防。文件也建議做「電流預算」：列出各機構的電流需求，如果某些功能不會同時使用，就在程式裡強制它們不同時動作[3]。

從 DS Log 看出斷線原因

Driver Station 的 Log Viewer 會畫出電壓、延遲（trip time）、roboRIO CPU、掉封包與機器人模式，並標出事件[4]。文件整理了幾種典型的斷線樣子，其中最常用來判斷的是roboRIO 重開：主要線索是 DS 事件裡的「Time since robot boot」訊息，斷線後其他裝置都 ping 得到、只有 roboRIO 不回應，接著 roboRIO 重新回應[4]。常見的另外兩種是機器人上的網路線問題與無線電重開，看到斷線時先對照文件中的圖例。

Driver Station 訊息也有幫助[5]：「No robot code is currently running」表示 roboRIO 有連上，但程式沒在跑（程式當掉、還在開機、或部署失敗）；「The Driver Station has lost communication with the robot」則是 DS 和機器人的通訊中斷。

Pit 分診：從最簡單的原因查起

兩場比賽之間時間很短。和第 12 章的 CAN 除錯一樣，先查最常見、最容易檢查的原因。

比賽期間改程式的規矩

下面是一般隊伍在比賽期間常用的原則，不是官方規定，但能避免大多數「越改越糟」的情況：

  1. 一次只改一件事。同時改兩個地方，出問題時就不知道是哪一個。
  2. 只改和問題直接相關的地方。「順便」重構、改命名、升級函式庫，都留到比賽後。
  3. 改完要在 Pit 測過才上場。至少 Enable 一次，動一下改到的機構；自動程式的修改要在練習場跑一次，或至少把底盤架高、在模擬裡跑過。
  4. 改數字前先記下原本的值。比賽分支的自動 commit（第 18 章）會幫你記，但口頭也要跟隊友說。
  5. 來不及測，就不要改。用已知可以動的版本上場，比帶著沒測過的修改上場安全。
  6. 每次部署後確認版本。部署失敗但沒注意到，就會帶著舊程式上場。
教練提醒：分工Pit 裡同時有機構組在修東西時，Enable 前一定要大聲喊，確認所有人的手都離開機器人（第 0 章）。程式組改程式時，指定一個人負責部署，避免兩台電腦先後部署不同版本。

常見錯誤

沒帶筆電充電器上場Windows 在電池模式下的電源管理比較激進，Driver Station 的表現比較難預測[2]。
比賽中 Windows 開始更新出發前沒暫停更新、沒設使用時段，結果上場前筆電在重新開機。
把 brownout 當成程式 bug機構動作突然停一下又恢復，先看 12V fault 計數和 DS Log 的電壓，不要急著改程式。
用 USB 線測線材文件提醒搖線測試時要用網路線連接，不是 USB，否則測不到機器人上真正的通訊路徑[1]。
在 Pit 大改程式兩場之間重寫一整個指令，沒時間測就上場，常常比原本的問題更嚴重。

小測驗

練習：讓程式幫你做賽前檢查

用第 12 章的 Alert，在 Disabled 時檢查兩件事：電池電壓太低（門檻由隊上決定），以及自動程式選單還是預設值。提示：RobotController.getBatteryVoltage() 回傳電池電壓；AutoBuilder.getAllAutoNames() 回傳專案裡所有 Auto 的名字，可以用它自己建立選單，並記住預設選項。

看參考答案 
// RobotContainer
private static final double LOW_BATTERY_VOLTS = 12.0; // TODO: 隊上決定門檻
private final Alert lowBattery = new Alert("電池電壓偏低，上場前請換電池", AlertType.kWarning);
private final Alert noAuto = new Alert("尚未選擇自動程式", AlertType.kWarning);
private final Debouncer batteryDebounce = new Debouncer(1.0, Debouncer.DebounceType.kRising);
private final Command doNothing = Commands.none().withName("DoNothing");

// 建構子裡（Named Commands 註冊之後，第 16 章）
autoChooser = new SendableChooser<>();
autoChooser.setDefaultOption("Do Nothing", doNothing);
for (String name : AutoBuilder.getAllAutoNames()) {
    autoChooser.addOption(name, new PathPlannerAuto(name)); // 開機時就建立
}
SmartDashboard.putData("Auto Chooser", autoChooser);

/** 在 Robot.robotPeriodic() 裡呼叫。 */
public void updatePreMatchAlerts() {
    boolean disabled = DriverStation.isDisabled();
    lowBattery.set(disabled
        && batteryDebounce.calculate(RobotController.getBatteryVoltage() < LOW_BATTERY_VOLTS));
    noAuto.set(disabled && autoChooser.getSelected() == doNothing);
}

幾個重點：電壓會跳動，用 Debouncer 要求持續 1 秒低於門檻才警告（第 12 章）；只在 Disabled 時檢查，因為比賽中大電流時電壓本來就會掉。buildAutoChooser() 的預設選項是它內部建立的 Commands.none()，程式拿不到那個物件；所以這裡自己建立選單，把自己的 doNothing 當預設選項，就能用 == 判斷有沒有換過。用 AdvantageKit 時，選單換成第 18 章的 LoggedDashboardChooser，判斷方式相同。Alert 會自動被 AdvantageKit 記錄（第 18 章），賽後也查得到。
