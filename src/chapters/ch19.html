CAN ID 19｜上場

上場檢查與 Pit 除錯：考試當天

最後一章，講的是比賽當天。程式寫得再好，上場前忘了檢查一樣會出事。這章整理出發前、每場比賽前、每場比賽後要檢查什麼，怎麼從 Driver Station 看出 brownout、roboRIO 重開或網路問題，還有兩場比賽之間那一點點時間，要照什麼順序找問題、改程式要守哪些規矩。

版本說明這章是照 WPILib 2026 文件（roboRIO 和 NI Driver Station）寫的。2027 年起控制系統會換成 SystemCore，Driver Station 和一些檢查項目會不一樣。這裡的檢查清單是官方文件加上很多隊伍常見的做法，請依隊上的機器人自己調整。

比喻：考試當天

准考證、2B 鉛筆、橡皮擦、手錶，前一晚就要放進袋子。考試當天早上才發現鉛筆沒削，就來不及了。

每節考試進場前再摸一下：准考證在嗎？座位號碼對嗎？手機關了嗎？這些檢查很無聊，但一節考試就只有一次機會。

考到一半筆寫不出來，先看是不是沒按筆頭，再看是不是沒水，最後才懷疑是不是桌子有問題。從最常見、最好檢查的原因開始找。

兩節考試中間只有十分鐘，可以換支筆、借個橡皮擦，但不可能重新複習一整章。

每節考完把題目和自己的答案記下來，回家才知道錯在哪。

出發前

Driver Station 筆電

WPILib 的 Driver Station 最佳實務建議這幾件事[2]：

  • 準備一台專門開車用的筆電，只裝 Driver Station 和儀表板，不要拿來寫程式。
  • 電源設定改成不睡眠、關省電、效能最佳；確認在這些設定下電池至少撐一小時，排隊上場沒插座也不怕。
  • 出發前把 Windows 更新全部裝完、實際連機器人測過，然後暫停更新到比賽結束，再設好使用時段，免得比賽中跑去裝更新。
  • 帶一條可靠的 USB 線和網路線，用來直接連 roboRIO。
  • Driver Station 不支援 ARM 處理器的筆電，買筆電前要注意。

程式與工具

  • 開好 event_ 開頭的比賽分支（第 18 章），確認部署時會自動 commit。
  • 所有 vendordep（Phoenix 6、PathPlannerLib、AdvantageKit…）都更新到要用的版本，而且在機器人上測過。比賽場地通常沒網路，不要打算到現場才上網更新[2]。
  • 準備一個「確定會動」的程式版本（例如打一個 Git tag），真的改壞了可以馬上退回去。
  • FAT32 隨身碟（第 18 章）至少兩支，一支插在機器人上，一支備用。

每場比賽前

Driver Station 這邊要做的[2][1]：前一場還沒結束就先把筆電開機登入；關掉用不到的程式；一定要帶筆電充電器上場，因為插著電的時候 Windows 的電源管理比較不激進，Driver Station 比較穩；用魔鬼氈把筆電黏在操作台上。現場要關掉 Windows 防火牆和 Wi-Fi[2]。

下面是程式組可以直接拿去用的檢查清單：

電池充飽、接頭鎖緊電壓表或 Battery Beak；用力扳動電池線，接頭不能動本章
程式是這一場要用的版本儀表板顯示 GitSHA，或確認最後一次部署18

每場比賽後

  1. 用 AdvantageScope 下載 AdvantageKit 日誌（第 18 章），檔名或資料夾標上場次。
  2. 打開 Driver Station 的 Log Viewer，看這場的電壓、延遲、掉封包和模式。
  3. 看 Driver Station 的 CAN/Power 分頁，12V fault 計數有沒有變多（下面會講 brownout）。
  4. 問駕駛和操作手：有沒有哪裡「感覺怪怪的」？把時間點記下來，再去日誌裡找。
  5. 換電池、充電，電池編號跟場次一起記下來。

看懂 Brownout

大電流的時候，電池電壓會一瞬間掉下去。roboRIO（1.0）有分段的保護機制[3]：

階段電壓發生什麼
1低於 6.8 VPWM 腳位的 6V 輸出開始下降
2低於 6.3 V進入 brownout 保護：PWM 輸出關閉、使用者電源軌關閉、CAN 馬達控制器收到停用命令；電壓回到 7.5 V 以上才恢復
3低於約 4.5 V可能直接斷電，電壓回升後重新開機

roboRIO 2.0 第 2 階段的預設門檻是 6.75 V，可以用 RobotController.setBrownoutVoltage 調；roboRIO 1.0 固定 6.3 V[3]。brownout 發生時，roboRIO 的電源燈會變琥珀色、Driver Station 的電壓底色變紅並顯示 Voltage Brownout、CAN/Power 分頁的 12V fault 計數加一，DS 日誌也會記下來[3]。

程式能做什麼？第 11 章的電流限制是最直接的預防。另外可以做「電流預算」：列出每個機構要多少電流，某些功能本來就不會同時用的話，就在程式裡強制它們不要同時動[3]。

從 DS Log 看出斷線原因

Driver Station 的 Log Viewer 會畫出電壓、延遲（trip time）、roboRIO CPU、掉封包和機器人模式，還會標出事件[4]。WPILib 整理了幾種典型的斷線圖，最常用來判斷的是roboRIO 重開：主要線索是 DS 事件裡出現「Time since robot boot」，斷線時其他裝置都 ping 得到、只有 roboRIO 沒反應，接著 roboRIO 又回來了[4]。另外兩種常見的是機器人上的網路線問題和無線電重開，看到斷線先拿去跟文件裡的圖對一下。

Driver Station 的訊息也很有用[5]：「No robot code is currently running」代表 roboRIO 有連上，但程式沒在跑（程式掛了、還在開機，或部署失敗）；「The Driver Station has lost communication with the robot」則是 DS 跟機器人斷線了。

Pit 分診：從最簡單的原因查起

兩場比賽之間時間很趕。跟第 12 章的 CAN 除錯一樣，從最常見、最好檢查的原因開始查。

比賽期間改程式的規矩

下面這些是很多隊伍比賽期間會守的原則，不是官方規定，但可以避免大部分「越改越糟」的狀況：

  1. 一次只改一件事。同時改兩個地方，出問題就不知道是哪個害的。
  2. 只改跟問題直接有關的地方。「順便」重構、改命名、升級函式庫，通通留到比完再說。
  3. 改完要在 Pit 測過才能上場。至少 Enable 一次、動一下改到的機構；自動程式改了要在練習場跑一次，不然至少把底盤架高、在模擬裡跑過。
  4. 改數字前先記下原本的值。比賽分支的自動 commit（第 18 章）會幫你記，但嘴巴也要跟隊友講一聲。
  5. 來不及測，就不要改。用確定會動的版本上場，比帶著沒測過的修改上場安全多了。
  6. 每次部署完都確認版本。部署失敗卻沒發現，就會帶著舊程式上場。
教練提醒：分工Pit 裡機構組也在修東西的時候，Enable 前一定要大聲喊，確定所有人的手都離開機器人了（第 0 章）。程式組改程式時，指定一個人負責部署，不要兩台電腦一前一後部署不同版本。

常見錯誤

沒帶筆電充電器上場Windows 用電池的時候電源管理比較激進，Driver Station 的表現比較難預測[2]。
比賽中 Windows 開始更新出發前沒暫停更新、沒設使用時段，結果要上場了筆電還在重開機。
把 brownout 當成程式 bug機構突然停一下又恢復，先看 12V fault 計數和 DS Log 的電壓，不要急著改程式。
用 USB 線測線材搖線測試要用網路線連，不是 USB，不然測不到機器人上真正的通訊路徑[1]。
在 Pit 大改程式兩場之間重寫一整個指令、沒時間測就上場，結果常常比原本的問題更嚴重。

小測驗

練習：讓程式幫你做賽前檢查

用第 12 章的 Alert，在 Disabled 時檢查兩件事：電池電壓太低（門檻隊上自己訂），還有自動程式選單還停在預設值。線索：RobotController.getBatteryVoltage() 回傳電池電壓；AutoBuilder.getAllAutoNames() 回傳專案裡所有 Auto 的名字，可以拿它自己建選單，順便記住預設選項。

兩個檢查都只在 Disabled 時做；電壓會跳，要避免瞬間掉一下就跳警告。

用兩個 Alert；電壓用 RobotController.getBatteryVoltage() 搭配 Debouncer；選單要能判斷「還是預設值」。

buildAutoChooser 的預設選項拿不到物件，所以自己建 SendableChooser：setDefaultOption("Do Nothing", doNothing)，再用 AutoBuilder.getAllAutoNames() 加入其他選項，判斷 getSelected() == doNothing。

// RobotContainer
private static final double LOW_BATTERY_VOLTS = 12.0; // TODO: 隊上決定門檻
private final Alert lowBattery = new Alert("電池電壓偏低，上場前請換電池", AlertType.kWarning);
private final Alert noAuto = new Alert("尚未選擇自動程式", AlertType.kWarning);
private final Debouncer batteryDebounce = new Debouncer(1.0, Debouncer.DebounceType.kRising);
private final Command doNothing = Commands.none().withName("DoNothing");

// 建構子裡（Named Commands 註冊之後，第 16 章）
autoChooser = new SendableChooser<>();
autoChooser.setDefaultOption("Do Nothing", doNothing);
for (String name : AutoBuilder.getAllAutoNames()) {
    autoChooser.addOption(name, new PathPlannerAuto(name)); // 開機時就建立
}
SmartDashboard.putData("Auto Chooser", autoChooser);

/** 在 Robot.robotPeriodic() 裡呼叫。 */
public void updatePreMatchAlerts() {
    boolean disabled = DriverStation.isDisabled();
    lowBattery.set(disabled
        && batteryDebounce.calculate(RobotController.getBatteryVoltage() < LOW_BATTERY_VOLTS));
    noAuto.set(disabled && autoChooser.getSelected() == doNothing);
}

幾個重點：電壓會跳，所以用 Debouncer 要求持續 1 秒低於門檻才警告（第 12 章）；只在 Disabled 時檢查，因為比賽中大電流時電壓本來就會掉。buildAutoChooser() 的預設選項是它裡面自己 new 的 Commands.none()，程式拿不到那個物件；所以這裡自己建選單，把自己的 doNothing 當預設，就能用 == 判斷有沒有換過。用 AdvantageKit 的話，選單換成第 18 章的 LoggedDashboardChooser，判斷方式一樣。Alert 會自動被 AdvantageKit 記下來（第 18 章），賽後也查得到。
