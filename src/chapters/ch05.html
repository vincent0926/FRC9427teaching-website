CAN ID 05｜Java 與物件導向

列舉、常數與套件：鐘聲、校規和年級班級

這章講三個比較零碎、但每天都會用到的東西：用 enum 表示機構的狀態、把散落各處的數字收進 Constants，還有套件和 import。最後一個看起來很無聊，但你總有一天會因為檔案放錯資料夾而編譯失敗，到時候就會想起這章。

比喻一：學校的鐘聲只有幾種

學校的鐘聲系統只設了四種：上課鐘、下課鐘、午休鐘、放學鐘。值班老師按按鈕的時候，只能從這四個裡面挑。

如果改成輸入數字呢？1 是上課、2 是下課、3 是午休、4 是放學。哪天新老師輸入 5，系統照收，但沒人知道 5 是什麼鈴，全校愣在那邊。更慘的是有人記錯，把 2 當成上課，學生在上課時間衝去福利社。

每種鈴聲還可以帶一點資訊：上課鐘後面是 50 分鐘，下課鐘後面是 10 分鐘。長度跟著鈴聲走，不用另外查表。

這就是列舉（enum）：一份固定的清單，變數只能是清單上的值，寫錯編譯器馬上抓到。而且 Java 的 enum 其實是一種特別的類別，可以有欄位、建構子和方法[1]。

比喻二：貼在公布欄的校規

「每節課 50 分鐘」這件事，如果每個老師都在自己的教案裡各寫一次 50，哪天改成 45 分鐘，就要一本一本翻出來改，漏一本那個老師就多上 5 分鐘。

所以學校把它寫成一條校規貼在公布欄，大家都看這一條。要改只改一個地方，而且任何人一看就知道這個 50 是什麼。

程式中間直接寫死、看不出是什麼意思的數字，叫「魔術數字」。把它們收成有名字的常數，要改只要改一處。Java 的習慣是常數名稱全部大寫，單字中間用底線[3]。

比喻三：三年二班的王小明

全校有兩個王小明，一個三年二班、一個一年五班。廣播只喊「王小明到學務處」，兩個都會跑來。

喊「三年二班王小明」就只會來一個。班級就像名字前面的地址。

名冊上寫小明在三年二班，他就要坐在三年二班的教室。人在一年五班、名冊卻寫三年二班，點名的時候兩邊都對不起來。

三年二班想找一年五班的同學來幫忙，要先在登記簿寫「今天借一年五班王小明」，之後在班上叫「小明」大家就知道是誰。沒登記的話，每次都得喊全名。

這就是套件（package）和 import。有了套件，同名的類別可以同時存在，大專案也比較好整理[5]。

換成機器人：enum

隊上的 Intake 是用 enum 表示狀態的：NONE、INTAKING、SCORING，再用 switch 看狀態決定要做什麼：

public enum IntakeState {
    NONE, INTAKING, SCORING
}

// IntakeSubsystem 裡
private IntakeState state = IntakeState.NONE;

@Override
public void periodic() {
    switch (state) {
        case NONE -> setRollerVoltage(0.0);
        case INTAKING -> setRollerVoltage(8.0);  // TODO: 實測調整
        case SCORING -> setRollerVoltage(-6.0);  // TODO: 實測調整
    }
}

這種 case X -> 的寫法從 Java 14 開始就是正式語法了，WPILib 用的是 Java 17，放心用[2]。

enum 也可以把資料帶在身上，就像鈴聲帶著時間長度。下面只是示範語法，不是說隊上的 IntakeState 要改成這樣：

public enum IntakeState {
    NONE(0.0),
    INTAKING(8.0),  // TODO: 實測調整
    SCORING(-6.0);  // TODO: 實測調整

    public final double rollerVolts;

    IntakeState(double rollerVolts) {
        this.rollerVolts = rollerVolts;
    }
}

// 使用時，switch 整個可以省掉
setRollerVoltage(state.rollerVolts);

換成機器人：Constants

Command-based 範本專案本來就附一個 Constants 類別，放整台機器人共用的常數[4]。常見的整理方式是每個機構開一個巢狀類別：

public final class Constants {
    private Constants() {} // 不讓別人 new 這個類別

    public static final class IntakeConstants {
        public static final String CAN_BUS = "9427";
        public static final int ROLLER_LEADER_ID = 21;   // TODO: 依接線確認
        public static final int ROLLER_FOLLOWER_ID = 22; // TODO: 依接線確認
    }
}

// 使用時
new TalonFX(IntakeConstants.ROLLER_LEADER_ID);

換成機器人：套件與 import

// 檔案位置：src/main/java/frc/robot/subsystems/intake/IntakeSubsystem.java
package frc.robot.subsystems.intake;

import com.ctre.phoenix6.hardware.TalonFX;            // 向 CTRE 借
import edu.wpi.first.wpilibj2.command.SubsystemBase;  // 向 WPILib 借
import frc.robot.Constants.IntakeConstants;           // 向自己專案的 Constants 借

public class IntakeSubsystem extends SubsystemBase {
    // ...
}

package 那行是在說「我在哪一班」，import 那幾行就是「跨班借人的登記」。不 import 也可以用，只是每次都要打全名，像 com.ctre.phoenix6.hardware.TalonFX，打到手會酸。

檔名、類別名、套件名要對上public 類別的名字要跟檔名一樣（IntakeSubsystem.java 裡面是 public class IntakeSubsystem），package 宣告要跟檔案所在的資料夾一樣。只要有一個對不上，javac 就編譯失敗。在 VS Code 裡搬檔案或改檔名之後，第一件事就是檢查這兩行。
教練提醒Code review 時看到程式中間冒出 21、0.35、8.0 這種沒名字的數字，我一定會請你搬進 Constants，順便標上單位。比賽當天在 pit 急著改參數的時候，你會很感謝當初的自己。

小測驗

練習：幫手臂整理位置

寫一個 enum ArmPosition，有 STOW（0 度）、INTAKE（15 度）、SCORE（95 度）三個值，每個值都帶一個 degrees 欄位。再寫一個 describe(ArmPosition p)，用 switch 回傳中文說明。

enum 的每個值都可以帶資料：在值後面加括號，再寫一個建構子收它。

欄位宣告成 public final double degrees;，建構子 ArmPosition(double degrees) { this.degrees = degrees; }。describe 可以用 switch 運算式。

STOW(0.0), INTAKE(15.0), SCORE(95.0); 之後接欄位與建構子；describe 寫成 return switch (p) { case STOW -> "收起"; ... };，漏掉任何一個值會編譯失敗。

public enum ArmPosition {
    STOW(0.0),     // TODO: 實測
    INTAKE(15.0),  // TODO: 實測
    SCORE(95.0);   // TODO: 實測

    public final double degrees;

    ArmPosition(double degrees) {
        this.degrees = degrees;
    }
}

public static String describe(ArmPosition p) {
    return switch (p) {
        case STOW -> "收起";
        case INTAKE -> "取件";
        case SCORE -> "得分";
    };
}

switch 當運算式用的時候，每個 enum 值都要處理到，漏一個就編譯失敗。這就是 enum 比數字安全的地方：你想漏都漏不掉[2]。
