列舉、常數與套件：鐘聲、校規和年級班級

讀完這章，你會用 enum 表示機構狀態、把魔術數字整理進 Constants，並看懂為什麼檔案放錯資料夾會編譯失敗。

生活比喻一：學校的鐘聲只有幾種

廣播系統只有固定幾種鈴聲。學校的鐘聲系統只設定了四種：上課鐘、下課鐘、午休鐘、放學鐘。值班老師按按鈕時，只能從這四個裡面選。

如果改成用數字。假設系統改成輸入數字：1 是上課、2 是下課、3 是午休、4 是放學。有一天新來的老師輸入了 5，系統照樣接受，但沒有人知道 5 是什麼鈴聲，全校愣在原地。更糟的是，有人記錯把 2 當上課，學生在上課時間衝去福利社。

每種鈴聲可以帶附加資訊。上課鐘後面接的是 50 分鐘，下課鐘後面是 10 分鐘。這個長度跟著鈴聲走，不用另外查表。

這就是列舉（enum）：一份固定的清單，變數只能是清單上的值，寫錯了編譯器直接抓到。Java 的 enum 還是一種特別的類別，可以帶欄位、建構子和方法[1]。

生活比喻二：貼在公布欄的校規

數字散落在各處。「每節課 50 分鐘」這件事，如果每位老師在自己的教案裡各寫一次 50，哪天改成 45 分鐘，就得一本一本找出來改，漏一本那位老師就會多上 5 分鐘。

集中到公布欄。學校的做法是把它寫成一條校規，貼在公布欄，所有人都參照這一條。要改只改一個地方，而且大家一看就知道這個 50 是什麼意思。

程式裡直接寫在中間、看不出意義的數字叫「魔術數字」。把它們集中成有名字的常數，要改只改一處。Java 的命名慣例是常數全部大寫、單字用底線隔開[3]。

生活比喻三：三年二班的王小明

同名同姓。全校有兩個王小明，一個在三年二班，一個在一年五班。廣播只喊「王小明到學務處」，兩個人都會跑來。

加上班級就不會錯。喊「三年二班王小明」，就只有一個人。班級就是名字前面的「地址」。

座位要和名冊一致。名冊上寫小明是三年二班，他就必須坐在三年二班的教室。人在一年五班、名冊卻寫三年二班，點名時兩邊都對不上。

跨班找人要先登記。三年二班要請一年五班的同學來幫忙，要先在登記簿寫下「今天借用一年五班王小明」，之後在班上直接叫「小明」就知道是誰。沒登記的話，每次都得喊全名。

這就是套件（package）與 import。套件讓同名的類別可以並存，也讓大專案容易整理[5]。

換成機器人：enum

隊上的 Intake 用 enum 表示狀態：NONE、INTAKING、SCORING。用 switch 依狀態決定動作：

public enum IntakeState {
    NONE, INTAKING, SCORING
}

// IntakeSubsystem 裡
private IntakeState state = IntakeState.NONE;

@Override
public void periodic() {
    switch (state) {
        case NONE -> setRollerVoltage(0.0);
        case INTAKING -> setRollerVoltage(8.0);  // TODO: 實測調整
        case SCORING -> setRollerVoltage(-6.0);  // TODO: 實測調整
    }
}

這種 case X -> 的 switch 寫法從 Java 14 開始是正式語法，WPILib 使用 Java 17，可以放心用[2]。

enum 也可以把資料帶在身上，就像鈴聲附帶時間長度。下面只是示範語法，不代表隊上的 IntakeState 要改成這樣：

public enum IntakeState {
    NONE(0.0),
    INTAKING(8.0),  // TODO: 實測調整
    SCORING(-6.0);  // TODO: 實測調整

    public final double rollerVolts;

    IntakeState(double rollerVolts) {
        this.rollerVolts = rollerVolts;
    }
}

// 使用時，switch 整個可以省掉
setRollerVoltage(state.rollerVolts);

換成機器人：Constants

WPILib 的 Command-based 範本專案附有一個 Constants 類別，用來放整個機器人共用的常數[4]。常見的組織方式是每個機構一個巢狀類別：

public final class Constants {
    private Constants() {} // 不讓別人 new 這個類別

    public static final class IntakeConstants {
        public static final String CAN_BUS = "9427";
        public static final int ROLLER_LEADER_ID = 21;   // TODO: 依接線確認
        public static final int ROLLER_FOLLOWER_ID = 22; // TODO: 依接線確認
    }
}

// 使用時
new TalonFX(IntakeConstants.ROLLER_LEADER_ID);

換成機器人：套件與 import

// 檔案位置：src/main/java/frc/robot/subsystems/intake/IntakeSubsystem.java
package frc.robot.subsystems.intake;

import com.ctre.phoenix6.hardware.TalonFX;            // 向 CTRE 借
import edu.wpi.first.wpilibj2.command.SubsystemBase;  // 向 WPILib 借
import frc.robot.Constants.IntakeConstants;           // 向自己專案的 Constants 借

public class IntakeSubsystem extends SubsystemBase {
    // ...
}

package 那行說「我在哪一班」，import 那幾行是「跨班借人的登記」。沒有 import 也能用，只是每次都要寫全名，例如 com.ctre.phoenix6.hardware.TalonFX。

檔名、類別名、套件名要對上public 類別的名字必須和檔名相同（IntakeSubsystem.java 裡是 public class IntakeSubsystem），package 宣告要和檔案所在的資料夾一致。任何一個對不上，javac 都會編譯失敗。在 VS Code 裡搬移或改名檔案後，第一件事就是檢查這兩行。
教練提醒在 Code review 裡看到程式中間出現 21、0.35、8.0 這種沒名字的數字，我都會要求搬進 Constants 並加上單位。比賽當天在 pit 要改參數時，你會感謝自己。

小測驗

練習：幫手臂整理位置

寫一個 enum ArmPosition，有 STOW（0 度）、INTAKE（15 度）、SCORE（95 度）三個值，每個值帶一個 degrees 欄位。再寫一個方法 describe(ArmPosition p)，用 switch 回傳中文說明。

enum 的每個值可以帶資料：在值後面加括號，並寫一個建構子接收它。

欄位宣告成 public final double degrees;，建構子 ArmPosition(double degrees) { this.degrees = degrees; }。describe 可以用 switch 運算式。

STOW(0.0), INTAKE(15.0), SCORE(95.0); 之後接欄位與建構子；describe 寫成 return switch (p) { case STOW -> "收起"; ... };，漏掉任何一個值會編譯失敗。

public enum ArmPosition {
    STOW(0.0),     // TODO: 實測
    INTAKE(15.0),  // TODO: 實測
    SCORE(95.0);   // TODO: 實測

    public final double degrees;

    ArmPosition(double degrees) {
        this.degrees = degrees;
    }
}

public static String describe(ArmPosition p) {
    return switch (p) {
        case STOW -> "收起";
        case INTAKE -> "取件";
        case SCORE -> "得分";
    };
}

switch 當成運算式使用時，每個 enum 值都必須處理到，漏了一個就編譯失敗。這正是 enum 比數字安全的地方[2]。
