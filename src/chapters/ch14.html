CAN ID 14｜控制

MotionMagic：校車司機怎麼開到下一站

第 6 章其實已經用過 MotionMagicVoltage，這章來解釋它到底在做什麼。為什麼不能直接把目標丟給 PID？梯形和 S-curve 軌跡長怎樣？巡航速度、加速度、jerk 要怎麼設？最後順便比較 MotionMagic Expo 和 Dynamic MotionMagic。

版本說明這章是照 Phoenix 6 的 2026 版（26.x）文件寫的。

比喻：校車開到下一站

新手校車司機只看距離：下一站還很遠，油門就踩到底；快到了才猛踩煞車。車上同學一下往後倒、一下往前撲，書包掉滿地。這就是第 13 章只用 P 的樣子：一開始誤差很大，輸出直接衝到最大。

老司機不一樣，他出發前就有一張行車計畫：用固定的加速度慢慢起步，到速限就維持巡航，算好距離提早減速，剛好停在站牌前。每一秒車子該在哪、該開多快，全都在計畫裡。

如果下一站就在隔壁呢？車子還沒加速到速限就得開始減速了，這時候的速度圖不是梯形，而是一個尖尖的三角形。

更厲害的司機連踩油門的動作都很溫柔，加速度不是一瞬間從 0 跳到最大，而是慢慢踩下去、慢慢放開，同學幾乎感覺不到頓一下。代價是到站稍微慢一點，不過可以用大一點的加速度補回來。

而且司機是自己照計畫開的，老師不用每秒告訴他踩多少油門，只要說「開到圖書館」。中途想改去體育館，說一聲就好，司機會從現在的位置和速度重新規劃。

比喻MotionMagic
油門踩到底、猛煞車把遠方的目標直接丟給 PID
行車計畫運動軌跡（motion profile）
速限巡航速度 MotionMagicCruiseVelocity
起步和減速的快慢加速度 MotionMagicAcceleration
加速—巡航—減速的速度圖梯形軌跡
站太近，來不及開到速限三角形軌跡
油門慢慢踩、慢慢放jerk 限制 → S-curve
司機自己照計畫開軌跡在 TalonFX 內產生並追蹤
中途改目的地隨時用 withPosition 換目標
這個比喻哪裡不準司機會看路況臨時變通，MotionMagic 不會。它只照你設的速度、加速度上限去規劃，根本不知道機構實際上做不做得到。設得比機構能力還快，馬達輸出飽和，機構就跟不上計畫，誤差越拉越大。

為什麼需要軌跡

直接叫機構「去目標」也許做得到，但通常不是最好的方法；比較好的是讓目標平順地變過去，也就是運動軌跡[1]。而且第 13 章說過，前饋的 kV、kA 需要「目標速度」和「目標加速度」，軌跡剛好就提供這兩個。

跟單純的位置 PID 比，MotionMagic 的好處是：整段運動都在控制之下，不是一路衝向目標；機構的慣性被控制住，目標之間的切換很平順；電池和馬達負載變了，重現性也比較好[2]。

梯形、三角形與 S-curve

MotionMagic 會自動產生梯形或 S-curve 的速度曲線，保證不超過你設的巡航速度、加速度和 jerk[2]。

  • 梯形：加速 → 以巡航速度等速 → 減速。
  • 三角形：距離太短，還沒到巡航速度就得開始減速[2]。
  • S-curve：jerk 設成非 0，曲線的轉角會被磨圓，變成連續的 S 形。好處是機構比較不會晃、動作更穩定好重現；壞處是 jerk 限制會讓動作花比較久，可以用大一點的加速度補回來[2]。

動手試：畫出速度曲線

拉一拉移動距離、巡航速度和加速度，看速度曲線什麼時候是梯形、什麼時候變三角形，總共要花多久。單位是手臂端的圈數（rot）。試試看把距離縮到很短會怎樣。

設定 MotionMagic

MotionMagic 一定要設巡航速度和加速度，jerk 可以不設[2]。拿第 6 章手臂的設定當例子：

MotionMagicConfigs mm = config.MotionMagic;
mm.MotionMagicCruiseVelocity = 0.0; // [CONSTRAINT] TODO: rot/s（手臂端）
mm.MotionMagicAcceleration = 0.0;   // [CONSTRAINT] TODO: rot/s²
mm.MotionMagicJerk = 0.0;           // [CONSTRAINT] TODO: rot/s³，0 = 梯形，非 0 = S-curve

// 在 MotionMagic 裡，Slot0 的每一項這樣用：
// kG 重力、kS 靜摩擦、kV × 軌跡速度、kA × 軌跡加速度、
// kP × 位置誤差、kD × 速度誤差

最後那段註解講的是 MotionMagic 的增益怎麼運作[2]：軌跡在每個瞬間都有目標速度和加速度，kV、kA 會拿去用；PID 只負責修剩下的誤差。所以 MotionMagic 才建議用速度的正負號決定 kS 的方向（第 13 章）。

送目標的寫法跟第 6 章一樣，建一次、重複用：

private final MotionMagicVoltage request = new MotionMagicVoltage(0.0);

public void setPositionGoal(double positionRot) {
    leader.setControl(request.withPosition(positionRot));
}

設定好之後，roboRIO 只要定期送目標位置就好，沒有規定一定要等軌跡跑完；想知道到位了沒，自己讀位置判斷[2]。第 6 章的 atGoal() 就是這樣寫的。

參數怎麼選

  1. 先估機構最快能多快。[MODEL] 第 13 章的前饋說，維持速度 v 大約要 kV × v 伏特，所以 12 V 左右能到的速度上限大概是 12 ÷ kV（還要扣掉 kS、kG）。巡航速度設在這個上限以下，留點空間給 PID 修正和電池掉電。
  2. 加速度先保守一點。[CONSTRAINT] 先設「大約 0.5 秒加速到巡航速度」，也就是加速度 = 巡航速度 × 2，確定很順之後再往上加。CTRE 的範例剛好就是巡航 80 rps、加速度 160 rps/s（0.5 秒）[2]。
  3. 機構會晃再加 jerk。CTRE 範例的 jerk 是 1600 rot/s³，意思是大約 0.1 秒從 0 加到 160 rot/s² 的最大加速度[2]。
  4. 看圖調。把目標位置和實際位置畫在同一張圖上（AdvantageScope 或 Tuner X 的 Plot），實際位置應該貼著軌跡走。跟不上的話，就是巡航速度或加速度太大，不然就是 kV、kA 不準。
可以邊跑邊改韌體 24.0.6.0 以後，巡航速度、加速度和 jerk 都可以在執行中改[2]。但改設定一樣是會卡住等回應的 apply（第 11 章），只能在狀態改變時做一次，別放進 periodic。

MotionMagic 的其他版本

請求做什麼需要
MotionMagicVoltage梯形或 S-curve 位置軌跡無
MotionMagicVelocityVoltage以加速度（與 jerk）限制平順地改變速度無
MotionMagicExpoVoltage用系統的 kV、kA 產生指數型軌跡無
DynamicMotionMagicVoltage在請求中直接指定速度、加速度、jerk，可隨時更換Pro 授權 + CANivore

MotionMagic Expo：它產生的是指數型軌跡，最貼近系統本身的動態，跟梯形比，過衝和到位時間都可以一起變少。它有自己的 MotionMagicExpo_kV 和 MotionMagicExpo_kA（單位固定是伏特），供電電壓除以 kV 就是軌跡的最高速度；巡航速度設 0 的話，會往系統的最高速度加速[2]。這兩個值可以直接拿第 15 章 SysId 算出來的 kV、kA 當起點。

Dynamic MotionMagic 沒有 Pro 會直接停止輸出這點跟 EnableFOC 不一樣（第 11 章）：沒授權的 TalonFX 用 Dynamic MotionMagic，會直接關掉輸出，還觸發 UnlicensedFeatureInUse 故障[2]。沒有 Pro 就不要用它。

在 roboRIO 上做同樣的事

如果馬達控制器沒有內建軌跡功能，或是像第 6 章 D-3 那樣在模擬裡自己算，WPILib 有 TrapezoidProfile 可以產生軌跡，ProfiledPIDController 則是把軌跡跟 PID 包在一起[1][3]。CTRE 也示範過用 TrapezoidProfile 每 20 ms 算一個點，再把位置和速度丟給 PositionVoltage[4]。不過能用 MotionMagic 的話，讓控制器自己跑（1 kHz）比較簡單，也比較不會被 roboRIO 迴圈延遲影響。

常見錯誤

單位填錯設了 SensorToMechanismRatio 之後，巡航速度和加速度都是機構端的 rot/s、rot/s²。把馬達端的數字填進去，手臂會快上幾十倍。
巡航速度超過機構能力軌跡跑得比馬達給得出來的還快，輸出飽和，實際位置越落越後，到終點附近很容易衝過頭。先用 12 ÷ kV 估一下上限。
每一輪都 new 請求物件new MotionMagicVoltage(...) 放在 periodic 裡會一直產生垃圾物件。建一次，用 withPosition 改目標就好。
以為 jerk 越大越好jerk 是 S-curve 的「圓滑程度」，數字越小越圓滑、也越慢；設 0 是完全不限制（梯形）。很多人以為反過來。

小測驗

練習：升降機構的兩種速度

升降機構平常用正常速度，但機器人夾著遊戲物件的時候要慢一點，免得甩掉。假設沒有 Pro，不能用 Dynamic MotionMagic。你會怎麼做？寫出關鍵的程式。

不能用 Dynamic MotionMagic，就只剩「改設定」這條路。想想看：設定要在什麼時候改、多久改一次？

準備兩份 MotionMagicConfigs（快、慢），只在「有沒有夾著物件」改變時用 getConfigurator().apply(...) 套用其中一份。

用一個 boolean slowMode 記住目前狀態，setSlowMode(slow) 開頭寫 if (slow == slowMode) return;，避免每輪都 apply。

一種做法（單位寫法照 CTRE 的 MotionMagic 範例[5]）：準備兩份 MotionMagicConfigs，只有在「有沒有夾著物件」改變時才套用一次。

// 放在 ElevatorIOHardware（硬體層），Subsystem 透過 IO 介面呼叫 setSlowMode
private final MotionMagicConfigs fastMM = new MotionMagicConfigs()
    .withMotionMagicCruiseVelocity(RotationsPerSecond.of(0.0))        // TODO
    .withMotionMagicAcceleration(RotationsPerSecondPerSecond.of(0.0)); // TODO
private final MotionMagicConfigs slowMM = new MotionMagicConfigs()
    .withMotionMagicCruiseVelocity(RotationsPerSecond.of(0.0))        // TODO: 比 fast 小
    .withMotionMagicAcceleration(RotationsPerSecondPerSecond.of(0.0)); // TODO: 比 fast 小
private boolean slowMode = false;

/** 只在狀態改變時套用：apply 會等待回應，不要每輪呼叫。 */
public void setSlowMode(boolean slow) {
    if (slow == slowMode) return;
    slowMode = slow;
    leader.getConfigurator().apply(slow ? slowMM : fastMM);
}

只套 MotionMagicConfigs 這一組，其他設定不會被動到（第 11 章）。在 Subsystem 裡可以用 Trigger 偵測「有沒有物件」的變化來呼叫它（第 9 章）。你可能會想到用 Slot0 / Slot1 準備兩組增益，但巡航速度和加速度不在 Slot 裡，所以最後還是得改 MotionMagicConfigs。
