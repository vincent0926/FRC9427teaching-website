# 還沒做的項目與原因

對照改進規格（FRC9427 Teaching Website Improvement Spec）。P0、P1 都已完成；以下是刻意還沒做的部分。

## P2-1 學習紀錄：先不做後端

已完成：學習紀錄（章節完成、小測驗分數、實驗、工具站任務、提示使用、最終評量）存在瀏覽器，學生可以下載成 JSON，教練在 `#coach` 一次匯入全隊的檔案彙整。

沒做：帳號、雲端資料庫、即時的教練儀表板。規格要求「除非對隊伍訓練有實質幫助，否則不要加後端」。目前隊伍規模用匯出／匯入就夠，加後端會多出帳號管理、隱私與維護成本。如果之後需要，可以在不改內容的前提下，把 `src/components/progress.js` 換成送到後端的版本。

## P2-2 真的編譯、執行 Java：還沒做

目前做法：練習用三層提示引導學生自己寫，最後對照完整解答。

沒做的原因：要在瀏覽器裡編譯並執行 Java，需要把 JVM 或編譯器轉成 WebAssembly（例如 CheerpJ、TeaVM 一類的方案），或是另外架一個安全的沙盒伺服器。前者檔案很大、會讓網站變慢；後者需要後端與資安維護。而且 WPILib、Phoenix 6 的程式離開機器人或模擬環境很難執行，能自動測的主要只有純 Java 的練習（第 1～5 章）。

可行的下一步：先針對第 1～5 章的純 Java 練習，寫 JUnit 測試放在一個範本專案裡，讓學生在自己電腦的 WPILib VS Code 跑 `./gradlew test`。這不需要網站執行程式碼，也是學生之後真的會用的流程。

## P2-3 用真實 FRC 日誌驗證：還沒做

本網站本身不做自動診斷，所以沒有「診斷正確率」需要驗證。最終評量用的日誌是教學用的合成資料，頁面上已經註明。

工具站（電梯／手臂調參工作站）的 2F 有自動診斷，它的 README 已經把目前的數字標成「合成資料測試」。要依規格分開報告真實日誌、盲測日誌與學生診斷的正確率，需要先蒐集隊上實機的日誌，這必須上機才能做。

## 需要真人才能完成的

- 找新隊員實際走一遍核心路徑，看學習卡的目標是否合理、情境題是否太難或太簡單。
- 教練試用 `#coach` 彙整頁，確認表格的欄位是否對訓練有用。
